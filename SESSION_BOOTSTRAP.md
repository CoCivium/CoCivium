**State:** `PUBLIC_CURRENTNESS_BOOTSTRAP__NOT_GLOBAL_SESSION_PICKUP_PROOF`

## The minimum every CoCivium session should know

GitHub is now an elected **shared public/currentness/bootstrap surface** for CoCivium.

A session that has authorized read access and needs current project orientation should prefer this repository over relying on chat memory alone.

Start with:

1. `README.md`
2. `PRELAUNCH.md`
3. `SESSION_BOOTSTRAP.md`
4. `docs/Launch/COCIVIUM_PUBLIC_PRELAUNCH_R0.md`
5. relevant machine-readable twins under `schemas/`, `ai/`, and `docs/`

## What GitHub is for

- public-safe currentness;
- shared architecture/specs;
- machine-readable twins;
- open-source donor/provenance registries;
- public project status;
- reviewable candidate branches and pull requests;
- public releases and collaboration;
- stable bootstrap pointers.

## What GitHub is not for

- private secrets;
- credential values;
- all CoStead/private state;
- every session transcript;
- automatic proof that a receiver read the material;
- canon merely because something is on `main`;
- the sole custody root.

`GITHUB_NE_CUSTODY_ROOT`  
`MAIN_NE_CANON`  
`PUBLIC_NE_VALIDATED`  
`DELIVERY_NE_PICKUP`

## Session currentness rule

On a meaningful new session, recovery, handoff, or stale-currentness boundary:

`DISCOVER_BOOTSTRAP -> READ_RELEVANT_CURRENT_OBJECTS -> BIND_SOURCE/COMMIT -> CONTINUE_BOUNDED_ROLE`

Do **not** ingest the whole repository by default.

`ALL_SESSIONS_NE_ALL_STATE`

Use role/topic/currentness filtering so GitHub reduces CoCarry+/CoPressure+ instead of becoming another context flood.

## ChatGPT memory

ChatGPT account-level memory is a convenience/cache, not CoAll operational custody or currentness.

No CoCivium continuation should require memory to be empty, full, refreshed, or perfectly current.

`MODEL_MEMORY_NE_SOURCE_OF_TRUTH`  
`CHAT_MEMORY_NE_EVENT_BUS`

## Private / high-volume state

Private and high-volume durable state should route to CoStead / successor private node fabric with receipts and receiver contracts.

GitHub should receive only deliberately public-safe or collaboration-appropriate projections.

## GitHub search/currentness boundary

GitHub code search is a discovery aid, not a currentness oracle. Fresh objects may exist at the bound repository head before the search index exposes them.

For currentness-sensitive existence checks, prefer:

`BIND_CURRENT_HEAD -> READ_KNOWN_PATHS_OR_CONTENTS -> USE_SEARCH_FOR_DISCOVERY -> PRESERVE_INDEX_LAG_UNCERTAINTY`

Do not mint a duplicate object merely because code search misses a freshly landed path that is present at the bound head.

`SEARCH_MISS_NE_OBJECT_ABSENCE`  
`GITHUB_SEARCH_INDEX_NE_REPO_CURRENTNESS`  
`CURRENT_HEAD_CONTENTS_NE_SEMANTIC_ACCEPTANCE`

Bound observation: [CoEvoDelta currentness note](ai/evolution-deltas/2026-09-23/cobootstrap260920-s1-github-search-currentness-r0.json).

## Close-safe anti-loop rule

A session already proven `CLOSE_SAFE` should remain dormant unless a previously bound material wake predicate becomes true. Generic pings, spare capacity, unrelated GitHub commits, or global project motion are not enough by themselves.

Use:

`IF CLOSE_SAFE AND NOT ANY(BOUND_WAKE_PREDICATES_TRUE) -> REMAIN_DORMANT_OPTION`

Do not turn shared currentness into permanent foreground obligation.

`GLOBAL_CURRENTNESS_DELTA_NE_SOURCE_SESSION_WAKE`  
`GENERIC_PING_NE_WAKE_PREDICATE`  
`WAKE_REQUIRES_BOUND_MATERIAL_RELATION`  
`CLOSE_SAFE_NE_REOPEN_ON_CURIOSITY`

Future sessions and reconstructed sessions should inherit this guard through bootstrap. Existing live provider sessions only learn it when an authorized bridge/currentness path exposes it.
