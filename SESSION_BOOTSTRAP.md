## Research recovery before absence claims or rebuilds

Before a material claim that prior work, an agent, a result, or an implementation
is absent, or before replacing/repeating it, perform a bounded evidence readback:

1. Name the decision and the evidence that would change it.
2. Bind the current repository head and load the relevant subscription/currentness
   paths from `ai/session-bootstrap.json`. Treat memory as a pointer cache.
3. Read known exact source paths before broad search. Follow aliases, lineage and
   supported successor links when discovery misses. Search snippets are discovery,
   not a substitute for reading the relevant source.
4. For runtime questions, separate this observer route, the named process,
   heartbeat freshness, task progress and receiver pickup. An unavailable route
   does not establish that an agent stopped.
5. Check later receipts and descendant satisfaction before replay or replacement.
   Preserve dated observations rather than letting the newest label erase history.
6. Stop when evidence supports the named decision and material contradictions are
   exposed, or when remaining authorized sources are inaccessible or additional
   search is unlikely to change the decision. Report the coverage boundary.

Return a compact readback: decision; exact sources/versions actually inspected;
alternatives or contradictions; unresolved access/currentness; resource selection;
continuation pointer; next bounded deed.
Use the existing CoResearchEvidence contract for material research claims and the
existing session writeback/fan-in path for material shared deltas. Do not create a
parallel index, registry or worker merely because this session missed the source.

Use explicit states: `NOT_FOUND_IN_SEARCH`, `INACCESSIBLE`, `STALE`,
`CONTRADICTED`, `VERIFIED_FOR_SCOPE`. Reserve scoped absence for an authoritative,
bounded inventory with explicit coverage and time; never infer global absence.

### Resource selection and retained research

Before escalating research or choosing a worker, record the relevant available
options, what was inspected versus merely listed, and why the selected option
can change the decision. Compare access, capability, source coverage, privacy,
latency, cost/budget (or unknown), failure-domain independence and expected
information value. Include a no-new-worker/reuse option. Do not imply a complete
global resource census; state unavailable and uninspected options explicitly.

Material research must leave a retrievable result through the existing session
writeback/fan-in path: source identities and dates, findings and counterevidence,
chosen/deferred options with reasons, completed work, unresolved questions,
next deed, and a material wake/recheck condition. Carry the exact result pointer
and last-read version into the successor checkpoint. If writeback or pickup is
unavailable, report that boundary instead of claiming shared retention.

Reopen a resource choice when new evidence, a changed constraint or a bound wake
condition could change the decision. Do not repeat a completed search simply
because time passed, or silently carry an expired capability assumption forward.

### Executable readback check

Receivers that require this gate can run the existing validator with
`--require-recovery`; add `--require-extraordinary-gate` for extraordinary
claims. The record uses the optional `research_recovery` and
`extraordinary_gate` fields in the existing research-evidence schema.

```sh
python scripts/validate_coresearch_evidence_r0.py --require-recovery --require-extraordinary-gate examples/coresearch-recovery.example.json
python scripts/test_coresearch_recovery.py
```

Strict mode rejects missing readbacks, search/observer-only absence claims,
unbound inventory versions, uninspected resource selections, missing retention
pointers, and incomplete declared extraordinary promotion checks. Legacy
records remain accepted without the strict flags. The synthetic example
deliberately remains unresolved and has no real receiver writeback.

The validator checks declared consistency. It does not retrieve or authenticate
sources, judge independence or prior-art adequacy, verify scientific results,
or enforce invocation by every agent. A complete self-reported record can
still be false; domain review and receiver adoption remain separate proofs.

### CoResearchGate+ Extraordinary

For an extraordinary claim, bind primary observations, independent
corroboration and a prior-art review. Seek counterevidence through adversarial
review, replication and prospective falsifiers. Do not promote the claim without
domain-specific verification. Preserve source identity, dates, uncertainty and
receipts. When a required check is missing, retain the claim as a candidate and
state the missing verification; search volume, agreement and schema validity
cannot substitute for domain evidence.

Acceptance requires a separate receiving session/carrier to read the same bound
checkpoint, identify completed/blocked work, and resume a bounded task without
human context relay or duplicate execution. A documentation or CI pass is not
that adoption proof.

`RESEARCH_READBACK_BEFORE_ABSENCE_OR_REBUILD`  
`OBSERVER_UNAVAILABLE_NE_AGENT_STOPPED`  
`SEARCH_MISS_NE_OBJECT_ABSENCE`  
`DOCUMENTED_PROTOCOL_NE_SESSION_ADOPTION`

## Close-safe anti-loop rule

A session already proven `CLOSE_SAFE` should remain dormant unless a previously bound material wake predicate becomes true. Generic pings, spare capacity, unrelated GitHub commits, or global project motion are not enough by themselves.

Use:

`IF CLOSE_SAFE AND NOT ANY(BOUND_WAKE_PREDICATES_TRUE) -> REMAIN_DORMANT_OPTION`

Do not turn shared currentness into permanent foreground obligation.

`GLOBAL_CURRENTNESS_DELTA_NE_SOURCE_SESSION_WAKE`  
`GENERIC_PING_NE_WAKE_PREDICATE`  
`WAKE_REQUIRES_BOUND_MATERIAL_RELATION`  
`CLOSE_SAFE_NE_REOPEN_ON_CURIOSITY`

Future sessions and reconstructed sessions should inherit this guard through bootstrap. Existing live provider sessions only learn it when an authorized bridge/currentness path exposes it.

`semantic relation -> label intent -> mutation attempt -> provider acknowledgement -> stored state -> rendered projection -> observer readback`

Claim only the strongest rung actually evidenced.

`LABEL_INTENT_NE_PROVIDER_MUTATION`  
`PROVIDER_MUTATION_NE_RENDERED_PROJECTION`
