# CoGbx / X2 / CoOrbWare UX acceptance R0

**Not all-session consensus.** The recommendations below are a synthesis of source-controlled CoCivium CoFleet R4, CoOrb Local UX, CoCopy Daily Continuity, CoOrbWare Legacy Coexistence, CoMap/CoAhead and CoVirtualSession. Independent designers, agents and human users have **not** all been polled or confirmed this design.

## Candidate surface hierarchy

- **Glance**: CoHereNow, currentness, one next action, alert only on material exception. X2 bottom CoBar is appropriate if a real observer and current data are proven.
- **Focus**: one task, source, why, authority, selected proof, reversible action, Stop/Undo. Use CoOrb context lens at pointer or keyboard, not another always-open application.
- **Explore**: CoMap typed relations, alternatives, negative space, contradictions, branches; all relations distinguish proposed vs independently verified.
- **Time**: CoAck/Rewise ribbon, history, sleep/recover, speculative futures separated from actual events. Time scrub must not rewrite source.
- **Depth**: optional perspective/spatial/VR layers only where user success warrants. Keep accessible 2D, keyboard, touch, reduced motion, audio, and machine API parity.
- **Exchange**: proposed CoGbx reference site, one task doorway and five optional specialist paths; no gatekeeping to public evidence; let users export, fork, revoke or leave.

## The two-way promise

The same exact `work_id` must survive collapse from full CoMap into one CoOrb and expansion again. Nothing in display state is permission to send, merge, spend, access sensors, or execute. An agent sees the same typed task/evidence state, not an invisible separately controlled shadow account.

## Real first-use trial

Test A: plain text-first. Test B: CoMap + optional depth/time. Randomize order for consenting independent participants and measure task correctness, time to answer, correct distinction between attempt and receiver ACK, ability to recover/Stop, screen-reader use, motion/attention cost. Prefer A when B adds complexity without measured benefit. Record negative results and actual device, browser, model and accessibility conditions.
