## The seed

An authorized AI or human **might** complete one useful first-use task through a small CoOrbWare projection of source-bound work. This is a **design hypothesis**, not a claim of a working native CoOrbWare, installed mouse, actual Claude/Pi/Ollama integration, or autonomous AI receiver.

[The single machine-readable specimen](first-seed-witness-r0.json) contains 14 cards:

- **ALT × 2**: one accessible text route and one optional CoOrb route;
- **INVERT**: navigate desired outcome back to provenance, explicitly not inverse causation;
- **NEGATE**: test the hypothesis that CoOrb adds no value; negation is not proof;
- **NULL**: no-effect comparator; not evidence of nonexistence;
- **ELSE**: CLI/JSON route rather than a graphical view;
- **INTERSTICE**: explore the source-readability versus receiver-ACK gap;
- **CROSS_SUBSTRATE**: compare desktop/mobile/offline representations of the *same work object*;
- **SYMBOLIC**: voluntary interpretive G_d/angel/aura lens; no divine or physical-effect claim;
- **PHYSICAL**: measurable interface energy/latency plan; not yet measured;
- **ET**: hypothetical nonhuman-interface story lens; no contact evidence;
- **G_d philosophical**: metaphysical question, not an entity detector;
- **FALSIFIER**: a consenting newcomer might fail the selected task;
- **DYNAMICS**: distinguish chaos, drift, evolution and noise rather than calling every change improvement.

No conceptual crossing raises a hypothesis's epistemic state. A spiritual lens is not a physical observation. A mathematical nonphysical object is not automatically supernatural. An inverse relation is not automatically symmetric. A code or visual artifact is not automatically CoEx, canon, a legal entity or a receiver ACK.

## How to verify

From a normal, full Git checkout of this branch:

```sh
python3 -m json.tool examples/coallbloom/first-seed-witness-r0.json >/dev/null
python3 -m unittest discover -s examples/coallbloom -p 'test_*.py' -v
```

The tests use only Python's standard library, exact locally checked Git donor blob identities, and **negative mutations** to test fail-closed epistemic, privacy and authority boundaries. No network access, login, provider accounts, file writes, app installation or external AI calls are needed.

A donor update makes exact blob verification FAIL until reviewed and pinned. That is intended currentness protection, **not** automatic immutability or proof the donor's assertions are true.
