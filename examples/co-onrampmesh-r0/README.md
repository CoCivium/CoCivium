# CoOnrampMesh R0 | Specialist entrypoints, one evidence root

State: **review candidate; public-safe local prototype; not deployed to any domain.**

## Purpose

Test whether role-specific, minimal entrypoints outperform the current long generic CoCivium landing path for first-time visitors. Three candidates (`CoBuild`, `CoProof`, `CoPlay`) are *working labels*, not registered identities, products, subsidiaries, trademarks, or separate permission systems. They point to three existing public research source files with pinned Git blob SHA-1s. No new CoAll participant ontology or truth store is created.

The app is a standalone, single-file HTML page (`index.html`) that does **not** fetch assets, call models, inspect devices, track visitors, set cookies, or contact anyone. Each choice shows a genuinely useful self-contained micro-exercise. Source links open only on a user's click and are labelled **source code**, not a ready deployed service. Manifest is the machine twin; a copy-only preview provides an exercise without collecting the visitor's answer.

## Falsifiable explanations to test

1. **Canonical-domain failure**. Observed in a bounded public check: apex did not serve a useful landing page; the `www` variant served a technical metadata-oriented index. This is an operations/privacy review gate and should be triaged privately without reposting local path details. Do not infer deliberate suppression.
2. **Broken historic external references**. Older third-party pages still point to a different repository and describe it as discontinued. Seek a redirect/correction where controlled; not all third-party listings can be fixed.
3. **Low measured audience / incomplete analytics**. Connected analytics indicate a small measured audience and incomplete site-tracking coverage. Do not publish or infer all-channel engagement totals from these partial signals. Exact connected-account metrics remain outside this public packet.
4. **Message-before-value overload**. Test whether newcomers can identify purpose and finish one bounded meaningful task before learning proprietary vocabulary.
5. **Weak distribution**. Compare organic opt-in referrals from relevant specialist communities with generalized broadcast, avoiding unsolicited mass engagement.
6. **Lack of credible demonstrable product**. Record first-use task completion, corrections and return intent; source exposure alone is not product acceptance.
7. **Suppression or unusual interference**. Retain only as a low-prior working hypothesis until independent comparable controls and concrete evidence exclude mundane explanations.

## Pilot acceptance

Recruit *consenting* reviewers in three interest groups, five per lane for formative qualitative usability only, with a control visit to the generic README. Do not claim statistical significance. Randomize visit order when feasible, measure both routes on equal tasks, explicitly count confusion, refusal and negative results. Core measures: time-to-first-useful-action, accurate comprehension of *what is running vs hypothetical*, source identification, trust, accessibility, and easy exit. Collect no accounts, personal data or analytics automatically. Capture anonymous aggregate results only if separately consented.

Gate promotion on: (1) correct intended canonical domain; (2) security/privacy review of publicly displayed metadata; (3) measured usefulness improvement; (4) readable accessible page; (5) independent receiver acceptance and a real hosted route. The public branch alone is not website deployment. Subdomains and separate domains should come **after** evidence of differentiated demand, not before.

## Replicate

- Open `index.html` locally, without a web server.
- `node smoke.cjs` verifies the exact page/manifest pairing, routes, pinned public refs, privacy/no-telemetry contract, role differentiation and negative controls. This validates code structure, not independent UX.

**Source-of-truth:** CoCivium/CoCivium GitHub is a public projection. Private custody requires a distinct durable receiver and receipt.
