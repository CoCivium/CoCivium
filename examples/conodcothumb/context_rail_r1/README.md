# CoContextRail+ R1 | One deliberate gesture, a million addressable relations

**CoHereNow:** Public-safe, synthetic, browser-local preview and pure Node policy donor for the existing CoNod / CoThumb / CoOmniIO family. It is **not** a Windows driver, mouse mapping, device monitor, agent orchestrator, native CoOrbWare, or public release certification.

## Try it in 30 seconds

Open [index.html](index.html) in a browser that permits opening local files, or through an approved offline/static preview host. Choose one explicitly labelled **context** and one **Q&A&@ question**, then press **Preview one safe option**. Click **More relations** to see up to seven bounded candidates. Select the **Ordinary middle-click** gesture to confirm the native action is represented as `PASS_THROUGH_NATIVE`. Private/sensitive classifications fail closed. The optional download creates a local, **zero-authority proposal**, never a sent message, OS action or receiver receipt.

If your browser denies direct `file://`, that is a browser/sandbox restriction; no browser acceptance is inferred from extracting and rendering HTML in Chromium. The tested browser path used `page.set_content` with exact local source.

```sh
python3 build.py --check
node --test tests/test_context_rail.cjs
python3 tests/browser_qa.py            # Requires Playwright + local Chromium in a suitable sandbox
```

No external npm packages or credentials are required for `build.py` and the Node 22 pure tests. The HTML embeds an exact copy of `CoContextRailR1.js` and `manifest.json`, generated by `build.py`. The file's CSP denies network, form submission, object/embed and remote media. The synthetic UI does not read keys, OS mouse events, clipboard, screen, camera, mic, private paths or actual selected files.

## What is context?

The current, **qualified** task slice, not every byte from every session:

`CoContext = (Purpose, SelectedObject, Priors, Relations, Evidence, Scope, Privacy, Authority, Time, Receiver, ResourceBudget, DeviceCapability, Accessibility)`.

The R1 simulated subset has six axes:

- 15 contexts × 17 questions × 18 relations × 9 lenses × 7 time classes × 8 render surfaces = **2,313,360 syntactic combinations**.
- Addressable combinations are not independent useful ideas, real users, tokens, current live sessions, AI workers or executable permission.
- Only **one default** suggestion, or **up to seven** after an explicit request to expand.
- Deterministic mixed-radix decoder and seed-based sampling limited to **64** indices, no enumeration or provider fanout.

Prior ideas survive as references, not as automatically loaded context. Provenance/currentness binds the projection to source. Relevance filtering and per-task budgets decide what is materialized, at the moment it helps.

## The chosen mouse policy, not a second OS controller

**Native wheel/middle click always passes through by default.** The optional CoCivium summon is one explicitly elected **Logi Actions Ring / keyboard equivalent**, with app-specific preview and visible stop. The R1 demo selects `EXPLICIT_RING` in the UI to simulate that intent only. It **does not configure Logitech Options+**, bind `Ctrl+Alt+Shift+N`, change Perixx keys, install hooks, start a daemon, or inspect X2. Existing [CoOmniIO review PR #237](https://github.com/CoCivium/CoCivium/pull/237) and [CoMousePalette PR #231](https://github.com/CoCivium/CoCivium/pull/231) remain the candidate hardware interfaces, pending a *single* safe choice. Do not run two competing hotkey controllers.

The one-gesture context intention:

| Context | CoHereNow first candidate | Boundary |
| --- | --- | --- |
| Explorer / file | Inspect exact file identity, offer CoCopy pointer | No read until explicit selection and source qualification |
| Rich media | Propose capsule / integrity / rights checks | Bytes remain file-backed; no send or thumbnail claimed |
| Writing, code | Priors, alternate wording or test proposal | No keylogging or auto-typing |
| CoMap / CoOrb / diagram | Inversion, missing source and lineage | Projection cannot become authoritative source |
| Scientific claim | Falsifier, alternative explanation and evidence | Fiction/myth/ET/G_d remain hypotheses or stories |
| Device / Fleet | Local health, recovery and attention cost | This demo performs zero device telemetry |
| Outreach | Consent/recipient check and unsent draft | `@` never implies send or recipient ACK |
| Password/payment/sensitive | Block even the preview metadata | No raw fields or screen classification captured |

Tap/chord/hold/middle/wheel/dwell and posture are separate **candidate gestures**. Nothing automatically infers intent or permission from pointing, timing, silence or button combinations. Normal OS input remains usable and cancel/stop should be obvious in an eventual native interface.

## Q&A&@+ and CoGibberTru+/CoPriMath+

Questions are first-class source-linked objects: What? Why? How? Where? When? Who? Wherefore? Which? What-if? Why-not? What-not? What-else? NotElse? How much? How know? What next? And `@`, which means **attribution/receiver candidate, not transmission**.

Each question can be projected as a brief action and an accessible glyph. `¬` denotes a *candidate negation*, not proof of falsehood. `∅` is a closed-world empty scope **only with qualified evidence**. `∞` means unbounded logical hypotheses with bounded processing. `⊕` means combine only permitted sources, not merge rights or secrets.

These labels reuse [CoQuestionCommons](../../../docs/Architecture/COQA_QUESTION_COMMONS_R0.md), [CoInterstice / CoInversion](../../../docs/Architecture/COINTERSTICE_COINVERSION_COGLYPH_INPUT_FABRIC_R0_20261024.md), [CoRelationalUX / CoOrb](../../../docs/Architecture/CORELATIONAL_UX_PREDICTIVE_INPUT_R0.md), and [CoDoodle / CoNex](../../../docs/Architecture/CODOODLE_CONEX_EXPERIMENT_LAUNCHER_R0_20261024.md). They do **not** claim that an old CoGibberTru or CoPriMath definition has been reconciled or elevated to CoAll canon.

## AutoEvo, AutoCycle, AutoFuture and CoTurtle rails

`SOURCE Δ → qualify → ask/invert → deterministic proposal → select up to 7 → prior/challenge → bounded test → receipt → sleep.`

A future scenario is a hypothesis or planning branch. It cannot schedule an effect by merely existing. Any actual authorized scheduler must have resource ceilings, heartbeat, TTL, recovery and stop. The CoTurtle reviewer limits remain depth <=2, rounds <=2 and a shared inherited budget, with no authority expansion. New random branches may be useful for testing, but novelty is not truth, and predictions are not observations.

For `G_d`, spiritual/nonmaterial, ET and Civ2+/Civ3+ stories: use a *labelled symbolic/philosophical lane* or an explicitly testable public-data hypothesis. No metaphysical interpretation becomes a model backend, authenticated entity, discovered external intelligence, or physical measurement by notation alone.

## Input-envelope R1 hardening (candidate, 2026-10-25 UTC)

This is a **safety-first donor to the existing CoContextRail R1**, not a new hotkey controller or a claim that X2 already runs it. The pure preview classifier now rejects any undeclared `packet` field before returning visible context; this includes fake `raw_key`, `clipboard_text`, and `screen_pixels` fields. It also rejects explicit outward effect intent unless its field is exactly `false`; unsupported types do not inherit permission. The refusal includes no captured input bytes, source pointer, permission or receiver ACK.

Allowed optional field: `external_effect_requested: false`. A true/string/unknown effect request yields `HELD_EFFECT_REQUEST`. Any other undeclared field yields `HELD_UNDECLARED_INPUT`. Existing declared synthetic-browser controls continue as before.

**Proof protocol:** seven additional deterministic negative cases on top of the previously recorded 91; `node --test` + exact `python3 build.py --check` must be evaluated by branch CI before PASS claims. Regenerated `index.html` must match the *same* versioned manifest + source and not silently drift. Further browser-level and native Windows tests remain independently required.

**Hard boundary:** `NATIVE_MIDDLE` remains pass-through, no OS hook or key capture, no callback executes or sends, no session worker spawn, no provider/secret/account controls. Source hardening alone is not user acceptance, deployment, or a physical button mapping. When merging, preserve the old R1 receipt and add a new explicitly scoped one rather than rewriting historical rows.

`UNKNOWN_INPUT_NE_CONTEXT | PREVIEW_NE_SEND | GLYPH_NE_AUTHORITY | NEW_GUARD_NE_WINDOWS_RUNTIME`.
