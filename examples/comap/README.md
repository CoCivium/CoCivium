# CoMap+ Source Weave R0 | Working offline reader

**[Open or save the interactive CoMap+ HTML](source-weave-r0.html)**. GitHub may display HTML markup rather than execute the file; save the single file and open it in a browser. This has **no external requests, telemetry or machine control**. It is a source-registered projection, **not a live semantic bus, all-term crawler, CoAll canon, policy enforcement engine or CoOrb/X2 installation**.

## What is implemented and tested

- A searchable, zoomable SVG map of **56 source-registered objects and 61 typed relationships**: 21 evolution lanes, 21 named repositories, 10 highlight assets, 3 documents and 1 candidate CoMap view.
- Separate views for evolution domains, repository roles, highlights, documents, and unverified candidate links.
- Clickable node inspection, neighbor relations and GitHub source links. The embedded graph's node identities and 61 typed edges were checked against the separately committed [machine-readable source projection](../../ai/comap-source-projection-r0.json).
- Local relation scratchpad: choose two objects, label a relationship, explain why it is worth testing, inspect it as a dashed unverified candidate, clear it or export a **local JSON proposal**. Nothing is submitted or promoted automatically.
- Desktop (1366 px) and mobile (390 px) Chromium checks passed: initial 56/61 state, CoTheoryAll search selection, lens switching, reset, one candidate creation/clear, no JavaScript exceptions, no network requests, no horizontal overflow.

**Sources and currentness:** Public [evolution lanes](../../ai/evolution-lanes.json), [repository-role map](../../ai/repo-role-map.json) and [highlight registry](../../ai/highlight-assets.json). Source blob IDs are recorded in the graph snapshot. Those registries are snapshots (September 2026), not evidence of live freshness in November. Private repository **names** appear because the public role map names them; no private repository contents are included.

## The next several bounded, methodical evolution cycles

1. **Discover:** Start with existing CoLex/GIBindex terms, CoTheoryAll hypotheses, CoRails rules, MasterPlan decisions, CoSource provenance and source-bound CoHighlights. A title, code symbol, chat shorthand or public web mention is merely a candidate, not a governing term.
2. **Qualify:** Bind a real source, date, author/issuer, relevant receiver/problem, privacy level, epistemic class, semantic version and independent evidence if claimed; otherwise retain `UNKNOWN`.
3. **Relate:** Compare candidate meanings against exact existing terms, aliases, near-duplicates, incompatible senses and inverse/null interpretations. Prefer a new typed edge to minting a competing CoTerm.
4. **Challenge:** Require source distinctions, contradiction tests and authority/rights checks. Counterexamples, dissent and unknowns remain visible; do not assume graph proximity proves cause, permission or truth.
5. **Score:** Rank by expected **reader/useful receiver value**, source evidence, novelty, testability, edge-reuse and information gain minus compute, latency, privacy risk, coordination cost and maintenance debt. Keep multiple noncommensurate metrics; no sole magic score.
6. **Elect:** One authorized actuator promotes a bounded, versioned projection or branch after reviews. All other workers may propose independently but must not concurrently clobber the same semantic definition.
7. **Verify and sleep:** Independent reader or receiver reconstructs exact source and interprets the change correctly; record effect/receipt, preserve prior meaning and rollback path, then wake only on a material source/need change.

**Critical rules:** `NEARBY_NE_EQUIVALENT`, `LINK_NE_AUTHORITY`, `POPULAR_NE_TRUTH`, `ALL_ADDRESSABLE_NE_ALL_INGESTED`, `MAP_NE_CANON`, `NEWEST_NE_CURRENT`, `NO_NEWEST_WINS`, `HIGHLIGHT_NE_RELEASE_READY`, `PRIVATE_NAME_NE_PRIVATE_CONTENT`.

## Where CoMap belongs in the federation

CoMap is a **progressively disclosed, participant-relative projection** of existing CoAll/CoEcoAll/CoLex/CoEvo objects. Preserve one source graph and many views (CoOrb, book, map, topic lens, accessible list, machine-typed event, offline file). Use level-of-detail and relationship relevance rather than one infinite node ball. Edge permissions and actual service-cell execution remain behind the [Civ2+ Federated Cell architecture](../../docs/Architecture/CIV2_FEDERATED_CELL_HOSTING_R0.md).

**Current blockers:** Full CoLex ingestion, cross-provider currentness, independent receiver uptake, private semantic review, X2 CoBar/CoOrb binding and >24-hour survivorship remain **unverified**. This example is an editable local candidate explorer, not an autonomous term-harvesting worker.
