# CoTime + CoRecipeCache R0: temporal recipe replay

**State:** Synthetic candidate / code and tests on a review branch. Not a production work object, scientific finding, physics observation, public release, CoEx canon or device integration.

## Core problem

A historical event stays fixed, but later evidence can change its current interpretation. A candidate repair pattern can cross software domains without importing authority, silently rewriting history or treating a forecast as a future fact.

## What this experiment does

- Replays a fixed synthetic source manifest at two as-of times.
- Preserves source SHA-256 references and separate occurrence/recording times.
- Extracts a proposed evidence-bound status recipe from two independent *fictional* domains.
- Reserves null and inversion alternatives. A symbolic G_d/gnosis question remains a hypothesis-only interpretation.
- Emits a deterministic hash-bound receipt, one elected research-only candidate and unresolved future tests.
- Exercises fail-closed fixture parsing with Python's standard library only.

## Run

```sh
python examples/cotime_recipe_r0/test_recipe_replay.py
python examples/cotime_recipe_r0/recipe_replay.py --as-of 2026-11-02T20:00:00Z
python examples/cotime_recipe_r0/recipe_replay.py --as-of 2026-11-02T22:00:00Z
```

## Evidence ceiling and next gate

The input is entirely synthetic; passing unit tests can establish only deterministic logic and the explicit nonpromotion rules. No measured accuracy, physical insight, scalability, independent observer reception, G_d contact, actual CoIndex repair, or audible delivery is established.

Next acceptance: replace synthetic inputs with explicit approved, non-sensitive and version-pinned receipts; measure false-green rate and corrections against the existing baseline. Keep real effects behind a separate authority gate.
