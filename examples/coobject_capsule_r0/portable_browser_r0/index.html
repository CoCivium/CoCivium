One file. One portable object.
An honest recovery path.

A real, offline file task. Select a file, package exact bytes, export a self-contained capsule, reopen it in another browser, test loss, and restore what survives. No server, account, provider, or automatic effects.

Proof boundary: Two copies within one downloaded JSON file share a failure domain. SHA-256 checks internal integrity, not authorship. This browser does not prove remote custody, X2 health, human acceptance, 24-hour uptime, or that a capsule is better than copying a file directly.

1. Pick one task

The chosen file stays in browser memory. No upload, fetch, storage, or automatic execution. Closing or resetting is not a guaranteed forensic memory wipe. Avoid sensitive data unless you accept local-export risk.

2. Test, recover, export

This is an explicit, reversible experiment on the object in memory. The original file and any previously exported capsule are untouched.

Exports use ordinary browser downloads initiated by a click; browser download names are suggestions, not writes into existing files. A corrupt object fails closed.

A simple copy may be faster, smaller and entirely sufficient. The capsule pays for checks, metadata and recovery options with size and complexity. No universal winner.

Object contract and recovery limits

Identity is content-derived. State and observation time belong to this browser only; the local clock is untrusted. All imported bytes are data, even if they contain scripts. Manifest hashes do not authenticate original publishers. No external rights or consent are inferred. Unknown is not zero. Source selection, package, transport, inspection, challenge and restore are distinct events.
