## Evidence ladder, not REAL/FAKE by decree

Appearance -> OS process/window evidence -> bounded challenge/response -> distinct receiver readback -> source-bound effect receipt -> independently reproduced useful outcome.

A static wallpaper displaying "CoBar" is artwork. A replay or a moving video can depict liveness but is not evidence of a responding process or useful task. PID existence is not responsiveness. Consistent receipts are not authenticated causality. The R0 classifier therefore emits separate bounded states, explicit observer/time, no simulated authenticity, and allows conflict, unknown and stale cases. Video may help test actual pixel changes after explicit consent, but Windows-native process/window/health receipts can be more discriminating and cheaper. Audio/video collection is optional, on-demand, local-first and never an inferred general surveillance grant.

CoAura+, CoTele+ and CoMyth+ remain alternative explanation, symbolic and creative hypothesis lanes. They can generate falsifiable proposals, not actuation privileges or unproved physical-causal claims.

## CoDesktop and today's interruption

The user reported on 2026-11-08 that the PC had become laggy, intrusive PS7 mini-panels recurred, and a restart was necessary. This is evidence of an interruption and user-perceived performance, not an independently verified machine cause or cure. Remote Desktop Commander currently returns X2 OFFLINE, last seen about 43 minutes prior to observation, not proof of powered-off Windows. Restarting an unidentified CoDesktop process is held.

Existing CoDesktopPresence research previously found both headless launchers and some tasks using plain PowerShell consoles. Microsoft Win32 APIs support window-to-process attribution; Windows Terminal has documented cases where WindowStyle Hidden can still expose a console. These are candidate explanations, NOT proof of today's cause.

Use ReadOnlyWindowsPopupProbe.ps1 only after an authorized reachable Windows path exists. The probe returns bounded process/parent/creation-time and best-effort top-level-window metadata plus pseudonymous PowerShell task launcher IDs. It does not capture command lines, task arguments, raw window titles, screenshots, unrelated files or sensors, and does not write a file or restart anything. Task presence alone does not establish popup ownership; later correlate an actual incident to its exact process/task before recommending change.

## Productized opportunity detection, not another watcher

Existing CoEyes observations -> CoTime source qualification -> a deduplicated recurring friction pattern -> CoBoogie alternative causes -> CoRegroup bounded candidate -> one authorized CoRunner patch canary -> before/after proof and rollback -> CoBar quiet result.

At least three qualified owner-attributed events can justify reviewing a headless launcher fix. Repeated user reports without OS ownership trigger read-only attribution. Nothing executes automatically. Compare measurable interruptions/hour, loss of focus, latency and manual recovery time. Unknown baselines stay unknown.

A short-term forecast can be generated from three or more fresh consistent attributed intervals, but it remains UNCALIBRATED_PREDICTION with zero authority. Test against future observations and alternatives. Long-horizon models need separate source-bound out-of-sample calibration and changing regime checks, not an extrapolation from a few frames.
