**IA is unresolved.** Sources have not established an agreed expansion or identity rule for the term. Calling it IA does not automatically create a new being, account, legal status, autonomy or authority.

## One source-aware encounter (the candidate default)

`DISCOVER → BIND SOURCE → TYPE ROLE → QUALIFY → FIRST SAFE TASK → CHALLENGE → ACCEPT → PROJECT → CHECKPOINT → SLEEP/WAKE → EXIT`

1. **Discover just enough.** Start with `SESSION_BOOTSTRAP.md` and `ai/session-bootstrap.json`, then query role-relevant currentness. Avoid whole-repository context flooding.
2. **Bind origin.** Record exact source/commit/hash, observation date, rights, epistemic class, privacy scope and expiry.
3. **Qualify a replaceable role.** E.g. read-only researcher, local model examiner, deterministic verifier, contradiction reviewer. Existing authenticated provider accounts remain their real owners' accounts. No fabricated principal or provider-limit evasion.
4. **Run one harmless task.** Show the input, authorized model/tool, limits and a useful small output. Keep external messages, private data, device mutation, legal/financial effects behind their actual separate gates.
5. **Challenge the result.** Test a counterexample, source freshness and claims of uncertainty. `MULTIPLE_MODELS_NE_INDEPENDENT_EVIDENCE`.
6. **Receive or hold.** A publisher's source readback is not another agent's pickup. Record an independent receiver's exact-object/task acknowledgement before calling the encounter accepted.
7. **Project conditionally.** CoMap+/CoOrbWare+ can show work identity, source, currentness, disagreement, cost, progress and exit. The view gives no extra powers.
8. **Go quiet; wake on change.** Persist an allowed checkpoint, update only if the source, role, lease, evidence or user need materially changes, then sleep again. A daily check is optional, not a universal forced rewrite.

## A genuine evergreen test

A first consenting independent AI/client should return **(a)** its source revision, **(b)** the one task it chose, **(c)** a testable or useful output with a nonclaim, and **(d)** its actual bounded receiver acknowledgement. Later, after a meaningful source change, the *same authorized client or qualified successor* should fetch only the delta, correct or preserve its prior work, then checkpoint with no human text courier.

Until the two encounters have source-/receiver-produced receipts, this is **source-published readiness**, not autonomous evergreen onboarding.
