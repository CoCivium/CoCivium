# CoAndrew+ Provider-Neutral First Use R0

**State:** `PUBLIC_R&D__DRAFT_PR__NOT_DEPLOYED__NOT_ENDORSED`

## Purpose

Give an independent developer a useful, challengeable first encounter with CoCivium without requiring allegiance to CoCivium, a preferred AI provider, a live swarm, a device agent, or any hidden account linkage.

The first-use invariant is:

`BRING_ONE_REAL_PROBLEM -> GET_ONE_USEFUL_RESULT -> SEE_EVIDENCE_AND_LIMITS -> BREAK_OR_IMPROVE_IT -> LEAVE_WITH_RECEIPT`

## Supported executor classes

The architecture treats executors as replaceable instruments:

- deterministic/no-model baseline;
- Claude or another hosted model;
- local/open-source models through provider-neutral adapters;
- human review;
- mixed or multi-model panels where independence is explicitly qualified.

No executor gains authority merely by producing useful output.

`MODEL_NE_AUTHORITY`
`PROVIDER_NE_CONTROL_PLANE`
`OPEN_SOURCE_NE_AUTOMATICALLY_TRUSTED`
`LOCAL_NE_AUTOMATICALLY_PRIVATE`

## First-use contract

An independent developer should be able to:

1. clone or read the public material;
2. run a deterministic baseline without an AI account;
3. optionally bind one executor adapter;
4. challenge one claim or proposed improvement;
5. inspect sources, counterevidence, assumptions and uncertainty;
6. reproduce the bounded test;
7. export a receipt;
8. stop without creating a profile, granting device control, or joining a persistent program.

## Minimal result surface

Every first-use result should expose:

- result;
- exact source/version bindings;
- what was inferred versus observed;
- counterevidence and unresolved questions;
- executor/model identity when used;
- resource/cost notes when measurable;
- PASS/FAIL/HELD outcome;
- one bounded next deed;
- receipt or reconstruction pointer.

## CoAndrew+ acceptance metrics

Prefer metrics that reward usefulness rather than captivity:

- time to first useful result;
- number of blocking questions;
- manual steps;
- jargon burden;
- correction burden;
- evidence fidelity;
- reproducibility;
- model/provider swap cost;
- privacy exposure;
- ease of exit.

## Historical redo lane

Older CoCivium work is eligible for replay through current deterministic, hosted, local/open and mixed review lanes. Old results are preserved rather than silently overwritten.

`OLD_NE_BAD`
`NEWER_NE_BETTER`
`REPLAY_NE_REWRITE_HISTORY`

## Limits

This document does **not** establish:

- a deployed CoAndrew runtime;
- Anthropic/Claude integration;
- Ollama or Llama integration;
- public node pickup;
- independent developer acceptance;
- continuous/background execution;
- a million live sessions;
- scientific validation;
- merge to main.

It is a bounded public proposal for review and testing.
