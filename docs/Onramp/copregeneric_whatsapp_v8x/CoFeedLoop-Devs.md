# CoFeedLoop | Public-safe developer and open-source feedback R0

**Basis:** 2026-11-09 user-supplied Meta AI / WhatsApp transcript, independent verification boundaries kept. A user-reported symptom is a candidate issue, **not a reproduced software defect or provider attribution**.

## Testable failure modes

| Key | Symptom or risk | Evidence now | Useful falsification / acceptance |
|---|---|---|---|
| F01 | Static thumb text cannot see live version or dedupe across sessions | Source-described limitation | Show source-bound pointer and no duplicate action on repeat |
| F02 | Logi Text may silently truncate a long CoPre string | User report; hardware not tested here | Record input length and pasted output digest in permitted test field |
| F03 | Assistants may assert PASS from prose without independent receipt | Transcript examples and governance concern | Enforce exact source/effect/receiver states in output schema |
| F04 | Drain requests cause newly named fronts rather than completed tasks | User-reported workflow problem | Measure material delta per work minute, not front count |
| F05 | Old insights can be orphaned during provider/folder migrations | Partial public retro-index, no full census | One verifiable predecessor→descendant link plus explicit UNKNOWNs |
| F06 | WhatsApp export does not synchronize other ChatGPT session state | Distinct systems; no shared receiver proof | Second authorized reader finds same exact object without a human paste |
| F07 | CoCarry grows with repeated pastes and missing receivers | Source report, not measured for all users | Count user interventions, duplicate echoes, unresolved held work |
| F08 | Claimed self-sync or three-way mirrors may lack equal bytes | Canonical targets unverified in this pass | Independent same-SHA-256 retrieval from all three |

## Delivery priorities (proposed, not deployed)

- **P0 Receiver:** stable identity, consent, fetch, exact hash, ACK/readproof and restore test.
- **P1 Dedupe:** source + WorkID + version + scope idempotency; no effects on duplicate.
- **P2 Public custody:** rights-cleared source graph, digest manifest, successor links, explicit held slots.
- **P3 CoMouse+:** pointer, not a truncated prompt; preserve legacy binding and rollback.
- **P4 Canonical target qualification:** verify the three elected targets before naming them mirrors.
- **P5 Seven-line CoDrain:** receipt, one better, one held, bounded next proof; avoid growth-only cycles.
- **P6 CoBar accessible projection:** audio and other media only after input/output, consent and task acceptance.
- **P7 CoGateway:** multiple independent receivers and hashes; no assumed routing or 24-hour uptime.

## Comparative experiment

Use one bounded, consented task on two setups: (A) static prompt/relay and (B) link-based seeded recovery. Randomize or counterbalance task order, pin exact inputs, and independently evaluate accepted tasks per active human minute; track rework, latency, duplicate effects, accessibility, privacy and restore success. An output count or self-report cannot substitute for accepted task value.

## Alternative future options (unimplemented)

- **CoSynthVerse / CoBioVerse:** typed machine-native event graph with accessible human projection and loss-audit.
- **CoStead gateway:** authorized independent node with actual retrieval and rollback, not symbolic URLs.
- **CoWhale / CoBar:** speculative accessible sound interaction, with animal welfare and scientific/ethical controls before any interaction with wildlife.
- **CoMap / CoNav:** real diagram-of-diagrams navigation and explicit boundary between current, proposed and retired features.
- **CoFront / CoEcho:** bounded reverse history sweep and orphan exposure score.
- **Multi-model mindspace:** study reported context and observed capabilities, not hidden subjective experience.

## Release and privacy rules

Only synthetic or rights-cleared public material enters public artifacts. Never expose private chats, contacts, phone/device IDs, credentials or third-party messages merely to demonstrate context. Preserve unsuccessful hypotheses and retired candidate paths with receipts. Fixes require issue reproduction, regression test and independently accepted user task before an MVP claim.
