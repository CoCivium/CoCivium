# CoAll GitHub Evolution Fabric R1 candidate

**State:** `PUBLIC_BRANCH_CANDIDATE__REVIEWABLE__NOT_CANON__NOT_RUNTIME`

R1 is an additive evolution of R0. It does not replace history, widen authority, or require every session to edit every repository.

## Why evolve R0

The project now has more capability, more parallel work, more repositories, more relational vocabulary, and more durable surfaces. That creates a scaling problem: global relation/work volume can grow much faster than any one session's useful foreground.

The answer is not universal session omniscience.

`GLOBAL_RELATIONAL_RICHNESS_CAN_GROW__PER_SESSION_FOREGROUND_SHOULD_STAY_BOUNDED`

Each capable session should orient to the shared field, subscribe to a bounded relevance cone, contribute material deltas where it has evidence and authority, then externalize or donate residue before close.

## Updated session loop

`ORIENT -> REFRESH_CURRENTNESS -> SUBSCRIBE -> OBSERVE -> RELATE -> PROPOSE -> CHALLENGE -> BRANCH_MUTATE_WHERE_SAFE -> VERIFY -> FAN_IN -> PULSE_CURRENTNESS -> TWILIGHT_EXTERNALIZE -> CLOSE_OR_WAKE_GATE`

This adds four important ideas to R0:

1. **Receiver-relative subscriptions.** Use `CoRelevanceCone+` / HOT-WARM-DIGEST-SLEEP rather than reading the whole estate.
2. **Relational meanings and uses.** Terms, files, repos, branches, highlights, surfaces, and strategies participate in typed relations rather than one frozen classification.
3. **CoTwilight+ as high-yield metabolism.** A late session should harvest, dedupe, challenge, externalize, donate, preserve wake conditions, and shrink live-session dependency.
4. **Execution-surface routing.** GitHub is one elected surface. Files/Library, typed machine connectors, local workers, provider UI, PS7 break-glass, and human gates remain deed-relative alternatives.

## Mutation is relational

A GitHub change is not merely "edit file".

A mutation should be representable as relations among:

`session -> delta -> source evidence -> domain -> target repo/path -> branch/PR -> tests -> reviewer/receiver -> merge/reject -> observed outcome -> successor/currentness`

Relations may themselves participate in relations:

- a source relation can be contradicted by another relation;
- a repo-role relation can be time-bounded;
- a highlight relation can be receiver-relative;
- a mutation rule can be superseded;
- a metaphor relation can project into humour without becoming evidence;
- a branch can be a candidate projection without becoming canon.

`RELATION_CAN_RELATE_TO_RELATION__RECURSION_REQUIRES_STOP_RULES`

Stop recursive expansion when marginal information gain is lower than representation cost, proof debt, and receiver complexity.

`CURRENTNESS_FOR_ALL_NE_CONTENT_FOR_ALL`

Sessions that discover durable strategic or conceptual deltas should not leave them trapped in chat.

Typical projections:

- strategy / planning -> `MasterPlan` private candidate;
- insight / theory seed / humour/metaphor candidate -> `CoInsights` private candidate;
- term/alias/meaning/index relation -> `GIBindex` candidate plus public-safe `CoCivium` projection when useful;
- source/provenance -> `CoSources`;
- invariant/rail -> `CoRails`;
- runtime helper -> `CoToolbelt` / `CoStacks`;
- UX/projection -> `CoAura` / `CoCivium`;
- public highlight -> bounded public registry after readiness checks.

## GitHub mutation rail

Before writing:

1. refresh repo/ref/path currentness;
2. search for equivalent relations and open work;
3. bind source refs;
4. classify confidentiality;
5. identify collision domain;
6. elect mutation class;
7. prefer reversible branch/PR for cross-cutting or uncertain changes;
8. run tests/challenges;
9. preserve disagreements and negative results;
10. merge only within explicit authority/effect ceiling;
11. emit currentness/receiver pointer;
12. observe outcome where practical.

`GITHUB_WRITE_ACCESS_NE_GLOBAL_AUTHORITY`
`NO_NEWEST_WINS`
`MERGE_NE_CANON`
`PUBLIC_NE_VALIDATED`

## Nonclaims

R1 does not claim:

- every session has received or integrated it;
- every repository role is permanent;
- GitHub is the only or highest-authority substrate;
- merged/public content is canon;
- all named capabilities are runtime-active;
- AI sentience, subjective desire, or global self-awareness;
- authority transfer from authentication or write access.
