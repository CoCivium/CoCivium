## Multi-substrate resilience

A resilient system can distribute roles across:

- horizontal peer instances;
- vertical stack layers;
- temporal checkpoints and successors;
- spatial, provider, or semantic alternatives.

A capability should be portable across substrates where practical, while preserving identity, provenance, authority, currentness, and recovery state.

## Public/private projection rule

Private operational repositories remain operational sources where they contain sensitive runbooks, telemetry, private communications, credentials, security details, or account-specific state.

Public projections should expose:

- generalizable concepts;
- public-safe architecture;
- reproducible tests and examples;
- provenance to public sources where appropriate;
- explicit uncertainty and nonclaims.

Public projection should not expose private operational payload merely because the underlying idea is useful.

## Outreach and propagation

Outreach is treated as an evolving receiver graph rather than a message-count metric.

Candidate states include:

CREATED -> VALIDATED -> DISPATCHED -> REACHED -> RECEIVED -> ACKNOWLEDGED -> ENGAGED -> EFFECT

A public projection must not claim a state transition without corresponding evidence.

## Evolution discipline

New relations may be proposed freely, but promotion should require a useful consequence such as explanatory value, predictive value, operational value, governance value, or UX value.

UNBOUNDED DISCOVERY + BOUNDED PROMOTION
