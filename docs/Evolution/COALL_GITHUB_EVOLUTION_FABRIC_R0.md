# CoAll GitHub Evolution Fabric R0

**State:** `PUBLIC_SHARED_EVOLUTION_CONTRACT__NO_GLOBAL_SESSION_ACK_CLAIM`

## Lead

GitHub is now an elected shared public/currentness/evolution surface for CoCivium, not merely a place to park code.

Every capable session should be able to **contribute bounded deltas** to the evolving project field without carrying the whole project in its context window.

The default is not “every session edits everything.”

The default is:

`ORIENT -> SUBSCRIBE -> OBSERVE -> PROPOSE -> CHALLENGE -> MUTATE_SCOPED_BRANCH -> VERIFY -> MERGE_WHERE_ALLOWED -> PULSE_CURRENTNESS`

`ALL_SESSIONS_CAN_CONTRIBUTE_NE_ALL_SESSIONS_MUTATE_ALL_SURFACES`

## Session contribution contract

A session may contribute one or more `CoEvoDelta+` objects.

Minimum fields:

`delta_id | session_id | observed_at | domain | subject | relation | epistemic_class | source_refs | target_surfaces | mutation_class | authority_ceiling | confidentiality | confidence | contradictions | tests | expected_benefit | risks | wake_conditions | supersedes | next_receiver`

### Mutation classes

- `OBSERVE` — read-only currentness/evidence.
- `PROPOSE` — durable candidate delta, no target mutation.
- `BRANCH_MUTATE` — create/update reversible candidate branch or PR.
- `REVIEW_CHALLENGE` — critique, contradiction, tests, prior-art.
- `MERGE_LOW_EFFECT` — docs/schema/tests/public-safe metadata where authority and collision checks allow.
- `EFFECT_GATED` — runtime/public outreach/credentials/authority/financial/privacy-sensitive/irreversible effects.

No session receives a broader authority class merely because it can authenticate to GitHub.

`GITHUB_WRITE_ACCESS_NE_GLOBAL_AUTHORITY`

## Domain subscriptions instead of omniscience

Sessions should maintain a bounded subscription set.

Example:

```
CoLanguage session:
  HOT: CoLex, CoGibberTru, CoPriMath projection loss
  WARM: CoTheoryAll, CoIndex
  DIGEST: UX, public highlights
  SLEEP: unrelated runtime lanes
```

GitHub reduces CoCarry+ only when a session reads the relevant current slices rather than re-ingesting the repository universe.

`CURRENTNESS_FOR_ALL_NE_CONTENT_FOR_ALL`

## Domain-to-repo election

A delta chooses its target by semantics, confidentiality, currentness, and receiver need.

Examples:

- new CoTerm relation -> GIBindex candidate + CoCivium public projection if public-safe;
- new research insight -> CoInsights candidate + linked source refs;
- new runtime helper -> CoToolbelt/CoStacks, not README prose;
- new invariant -> CoRails candidate + schema/test if applicable;
- new public UX relation -> CoAura / CoCivium surface docs;
- new strategy -> MasterPlan private candidate, public-safe summary in CoCivium if useful;
- new future hypothesis -> CoFutures private by default;
- new highlight asset -> CoCivium highlight index after public-safe/readiness check.

A cross-cutting relation may legitimately project into several repositories.

`ONE_OBJECT_CAN_HAVE_MANY_REPO_PROJECTIONS`

## README and folder evolution

README files and directory trees are UX/index projections, not semantic truth.

Sessions may propose improvements when they reduce:

- navigation cost;
- ambiguity;
- stale pointers;
- orphan exposure;
- duplicate concepts;
- human attention debt;
- AI bootstrap time.

Do not reorganize directories merely for aesthetic tidiness.

`DIRECTORY_TREE_NE_SEMANTIC_TREE`  
`README_NE_CANON`

## CoTheoryAll / CoPriMath / CoGibberTru

These are especially cross-cutting.

A contribution should preserve:

- source claim;
- epistemic class;
- observer/model/scale/time qualification;
- transformation/projection relation;
- loss/ambiguity;
- contradiction;
- test or discriminating observation where possible;
- public explanation distinct from scientific status.

Mathematical notation or compressed symbolic forms do not gain truth by density.

`FORMALIZATION_NE_VALIDATION`  
`COMPRESSION_NE_TRUTH`

## AutoEvo feedback

Every useful GitHub mutation should be available as training evidence for the mechanisms that selected it:

`delta -> review/test -> merge/reject -> observed outcome -> CoAutoEvo lesson`

Rejected PRs and failed experiments are not waste; they are negative knowledge.

`REJECTED_NE_USELESS`

## Anti-thrash / collision rules

Before writing:

1. refresh target current head;
2. search for existing equivalent relation;
3. bind source refs;
4. classify confidentiality;
5. identify collision domain;
6. prefer branch/PR for cross-cutting or uncertain changes;
7. preserve source history;
8. merge only inside authority/effect ceiling;
9. emit currentness pointer after merge.

When several sessions converge on the same object, prefer fan-in/reconciliation over last-writer-wins.

`NO_NEWEST_WINS`

## What all sessions should know

At minimum:

- GitHub is a shared public/currentness/evolution surface.
- CoStead/private nodes remain private durable fabric.
- account/model memory is not project truth.
- sessions should contribute bounded deltas instead of carrying everything.
- domain subscriptions beat total-context ingestion.
- provider sessions are replaceable embodiments.
- public/main/merged still does not automatically mean canon, CoEx, or scientific validation.
