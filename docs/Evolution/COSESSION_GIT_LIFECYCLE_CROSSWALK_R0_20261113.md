## Purpose
Transfer the proven *discipline* of branching, merging, review, rollback, retirement and distributed history from Git and neighbouring systems to CoAll WorkIDs and session embodiments, while preserving actual source, authority, provenance, privacy and receiver distinctions.

**Key separation:** work identity != provider conversation != virtual session != worker/model process != Git commit. Native ChatGPT conversations cannot be fused using this proposal. We merge source-bound **work graphs**, not opaque personalities or private conversation transcripts.

## Git-like operations, with CoAll-specific evidence semantics

| Operation | Eligible CoAll transformation | Required protection |
|---|---|---|
| BRANCH | explore one alternative under the same WorkID lineage | source-version and authority ceiling |
| FORK | establish independent descendant ownership and evolution | explicit provenance, rights and non-merged identity |
| MERGE | reconcile compatible material deltas | preserve objections, distinct evidence and collisions |
| CHERRY_PICK | transfer one qualified improvement from a donor | source citation and receiver acceptance |
| REBASE | test old decisions against a new evidence baseline | no rewriting or retroactive fabrication of source history |
| SQUASH / ROLLUP | compact active representation | immutable input refs, loss ledger and rehydration test |
| TAG / RELEASE | name a reproducible checkpoint | evidence class and exact object identity |
| DIFF / BISECT | locate behavioural/proof regression | independent controls and exact input set |
| REVERT / ROLLBACK | restore earlier qualified behavior | distinguish reversible logical projection from irreversible external effects |
| MIRROR / BACKUP | preserve another copy or failure-domain option | actual independent restore and access tests |
| DRAIN / QUIESCE | stop new task admission; transfer or settle outstanding work | no unowned obligation; checkpoint and lease fence |
| DEPRECATE / RETIRE | remove preferred active embodiment | successor proof, wake triggers and owner disposition |
| GARBAGE_COLLECT / DELETE | erase retention-expired eligible content | user-specific authority, legal/privacy review and independent purge proof |

## CoMaterial / CoPhysical (candidate typing, not automatic CoTerms)
- **CoMaterial:** a work relationship can have a materialized representation such as bytes, checkpoints, containers, disks, caches or physical artifacts; representation does not establish usable receiver integration.
- **CoPhysical:** actual device, sensor, power, thermal, network and failure-domain embodiment, requiring measured locality, currentness and permission.
- **CoVirtual:** logical WorkID and work relationships may persist without any powered process.
- **CoNonMaterial / CoNull:** symbolic or epistemic absences may generate tests, but cannot imply an unmeasured physical state.
- **CoZelse:** explore missing operations and inversion controls before minting redundant terminology.

## CoReverence / CoDereverence inversion
- Preserve slow-changing invariants: identity, timestamps, source hashes, negative results, dissent, consent, privacy and last known good.
- Explicitly challenge sacred cow assumptions: every chat must stay open; matching titles imply duplicates; newer means better; every backup restores; every merge should eliminate branches.
- A true independent challenger may be retained as an intentional anti-merge minority.
- Source data remains protected even after the active view is compacted. Retiring a process does not justify deleting retained evidence.

## One bounded three-session canary
1. Identify **three actual** provider/session source IDs, exact scope and WorkIDs. A screenshot showing several similar titles is *not* a full census.
2. Source-bind each material decision, unique discovery, unresolved obligation, contradiction, currentness and permissible retention.
3. Baseline: independent active sessions; measure repeated relay, time to reconstruct, loss of unique work and cost.
4. Candidate: compatibility-gated fan-in to one WorkID projection; maintain dissent and donor refs; elect one next action.
5. Check successor readproof on a distinct eligible worker; challenge stale-source, privacy mismatch, collision and missing-receiver controls.
6. Freeze new duplicate work to selected redundant embodiments only after evidence. Mark CLOSE_SAFE when no unique obligation remains.
7. Keep original provider conversations and data unchanged until separately authorized deletion, after independent restoration and explicit retention/export checks.
8. Compare reduction in open session burden, verified recovery, cost and unique option retention against baseline; if regression, revert projection and keep siblings.

## Provider-exit gates
Inventory -> consent/rights partition -> source-preserving export -> dedupe and coverage ledger -> independent encrypted custody -> cold restore -> local/open worker and scheduler requalification -> account-specific service cancellation -> separate deletion/purge approval -> provider-specific confirmation. Unknown coverage means HOLD. Archive/hide/close tab is not deletion.

A browser title, source hash, file upload, synthetic test or GitHub branch is never evidence of independent receiver pickup.

## Stop rule
Run recursion only when expected marginal verified benefit exceeds compute, coordination, human attention and recovery cost; otherwise SLEEP. Parallelize discovery/challenge, serialize conflicting effects. Never grant a system authority over its own privacy, consent, deletion or public distribution merely by making it self-evolving.
