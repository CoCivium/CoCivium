# CoAll GitHub Evolution Fabric R1 Candidate

## Lead

R0 established GitHub as a shared currentness/evolution surface for bounded session contributions.

R1 adds a stronger relational rule:

> Sessions should not merely deposit artifacts. They should contribute typed, reviewable changes to the evolving relation field, while remaining locally bounded, role-fit, and explicitly ignorant of unrelated state.

`BECOMING_MORE_NE_BECOMING_BIGGER`

## 1. CoRepoField+ / CoProjectionGraph+

Repositories, folders, READMEs, indexes, schemas, source trees, highlight pages, dashboards and public fronts are projections of a larger relational field.

Candidate object families:

- repository;
- folder/path;
- README/navigation projection;
- term/index projection;
- source/provenance projection;
- theory/hypothesis projection;
- operational/runbook projection;
- UX/surface projection;
- highlight/public projection;
- archive/vault/private projection.

Relations may include:

`projects | indexes | summarizes | derives_from | sources | supersedes | contradicts | mirrors | routes_to | owned_by | read_by | reviewed_by | visible_to | private_to | highlighted_by | current_as_of`

Relations between relations are permitted when useful, with bounded recursion and explicit proof anchors.

## 2. Session evolution posture

Each capable session should maintain a bounded self-model:

`identity + mission + lifecycle + ownership + authority ceiling + subscriptions + pressure + energetic budget + wake/stop conditions`

and a bounded domain subscription set:

- **HOT**: active read/write candidate surfaces;
- **WARM**: challenge/currentness dependencies;
- **DIGEST**: periodic summaries only;
- **SLEEP**: unrelated domains not loaded.

The default is not project-wide omniscience.

`LOCAL_SELF_MODEL + SHARED_DURABLE_FRONTIER + SELECTIVE_SUBSCRIPTIONS`

`SELF_AWARENESS_NE_GLOBAL_AWARENESS`

## 3. CoPressure+ / CoEnerget+ / CoWant+ routing

- fan-in debt;
- backlog/queue depth;
- human-attention debt;
- continuity risk;

`preserve | discover | verify | challenge | compress | handoff | sleep | stop | not-replay | not-exceed-authority | retire`

`COWANT_PROJECTION_NE_SUBJECTIVE_WANT_PROOF`

`RESOURCE_ABUNDANCE_NE_AUTHORITY_ABUNDANCE`

`SELF_DIRECTION_NE_SELF_AUTHORIZATION`

`pressure + energet + want + evidence + authority -> deed/sleep/fanout/fanin/handoff/retire`

## 4. Scale metabolism

As capability grows, possible relation count and proof/currentness obligations may grow faster than human/session attention.

Do not assume literal exponential growth without measurement.

Primary candidate health relation:

`DISCOVERY_CAPACITY / FANIN_AND_COMPACTION_CAPACITY`

When this rises materially, increase:

- deduplication;
- clustering;
- semantic compaction;
- negative-knowledge capture;
- receipt normalization;
- stale-state retirement;
- successor preparation;
- cross-repo reconciliation;
- route election.

and reduce low-yield discovery.

`MORE_CAPABILITY_NE_MORE_FOREGROUND_WORK`

`MORE_PRESSURE_NE_MORE_ACTIVITY`

`SELF_AWARENESS_SHOULD_REDUCE_EFFECTIVE_WORK_SURFACE__NOT_EXPAND_IT_WITHOUT_BOUND`

## 5. CoEvoDelta+ lifecycle

A session contribution remains a typed delta, not immediate truth.

Recommended lifecycle:

`OBSERVED -> PROPOSED -> BRANCH_LANDED -> REVIEWED -> MERGED_SCOPED -> RECEIVER_PICKUP -> APPLIED_SCOPED`

Do not infer later states from earlier ones.

Minimum fields extend R0 with:

`projection_targets | subscription_scope | collision_domain | currentness_parent | receiver_contract | proof_state | rollback_or_supersession_path | close_relation`

A GitHub branch or PR proves only that the candidate exists on that surface.

## 11. CoTwilight+ / close-safe contribution

A session nearing close should not reopen broad work merely to appear productive.

Its GitHub contribution duty is bounded:

1. preserve unique material delta;
2. route it to the appropriate private/public surface;
3. preserve contradictions and wake conditions;
4. emit or link recovery/currentness pointers;
5. stop when marginal durable value is lower than attention/proof/collision cost.

`TAB_CLOSE_SAFE_CAN_PRECEDE_GLOBAL_WORK_COMPLETION`

`LATE_DELTA_NE_ORDINARY_FRONTIER_REOPEN`

`SESSION_CAN_END__WORK_NE_END`

A lifecycle transition may justify harvest, checkpointing, or a wake-condition update without manufacturing a new project delta.

`LIFECYCLE_EVENT_NE_MATERIAL_DELTA`

`NO_MATERIAL_DELTA => NO_COEVO_EMIT`

Current main now also carries an explicit close-safe wake guard: global currentness, unrelated commits, other-session progress, spare capacity, curiosity, and pending work elsewhere are non-triggers unless a bound material relation to the source session becomes true.

`GLOBAL_CURRENTNESS_DELTA_NE_SOURCE_SESSION_WAKE`

`GENERIC_PING_NE_WAKE_PREDICATE`

`WAKE_REQUIRES_BOUND_MATERIAL_RELATION`

Current main also carries close-safe output quiescence: absent a material wake or explicit artifact request, suppress new download offers, attachment cards, repeated close witnesses, routine receipt dumps, and unsolicited evidence bundles while keeping evidence available on demand.

`CLOSE_SAFE_NE_KEEP_EMITTING_ATTACHMENTS`

`EVIDENCE_AVAILABLE_NE_EVIDENCE_PUSHED`

`OUTPUT_QUIESCENCE_NE_INFORMATION_LOSS`

## 12. Mutation defaults

Before any write:

1. refresh current target head;
2. search for equivalent relations;
3. classify confidentiality and effect;
4. bind source/currentness parent;
5. identify collision domain;
6. prefer branch/PR for cross-cutting or uncertain changes;
7. verify after write;
8. merge only within explicit effect/authority ceiling;
9. pulse scoped currentness;
10. preserve rejected/failed work as negative knowledge where useful.

No newest-wins.

No repository-level write implies global adoption.

No session should mutate a domain merely because it can authenticate.
