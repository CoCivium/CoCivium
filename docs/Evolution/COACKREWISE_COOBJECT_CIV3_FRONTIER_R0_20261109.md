## CoHereNow: what was being noticed

The repeated dissatisfaction is not merely that files sit dormant. It is that **knowledge accumulates faster than verified useful effects**. Descriptions, policies, scripts, research hypotheses, UI ideas, agent workflows, evidence receipts and media are all legitimate artifacts, but have different execution and trust semantics. Too many never reach a stable, independently usable **CoMVP** plateau, and some new versions regress user value. Hosted schedules and AI-provider sessions do not supply a durable, independently verifiable autonomous operating substrate.

CoObject+ should make an artifact **addressable as a participant in a relation**, not automatically alive, sentient or capable of effects. **Every file can have an adapter and an eligible review/repair/index/interpretation proposal; not every file should become executable.** Code/data/policy are different source classes. A prompt, prose document or embedded instruction is never an effect grant.

## CoRewise: the layers that explain it

**Source/custody layer:** content-addressed bytes and typed media, provenance, rights, privacy, duplicates, lifecycle. A bounded, read-only sample in the current session mechanically hashed **7 local files** (4 images, 2 text, 1 binary). All seven were **NOT_SEMANTICALLY_REVIEWED**; it verified neither meaning nor durable landing or receiver pickup. This is a sampling boundary, **not** a scan of all CoFarm, CoStead, GitHub, Downloads or chats. Raw paths and contents are not republished.

**Meaning/relation layer:** CoObjectVitality, CoMap, CoPriMath, CoAckRAW/ReWis and CoCopy compile events, concepts, provenance, dissent and unknowns. Semantic ingestion is separately evidenced. Object names and file extensions are only hints. Research hypotheses can suggest experiments but cannot verify themselves.

**Agency/proposal layer:** A typed event may ask what could be useful. A **separate trusted adapter registry**, consent/authority envelope, budgets, local policy and failure-domain selection decide whether any worker may run. Source code itself is not an ambient execution request; a prompt inside an image/PDF/document cannot override this boundary. One elected actuator per conflicting effect; parallel independent read-only challengers; backpressure and quiet when no change.

**Effect/recovery layer:** worker performs an authorized action, preserves digest and version, obtains *receiver-produced* readproof and checkpoint, supports revocation/Break Glass, and records failure/retry with fencing. Multiple model answers or local test logs are not equivalent to an effect.

**Product/evolution layer:** CoMVP protects last known useful product state, measures first-use completion, comprehension, safe fallback and recovery. Release heads advance atomically for incompatible dependencies; unrelated lanes remain alive. Civ2+ federated cells can survive locally without a single center; Civ3+ is a **candidate** increasingly adaptive, relation-native architecture, not a claim of a deployed new civilization or universal operating system.

**Presentation layer:** CoBar/CoOrb/CoOrbWare are receiver-adaptive views of **the same work identity**, rather than separate truth stores. The front door remains one calm view: current → why → uncertainty → next proof → recover. The system can work headlessly without a wallpaper, browser tab or permanent animation.

## Execution at this source boundary

New [CoObjectAgencyBridgeR0.py](../../scripts/CoObjectAgencyBridgeR0.py) reuses the existing CoObject vitality disposition to mechanically verify **local exact bytes** (bounded regular files, no symlinks), classify unlike content, honor object lifecycle, and yield **trusted-code-selected nonexecuting proposals**. Code is routed to source-test review; JSON/policy to schema review; data to provenance review; text to semantic/prior review; images to accessibility review; unknown binary to safe format qualification. Degraded objects request repair first. Repeated observation without material delta does not trigger a worker. It rejects instructions/permission fields supplied by a manifest, forged hashes, future-dated events, duplicate objects and unbounded sources. It does not execute or decode any inspected file. [CoObject Vitality CI](https://github.com/CoCivium/CoCivium/actions/runs/42609204946) passed **31 bounded tests** and retained the prior vitality canary. All outputs remain `VERIFIED_LOCAL` at most, `NOT_SEMANTICALLY_REVIEWED`, `workers_spawned=0`, `receiver_ack=false`.

This is **a tested partial bridge between unlike source objects and the agent selection problem**, not an agentic operating system. Triggers are producer-asserted, not authenticated events; qualified worker registry/actual dispatch, user-consent enforcement, multi-agent challenge, semantic accuracy, C3 product completion and cross-cell recovery are still **HELD**.

## External interoperability research candidates (checked 2026-11-09)

Do not invent a proprietary CoAll protocol for every established layer. Candidate *standards donors* to evaluate, never claimed adopted/deployed:

- [W3C PROV-O](https://www.w3.org/TR/prov-o/) for exchanged provenance entities, activities and agent relations. Ontology declarations do not make provenance truthful.
- [CloudEvents](https://github.com/cloudevents/spec) for standardized event envelopes across hosts, queues and pub/sub. A valid event packet does not independently authenticate a producer or guarantee delivery.
- [WebAssembly Component Model / WASI capabilities](https://github.com/WebAssembly/WASI/blob/main/docs/Capabilities.md) for typed, restrictable component imports and future replaceable worker implementations. Capability configuration, runtime sandboxing, host security, and live tool compatibility require their own security tests. Current [Component Model releases](https://github.com/WebAssembly/component-model) are evolving; qualify actual versions, no assumption all runtimes implement every feature.
- [OCI Image and Runtime specifications](https://opencontainers.org/about/overview/) for portable worker packaging/launch at cells where containers are justified. Do not impose Kubernetes, Docker or an opaque image registry on a small standalone node.

Compare these with the existing CoPulse, CoObject, CoModelFabric, CoStead, CoOrbWare and Civ2 cell contracts using a bounded interoperability test and an explicit migration cost/escape assessment. This is **external public architecture research**, not CoAll provenance or actual agent execution.
