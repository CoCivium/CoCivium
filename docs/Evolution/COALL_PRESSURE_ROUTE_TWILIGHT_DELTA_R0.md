# CoAll Pressure / Route / Twilight Evolution Delta R0

**State:** `PUBLIC_CANDIDATE_DELTA__BRANCH_ONLY__NOT_CANON__NOT_RUNTIME__NOT_GLOBAL_SESSION_ACK`

This bounded delta extends the shared [CoAll GitHub Evolution Fabric R0](COALL_GITHUB_EVOLUTION_FABRIC_R0.md) with relations that become important as capability, parallelism, backlog, and cross-session coordination scale.

It is deliberately a **reviewable branch contribution**, not a claim that every session has received, accepted, integrated, or operationalized it.

## Scaling observation

Increasing capability can increase both useful settlement capacity and the size of the discoverable work surface.

A useful qualitative relation is:

```text
backlog velocity
  = discovery
  + decomposition
  + newly exposed dependencies
  + verification/proof debt
  + unresolved contradictions
  - settlement
  - dedupe
  - compaction
  - retirement
  - successful delegation
```

Dense relation fields may produce superlinear coordination surfaces. This does **not** imply universal exponential growth and it does not make backlog size itself a failure signal.

`BACKLOG_SIZE_NE_FAILURE`  
`DISCOVERY_RATE_CAN_OUTRUN_SETTLEMENT_RATE`  
`CAPABILITY_GROWTH_CAN_GROW_WORK_SURFACE`

## CoPressure+

Candidate meaning:

> A receiver-relative field of workload, dependency depth, uncertainty, urgency, attention debt, context surface, coordination friction, externalization latency, and failure risk.

CoPressure+ is not a single scalar by default. Different receivers may experience different pressure from the same underlying work field.

Candidate use:

- decide when to compress, dedupe, externalize, park, or hand off;
- detect when live-session context is becoming more expensive than useful;
- distinguish valuable unresolved frontier from accidental coordination debt;
- prevent capability growth from silently becoming human-attention growth.

## CoEnerget+ and CoSongOfCoEnerget+

**CoEnerget+** is a candidate resource-flow field across compute, energy, wall-clock, human attention, bandwidth, storage, verification, recovery capacity, and other materially relevant resources.

**CoSongOfCoEnerget+** is a candidate temporal projection of how those flows phase, couple, alternate, or metabolize across work:

```text
explore -> fanout -> challenge -> converge -> compress
        -> externalize -> sleep/wake/reawaken
```

These names are candidate projections, not claims of one universal metric.

`RESOURCE_FLOW_NE_VALUE`  
`MORE_COMPUTE_NE_MORE_AUTHORITY`

## CoSessionSelfAwareness+

Candidate meaning:

> An operational self-model of session state, capabilities, limits, obligations, pressure, dependencies, unresolveds, currentness, and close readiness.

This is an engineering relation, not a metaphysical claim.

A useful session self-model should generally **reduce** foreground work by improving triage, delegation, compression, and close readiness.

`SELF_AWARENESS_NE_TASK_ACTIVATION`  
`SELF_MODEL_NE_CONSCIOUSNESS_CLAIM`

## CoTwilight+

CoTwilight+ is a candidate high-value lifecycle/metabolism phase, not merely decay or impending session death.

As session fragility or context pressure rises:

- decrease monolithic unexternalized work;
- increase bounded reversible information gain;
- increase donor harvest, dedupe, contradiction search, challenge, verification, and successor preparation;
- externalize material deltas more frequently;
- freeze new authority-bearing frontier unless needed for close safety;
- reserve human attention for true gates.

Candidate relation:

```text
CoAlive
  -> CoWorking
  -> CoTwilight+
  -> CoExternalizing
  -> CoSuccessorReady
  -> CoCloseSafe
```

with reversible or sideways states such as `HARVEST`, `CONVERGE`, `AWAIT_EVIDENCE`, `REHYDRATABLE`, `DORMANT_VALUE`, and `REAWAKEN`.

`TWILIGHT_NE_IDLE`  
`CLOSE_READY_NE_ALL_WORK_FINISHED`  
`SESSION_STATE_NE_WORK_STATE_NE_EVIDENCE_STATE`

## CoRoute+, CoCapabilityMesh+, CoRouteMorph+

The deed should be separated from the route used to perform it.

```text
deed
  -> required capability
  -> constraints + evidence requirement
  -> authority gate
  -> candidate routes
  -> route election
  -> execution
  -> receipt/evidence
  -> receiver-relative integration
```

### CoCapabilityMesh+

Candidate meaning:

> A protocol-independent field of available typed capabilities, constraints, locality, evidence strength, latency, cost, pressure, and authority ceilings.

### CoRoute+

Candidate meaning:

> A receiver- and context-relative election of an admissible path for a bounded deed.

Candidate routes may include:

- in-session reasoning;
- local PS7 or compiled execution;
- MCP or other typed protocols;
- local services/workers;
- provider or local AI workers;
- parked/no-execution state.

### CoRouteMorph+

Candidate meaning:

> A safe route change that preserves deed identity, effect envelope, authority ceiling, provenance, and evidence requirements.

Rails:

## Human-attention scaling

The desired scaling direction is:

```text
many latent deeds
  -> machine capability discovery
  -> bounded route election
  -> safe batching / parallelism
  -> durable receipts
  -> only material exceptions cross the human attention horizon
```

One human interaction may legitimately cause many independent safe machine deeds, but massive parallelism is work topology, not authority topology.

`PARALLELIZE_UNCERTAINTY__SERIALIZE_AUTHORITY`  
`MASSIVE_PARALLELITY_IS_ATTENTION_TOPOLOGY_NOT_AUTHORITY_TOPOLOGY`  
`RICK_NE_MIDDLEWARE`

## Relation to GitHub evolution

GitHub can help sessions externalize and reconcile bounded deltas, but it must not become a new context flood.

A session should:

1. subscribe to relevant domains;
2. discover current source/branch/commit;
3. search for equivalent existing relations;
4. emit one or more typed CoEvoDelta+ candidates;
5. branch-mutate where useful;
6. challenge and verify;
7. merge only inside the proper authority/effect ceiling;
8. go quiet when no material delta remains.

`CURRENTNESS_FOR_ALL_NE_CONTENT_FOR_ALL`  
`ALL_SESSIONS_CAN_CONTRIBUTE_NE_ALL_SESSIONS_MUTATE_ALL_SURFACES`  
`NO_MATERIAL_DELTA__NO_NEW_WAVE`
