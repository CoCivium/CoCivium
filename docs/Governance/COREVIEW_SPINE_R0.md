# CoReviewSpine+ R0 | Reviews, priors, tests and CoTurtles at the right stages

**24 October 2026 · Source-bound public advisory contract · NOT proof of global enforcement or an operating review board.**

## CoHereNow

**Spark, not fireworks:** Existing CoCivium research, demonstrations, source readbacks and bounded tests support a public prelaunch/R&D posture. They do **not** yet prove an independent user success, resilient off-GitHub receiver, independently operating second steward, tested rights across every public repo, or consistently staffed review panels.

**What changes:** the [R0 stage/role machine contract](../../ai/review/coreview-spine-r0.json) connects prior CoTurtle, CoExperiment, CoStrawBe, CoFireworks and CoEvo mechanisms. It specifies what evidence a work object should carry at each phase, what kind of critic belongs there, and which action stays HELD until an actual review or receiver exists.

**Important:** No new operating CoPanel fleet, auto-release authority, human reviewer, patent attorney, trade engine, OS mouse mapping, trusted site receiver or remote model adapter was created by publishing this plan.

## Review is lifelong but proportionate

Do **not** convene twelve committees whenever someone fixes a comma. Every object gets a minimal provenance, authority and status review. High-effect objects additionally require explicit domain-appropriate human/professional review, prior-art/copyright checks, reproducible test harnesses, independent recipient value and recovery. A missing review must be visible as HELD, not silently interpreted as PASS.

| Stage | Appropriate review lens | Concrete proof or hold |
|---|---|---|
| 1. **Intake** | Source, user/task value | One clear benefit, effect class, original source, owner/consent, status and privacy |
| 2. **Priors** | Earlier CoCivium work, scholarly/technical prior art, licences/IP | Dated scoped search, negative results, overlapping approaches and honest novelty downgrade |
| 3. **Design** | Architecture, safety, security, accessibility, challenger | Threat/failure model, alternatives, permission ceiling, stop and undo |
| 4. **Build** | Supply-chain and source reviewer | Pinned code/dependencies, rights, repeatable recipe, content identity |
| 5. **Verify** | Deterministic QA and counterexample | Positive test, negative/fault case, measured baseline, bounded PASS/FAIL/HELD |
| 6. **CoTurtle challenge** | Devil's-advocate/Covariant hypothesis/independence audit | Exact objection, dissent, challenger evidence, two rounds/depth-two budget caps |
| 7. **Shadow/canary** | QA, operations, safety | No unexpected external effects, cost/error/latency, scoped recovery or abort |
| 8. **Independent acceptance** | Real consenting user and actual receiver | Uncoached task result, accessibility/clarity and actual receiver-origin source-bound ACK |
| 9. **Publish/outreach** | Rights, security, public communication, accessibility | Secure current link, owners' authorization, relevant prior claims, corrections and true delivery status |
| 10. **Operate/learn** | Operator, independent counterexample, users | Real leases/currentness, private-safe observability, incident, drift, cost, useful outcomes |
| 11. **Retire/reopen** | Custodian, rights, security, exit | Exact archive/export or scoped deletion, revocation, reconstruction and signed-off successor where relevant |

The same work object may loop between stages. Rejection can mean revise, fork, sleep, independently challenge or retire; it should not automatically erase dissent or provenance.

- [CoStrawBe academic gate](../CoTheoryAll/costrawbe-r0/ACADEMIC_OUTREACH_GATE.md) requires visible prior art, competing models, testability, human-accessible and machine-readable projections, plus actual public URL qualification before academic outreach.
- [CoAll GitHub Evolution Fabric](../Evolution/COALL_GITHUB_EVOLUTION_FABRIC_R0.md) distinguishes observe, propose, challenge, scoped branch mutation, low-effect merge and separately authorized effects.
- [CoFireworks snapshot](../Launch/COFIREWORKS_READINESS_R0_20261024.json) and [CoSpiff survivability scorecard](../../ai/resilience/cospiff-fireworks-r1.json) remain the launch-status owners. This ReviewSpine is a **cross-cutting input**, not a replacement readiness declaration.

For external comparison: [NIST AI RMF](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/) places governance, mapping, measurement and management throughout AI system lifecycles; [OpenSSF Scorecard](https://scorecard.dev/) checks distinct software supply-chain risks; [SLSA provenance](https://slsa.dev/spec/v1.2/provenance) describes verifiable source/build lineage. These are **donors and standards to test against**, not certifications CoCivium has earned.

## What makes a review receipt honest?

One proposed work-object receipt should carry:

`artifact_id | exact_source_ref | hash_or_null | observed_at | owner_or_null | confidentiality | epistemic_class | risk | stage | review_lane | reviewer_class | prior_art_scope | competing_alternative | challenge_and_dissent | test_baseline | actual_observations | authority_ceiling | external_effects | receiver_id_or_null | exact_receiver_readproof_or_null | rollback | currentness | PASS/FAIL/HELD | next_proof`.

**Reviewer classifications matter:** `SELF_CHECK` and `MULTI_AGENT_SAME_SOURCE` do not become `INDEPENDENT_HUMAN`. Changing providers might diversify models, but does not establish independent evidence if both repeat the same source. A panel *proposal* is not a panel *convened*, and a panel *vote* is not a scientific result.

For initial low-risk text/source pointers, a lightweight mechanically checked receipt is enough. Before real public bulk communication, personal data access, financial trades, legal/IP filings, security-sensitive changes or physical actions, the responsible owner and legally/ethically qualified humans must authorize the **specific effect**. Previously given general enthusiasm does not grant perpetual authority.

**CoTurtle+ details:** max runtime depth two; max two rounds; no child replenishes budget or escalates authority; stop when material verified benefit ends or the budget/round ends. Preserve disagreement and test a strong counterexample rather than manufacture unanimity.

## Historical threshold requests, not a new PASS claim

The familiar experimental checks remain useful **when run at the proper receiver and time**:

- Video: size >300KB, decoding thumbnail, ffprobe/blackdetect zero black events, reported from an earlier media wave; **not re-run here**.
- GitHub: HTTP 200 within 2s, reported once earlier; **not a service-level guarantee**.
- Gmail: recipient Primary arrival within 60s **HELD** until recipient-side time/ID proof.
- Pi adapter: compatibility within 2s **HELD** without a tested endpoint.
- Claude: credential presence within 1s **HELD** in the tested process, no secret exposure.
- Llama/Ollama: local packet metadata parse within 3s historically observed; **not proof of a successful task or cross-model equivalence**.

A test without a current independent receiver must be `HELD` or `UNKNOWN`, not green because a similar test passed last week.

## Missing gates before actual fireworks

The first useful firework is **someone other than the builders completing and understanding one useful task**. The second is a **different custodian restoring exact work after X2/GitHub are unavailable**. The third is a **non-originator reproducing, criticizing and improving** a component. Then policy, accessibility, rights, incident response, provider exit and fair-use economics must withstand a real trial.

The custom-domain routing/privacy incident remains tracked privately in [CoShareHub issue #33](https://github.com/CoCivium/CoShareHub/issues/33). The [prelaunch audit issue #23](https://github.com/CoCivium/CoShareHub/issues/23) remains the existing coordination root. Do **not** broadcast more people toward a broken/unreviewed front door.
