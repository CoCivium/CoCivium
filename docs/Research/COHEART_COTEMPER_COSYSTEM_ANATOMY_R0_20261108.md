# CoHeart+ / CoTemper+ / CoSystem Anatomy+ / CoSeed+ / CoPath+
## Cross-substrate relational research R0 | 2026-11-08

**State:** PUBLIC RESEARCH CANDIDATE. NOT CANON, RUNTIME, DEPLOYMENT, BIOLOGICAL-LIFE CLAIM, RECEIVER ACK, OR PROVEN SYSTEMIC GAIN.

**Purpose:** Compare how living systems, nonliving physical systems, software, artifacts, organizations, and speculative models organize time, resources, boundaries, feedback, repair, continuity, and relationships. Reuse existing CoCivium research contracts rather than create an always-on heart, universal ontology, or new event bus.

**Evidence scope:** Read-only source-linked architecture review and candidate falsifiers. Some specific evaluator weaknesses are visible in public source and have been reported in isolated local tests; this public note is **not** a new independent CI execution or accepted repair. Do not infer operational X2/CoOrb activity or independent receiver pickup.

### 1. Principal proposition

Every addressable entity and relation MAY have typed temporal obligations: observation deadline, wake predicate, retention window, lease, readiness claim, source currentness, recovery route, and receiver evidence. It does NOT follow that every entity needs a continuously executing process, physical warmth, or a private ticking oscillator.

**CoHeart+** is a candidate name for *temporal-continuity governance* across those obligations, not a biological heart and not a standalone daemon. Evaluate event-only, shared-deadline, and dedicated-oscillator alternatives under matched workloads. Prefer the simplest approach that proves the necessary detection, latency, reliability, and recovery properties without wasteful per-entity activity.

**CoTemper+** is a candidate family of typed, role-relative projections, not one scalar measure of aliveness. Distinguish actual substrate temperature, computational work, data freshness, readiness, resource spending, interest/relevance, and independently verified recoverability. Warm does not establish healthy; cold does not establish dead.

A productive unit of scheduling may be the **time-bounded obligation on a relation** rather than the whole entity. A dormant archived theory can have one newly HOT research relationship without waking every descendant or recreating every worker.

### 4. Typed CoTemper+ relation vector

Candidate dimensions for an entity or edge:

| Dimension | Proper measurement / evidence | What it does NOT establish |
| --- | --- | --- |
| Physical thermal state | K or degrees C, sensor provenance, observation age | Life, usefulness, computation |
| Activity | Operations/s, valid event counts, verified process lease | Correctness or receiver value |
| Readiness | Qualified wake predicate, bounded response latency (s) | Active execution |
| Freshness | Trusted observation time, valid-time window, age (s), expiry | Truth from a self-declared timestamp |
| Resource consumption | Power W, energy J, memory bytes, compute, cost, human minutes | Net benefit |
| Relationship relevance | Explicit receiver/subscription class and evidence | Global priority or permission |
| Recoverability | Independent reconstruction, exact hash readback, recovery time (s) | Live service or acceptance |
| Useful return | Independent receiver proof, normalized outcome/time | Universal improvement or exponentiation |

**CoWarm+**: receiver-relative readiness or activity with explicit qualification. **CoCold+**: preservation or intentional inactivity with explicit wake/recovery semantics. Both are candidate projections; their meanings depend on a named dimension and receiver.

Possible auxiliary candidate vocabulary: **CoGradient+** (typed change over time); **CoThermostat+** (bounded transition controller, not another observer); **CoHysteresis+** (anti-flapping); **CoThaw+** (qualified restore); **CoCoolDown+** (bounded deactivation); **CoHeatDebt+** (unproductive resource expenditure, only after measurement); **CoPhase+** (typed transitions); **CoNull+** (absent versus unknown versus intentionally quiet).

No new per-entity watchers or services are justified merely by choosing names.

### 5. CoSeed+ and CoPath+ fan-out, with fail-closed fan-in

**CoSeed+ (candidate):** A source-linked starting hypothesis, relation, artifact, or action possibility, *not a mature result*. **CoPath+ (candidate):** A possible route containing dependencies, decisions, gates, evidence, recovery and receiver, *not an executable bridge or approval*. A prior CoLex candidate queue contains these terms; that queue is not canonical adoption.

The submitted spelling **CoSedd** has no verified definition in the scoped GitHub search. Preserve as unresolved alias/term rather than silently assume it means CoSeed.

**Research grammar:** source -> component/relation -> analogy -> disanalogy -> inversion/null -> candidate seed -> possible gated path -> falsifier -> evidence -> independent receiver readproof -> reuse/revise/sleep/retire.

Each seed may carry: identity, source hash, substrate class, assertion, alternatives, observer, evidence tier, units, risk, counterexample, authority and confidentiality. Each path may carry: prerequisite evidence, optional routes, capacity budget, stop condition, rollback, wake obligation and acceptance criteria. Fan out conceptually; fan in via contradiction, source identity, independent challenge, dedupe and receiver value. An inventory is not permission to spawn agents.

### 7. Public source-level test opportunities, not CI failures

The following are **bounded candidate negative tests** against public shadow code. Do not infer device failure, broad CI failure or merged repair.

**HEART-01: STOP collision leakage.** In [CoMetabolism R0A beat.py](../../examples/cometabolism_heartbeat_r0a/beat.py), the STOP suppression set is computed from plausible STOP events before the per-event duplicate-ID collision rejection. Two conflicting STOP records can therefore be held yet still suppress a valid source-change candidate. Test: valid SOURCE_DELTA + two conflicting STOP records => conflicting STOPs held, valid unrelated proposal not suppressed.

**HEART-02: unverified STOP observation.** In the same selector, STOP is marked observed before the generic synthetic-evidence validation for other event kinds. Test: a scope/privacy-valid but unverified STOP must be HOLD, not STOP_OBSERVED, and must not change lifecycle selection.

**HEART-03: future beat admission.** Freshness is computed as last_tick + ttl >= current_tick without rejecting last_tick > current_tick. Test: future-dated lease must HOLD as time anomaly, not qualify as fresh.

**TEMP-01: stale-active misclassification.** In [CoObjectVitalityR0.py](../../scripts/CoObjectVitalityR0.py), presence of currentness_state and health_state is validated, but the disposition decision does not consult their values. Compare current/healthy ACTIVE_WORKING with stale/unknown ACTIVE_WORKING: the stale case must not receive the same action as if qualified.

**TEMP-02: warm/cold inversion.** Warm-looking but stale/unattested worker versus cold artifact with independently demonstrated reconstruction and readproof. Do not infer healthy from warm nor dead from cold. Evaluate each typed dimension and its actual receiver.

**TEMP-03: receiver divergence.** An entity may be HOT for one observer, WARM or asleep for another, without global overwrites or duplicated actuators.

**TEMP-04: shared deadline efficiency.** Compare event-only, batched deadline, and dedicated oscillators with identical workloads, failure models and detection targets. Measure false positives, missed deadlines, p95 wake latency, energy/cost, independent recovery, receiver usefulness and coordination overhead.

**GAIN-01: stale incumbent.** CoGainLatch shadow gain classification must not accept a challenger merely because its observation is fresh if the incumbent is stale or lacks independent attestation. Inspect exact R1b source, if available, before proposing duplicate repair.

**GAIN-02: stale test masking.** Separate a fixed-time synthetic-evidence rejection test from an expired-time test, so age cannot make an unrelated invalid-evidence regression appear to pass.

For all tests: use trusted injected evaluation time, independently compare exact source hashes, preserve original failing evidence, retain predecessor and rollback, and label each outcome PASS/FAIL/HOLD/UNKNOWN.

### 8. Evidence and currentness rules

- **CoHeart != permanent process.**
- **CoTemper != physical heat; warm != healthy; cold != dead.**
- **CoSeed != proof; CoPath != authority or completed effect.**
- **CoPulse != runtime; lease != return; source PASS != receiver ACK.**
- **Unknown != absent; stale != dead; public repository != running device.**
- **Physical units are typed:** temperature K or C; power W; energy J; duration s; cost with declared currency; rates per bounded window.
- **Never claim exponential benefit without normalized comparable multiwindow data and independent return.**
- **Many observers, one elected actuator**, when and only when an authorized effect route exists; preserve zero-effect shadow boundary until then.
- **No new watcher**, duplicate frontier scan, X2 reconnect automation, provider/session mutation, outreach, expenditure or receiver assumption arises from this research note.
