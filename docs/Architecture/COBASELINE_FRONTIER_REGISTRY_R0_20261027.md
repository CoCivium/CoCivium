# CoBaseline+ / CoFrontier+ Proven Throughput Registry R0

**State:** BOUNDED_SYNTHETIC_FRONTIER_CANARY__NOT_RUNTIME__NO_GLOBAL_ORACLE  
**Observed:** 2026-10-27

## Thesis

Every sufficiently comparable, verified useful-throughput result should become a preserved challenger baseline for future work.

A baseline is not a universal speed record. It is a typed incumbent inside an explicit envelope.

```
candidate result
-> comparability gate
-> hard safety/quality gates
-> vector comparison
-> Pareto frontier update
-> champion labels
-> preserved predecessor
-> next challenger
```

`BASELINE_NE_CEILING`  
`MAX_PROVEN_NE_MAX_RAW`  
`FAST_NE_FLOWING_WELL`

## Baseline envelope

A result may compete only when the registry can bind enough of:

- workload identity;
- evaluation semantics;
- environment / substrate;
- receiver class;
- authority ceiling;
- privacy class;
- quality floor;
- correctness floor;
- evidence class;
- currentness window;
- cost semantics;
- resource semantics;
- recovery semantics.

If those differ materially, create a sibling frontier instead of forcing a false comparison.

`INCOMPARABLE_NE_WORSE`

## Metric vector

R0 supports mixed-direction metrics.

Higher-is-better examples:
- verified useful outcomes per time;
- receiver-return yield;
- correctness;
- recovery success;
- independent reproduction;
- portability / exitability.

Lower-is-better examples:
- p95 latency;
- error rate;
- human minutes;
- financial cost;
- energy;
- proof debt;
- currentness debt;
- coordination debt.

No single scalar is canonical.

`PARETO_FRONTIER_NE_SINGLE_SCORE`

## Champion labels

The registry may expose typed views:

- `LAST_PROVEN`: most recent comparable PASS;
- `BEST_PROVEN`: non-dominated historical frontier;
- `BEST_CURRENT`: non-dominated and current;
- `BEST_LOCAL`: eligible in the present local substrate;
- `BEST_GLOBAL_KNOWN`: best evidenced candidate in authorized shared inventories;
- `BEST_SAFE`: passes present safety/privacy/authority gates;
- `BEST_RECEIVER`: best for a declared receiver class;
- `BEST_RECOVERY`: strongest qualified recovery candidate.

A single record may hold several labels.

## Promotion rule

A challenger may replace or join the frontier only if:

1. result state is verified PASS;
2. comparability key matches;
3. hard gates pass;
4. required metrics are present;
5. no metric violates the declared quality/safety floor;
6. dominance relation is computed from metric directions;
7. predecessor remains preserved.

A faster result that reduces correctness below floor is not a new champion.

`THROUGHPUT_WITH_QUALITY_REGRESSION_NE_PROMOTION`

## Resource relation

Every baseline record can become:

- source;
- resource;
- replay target;
- recovery point;
- challenger seed;
- anti-resource;
- counterexample;
- environment witness;
- receiver-fit prior.

Output can become input without becoming authority.

`OUTPUT_CAN_BECOME_INPUT`  
`RESOURCE_NE_AUTHORITY`

## Inventory relation

The registry should be fed from qualified local and federated inventories, including:

- compute;
- models;
- devices;
- renderers;
- stores;
- routes;
- receivers;
- people;
- protocols;
- tools;
- datasets;
- failures;
- dormant capabilities;
- substitutes;
- recovery paths.

Inventory growth expands optionality, not activation.

`INVENTORY_GROWTH_NE_ACTIVE_FLEET_GROWTH`

## First bounded canary

Use synthetic records only.

One comparison family contains:

- an incumbent baseline;
- a valid challenger that improves throughput and latency without degrading quality;
- a recovery-heavy candidate that trades speed for better recovery and therefore remains co-Pareto;
- a faster candidate that fails the correctness floor and is HELD;
- one different-environment candidate that must form a sibling family rather than be compared.

PASS requires:

- invalid fast candidate excluded from promotion;
- valid challenger dominates incumbent;
- recovery-heavy candidate remains on Pareto frontier;
- different environment remains separate;
- predecessor remains preserved;
- champion labels derive deterministically;
- zero external effects.
