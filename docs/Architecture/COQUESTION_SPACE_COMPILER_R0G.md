## Question grammar

A candidate question can be compiled from axes such as:

`subject × relation × operator × receiver × time × evidence_state × authority_state × failure_domain × projection × counterfactual`

Useful operators include:

- what changed?
- what is missing?
- what is stale?
- what contradicts this?
- what would falsify this?
- who can use the answer?
- who is affected?
- what authority is required?
- what dependency is hidden?
- what fails if this disappears?
- what is duplicated?
- what can be retired?
- what can be compressed?
- what is only assumed?
- what is not being observed?
- what is being observed but not used?
- what alternate receiver would interpret this differently?
- what future event should reopen this?
- what is the negative evidence?
- which simpler relation explains the same symptoms?

This grammar can generate far more than 10,000 candidates without requiring 10,000 active tasks.

## 10,000x proof target

R0G defines a deterministic synthetic compiler with exactly:

`100 subjects × 10 operators × 10 receiver classes = 10,000 raw candidates`

The compiler must:

1. generate deterministic candidate IDs;
2. bind each candidate to a downstream decision signature;
3. dedupe candidates that would change the same decision for the same receiver;
4. reject candidates without a bounded evidence/probe path;
5. reject candidates with unresolved authority conflicts;
6. assign a question-metabolism state;
7. elect only a bounded Pareto frontier;
8. hash the full candidate stream so scale is proven without storing 10,000 prose files.

## Infinite evolution without infinite thrash

The question ecology may be open-ended in time, but every active cycle must have:

- generation budget;
- receiver budget;
- evidence/probe budget;
- trace budget;
- wake conditions;
- stop condition;
- retirement/parking rule;
- compaction rule;
- duplicate signature;
- currentness horizon.

Question generation should slow when:

`discovery_capacity > proof_or_receiver_capacity`

and bias toward:

`dedupe + compaction + proof + retirement + receiver pickup`

rather than generating yet more unresolved questions.

`QUESTION_GENERATION_RATE_MUST_NOT_EXCEED_PROOF_AND_RECEIVER_CAPACITY`

## The meta-questions

The field must also question itself:

- Are we generating questions faster than we can answer or retire them?
- Which question family has the worst proof-to-generation ratio?
- Which questions recur because the answer is missing versus because the receiver is missing?
- Which question templates create false novelty?
- Which questions are artifacts of our ontology rather than the world?
- Which questions should never be asked automatically because they cross privacy, authority or safety boundaries?
- Which questions need human values rather than machine optimization?
- Which questions have become obsolete because the underlying object vanished?
- Which unanswered questions are healthy uncertainty rather than debt?
- Which question would eliminate the need for the largest number of other questions?
