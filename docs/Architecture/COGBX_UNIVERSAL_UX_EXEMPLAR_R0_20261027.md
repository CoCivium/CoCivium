# CoGbx+ / CoOrbWare+ Universal UX Exemplar R0

**State:** PUBLIC_SAFE_EXEMPLAR_CANDIDATE__STATIC_OFFLINE__NOT_DEPLOYED_TO_COGBX_ORG  
**Observed:** 2026-10-27

## Lead

The convergent UX recommendation across current CoCivium architecture is:

> one durable relational work fabric, many optional embodiments, very few visible surfaces.

The user should not have to manage provider tabs, model sessions, device-specific state, or backend worker topology as the primary information architecture.

Target:

```
CoWorkObject / CoVirtualSession
-> CoQuanta / PulseField
-> CoMap relation field
-> CoOrb receiver-relative focus
-> CoOrbWare projection
-> Text | Orb | Map | Ambient | Spatial/3D | XR | Mobile | Desktop
```

Every projection is disposable. Work identity is not.

`WORK_NE_WINDOW`  
`PROJECTION_NE_SOURCE`  
`DEVICE_NE_IDENTITY_ROOT`

## Why X2 is the exemplar

X2 is useful precisely because it makes failure modes obvious:

- very large screen area can still become a wall of independent provider rectangles;
- browser tabs can blank/stale/reload;
- continuity can be confused with keeping windows open;
- dense text can consume the display without improving relational understanding;
- repeated user relay remains visible when the control plane is fragmented.

The exemplar should therefore prove that a large desktop can become **calmer as capability increases**.

`MORE_CAPABILITY_NE_MORE_CHROME`

## Universal device contract

Every device class should consume the same typed work state while choosing a suitable projection.

### Tiny / glance

Watch, lock-screen-safe notification, narrow phone:
- one current state;
- one uncertainty;
- one reversible next action;
- no private payload by default.

### Phone

- HereNow;
- focused Orb;
- Text;
- compact Map;
- capture / CoThumb-equivalent;
- recovery and send/effect gates.

### Tablet / laptop

- Orb + Map;
- optional side evidence;
- predictive shadow input;
- virtual-session switch without provider-tab semantics.

### X2 / large desktop

- one primary relational field;
- a small persistent CoBar;
- sparse CoOrbs;
- spatial trails and currentness;
- optional local provider/render surfaces as temporary embodiments;
- no permanent dashboard wall.

### XR / spatial / future surfaces

- preserve exact 2D/Text accessibility projection;
- project relation topology spatially only when it reduces search/navigation or improves comprehension;
- spatial depth may encode relevance, currentness, confidence, dependency, or recovery distance;
- never require 3D interaction for a critical task.

`3D_NE_MANDATORY`  
`XR_NE_HIGHER_AUTHORITY`

## Progressive holography

"Holographic" means any bounded projection contains enough identity, provenance, currentness, recovery pointers, and relation anchors to reconstruct the useful work context for that receiver.

It does **not** mean every projection contains all data.

```
tiny glance
-> focused Orb
-> relational Map
-> deep Text/evidence
-> spatial/3D projection
```

Each level is a view of the same work object.

`HOLOGRAPHIC_NE_COMPLETE_COPY`

## Fractal relation

The same grammar should hold at multiple scales:

```
object
-> task
-> project
-> program
-> organization
-> community
-> federation
-> ecosystem
```

Each may expose:

`CURRENT | WHY | NEXT | UNKNOWN | CHALLENGE | RECOVER`

A nested object inherits no extra authority merely because it sits inside a larger one.

`FRACTAL_NE_AUTHORITY_MULTIPLIER`

## Non-crown / non-capturable design

No single:

- provider;
- browser;
- model;
- account;
- domain;
- database;
- machine;
- person;
- organization;
- AI agent

should be able to become the sole continuity root.

The UX should make substitution visible:

```
LOCAL
WEB
PEER
MODEL_A
MODEL_B
TYPED_RECOVERY
```

and show when only one path remains.

Candidate resilience indicator:

`PATHS 4 | INDEPENDENT FAMILIES 3 | RECOVERY 2 | CROWN RISK LOW`

`REDUNDANCY_NE_DUPLICATE_AUTHORITY`  
`NO_CROWN_NE_NO_STEWARDSHIP`

## Predictive but non-coercive

Prediction runs in a shadow layer:

```
RAW
-> ACK_RAW
-> RELATE
-> PREDICT
-> PREVIEW
-> ACCEPT / REJECT
-> EFFECT GATE
-> RECEIPT
```

Prediction can cover:
- likely next text;
- likely next evidence;
- likely next tool;
- likely failure;
- likely alternative;
- likely receiver;
- likely recovery;
- likely visualization.

It may precompute aggressively.

It may not silently send, spend, publish, delete, authenticate, or change accounts.

`PREDICTED_NE_AUTHORIZED`  
`PRECOMPUTED_NE_EXECUTED`

## Evolution to each user

Personalization should learn:
- information density preference;
- preferred projection;
- accessibility needs;
- accepted/rejected predictive patterns;
- interruption tolerance;
- evidence depth;
- device context;
- local/remote preference;
- privacy ceiling;
- recurring workflows.

It should not learn away:
- authority;
- consent;
- privacy boundaries;
- provenance;
- recovery;
- challenge/appeal;
- exit.

`PERSONALIZATION_NE_CAPTURE`

User state should remain exportable and reconstructable where technically possible.

## CoGbx role

Existing Master Plan lineage already describes `cogbx.org` as a light active **CoGbxNet / exchange-layer concept + reference-docs hub**.

R0 therefore treats CoGbx.org as a candidate **exemplar landing**, not the identity root of CoAll.

Recommended public front door:

1. **One sentence:** "One work fabric. Many devices, models and communities. No single crown."
2. **Try locally:** open the zero-network exemplar.
3. **See the same work four ways:** Orb / Map / Text / Ambient.
4. **Predictive input:** preview, accept/reject, undo.
5. **Recovery:** prove the work survives the surface.
6. **Evidence:** exact source, tests, nonclaims.
7. **Fork / leave:** portable public artifacts and clear exit.

No sign-up should be required to understand or run the public-safe exemplar.

`LANDING_NE_LOCK_IN_FUNNEL`

## Device evolution ladder

### R0
Static responsive source exemplar.

### R1
Independent accessibility review:
- keyboard;
- screen reader;
- zoom;
- reduced motion;
- high contrast;
- narrow viewport.

### R2
X2 local reconstruction:
- bind one real local work object;
- no provider mutation;
- recover after renderer closure.

### R3
Phone/tablet parity:
- same task packet;
- same currentness/evidence;
- device-specific projection only.

### R4
Independent renderer parity:
- WebView2/Chromium family;
- Firefox/Gecko family;
- typed headless recovery projection.

### R5
Spatial/XR canary:
- same object digest;
- 2D fallback remains complete;
- 3D demonstrably improves one bounded navigation/comprehension task.

### R6
Peer/federated receiver:
- exact-object readproof;
- no central service required for reconstruction.

## Generative UX grammar

Do not enumerate zillions of screens.

Generate projections from dimensions:

```
receiver
x device
x viewport
x input_mode
x accessibility
x privacy
x attention
x work_scale
x currentness
x confidence
x authority
x topology
x embodiment
x network_state
x recovery_state
x prediction_state
x evidence_depth
x spatiality
x motion_budget
x energy_budget
```

Hard gates first.

Then choose the smallest projection that preserves:
- work identity;
- currentness;
- uncertainty;
- authority;
- next action;
- recovery;
- evidence access.

`ZILLIONS_LOGICAL_NE_ZILLIONS_VISIBLE`

## First-use acceptance

A first-time user should be able to answer within roughly one minute:

1. What is this?
2. What is current?
3. What can I safely do?
4. What is uncertain?
5. How do I recover?
6. How do I leave/fork/export?
7. Where is the evidence?

No CoCivium vocabulary knowledge should be required.
