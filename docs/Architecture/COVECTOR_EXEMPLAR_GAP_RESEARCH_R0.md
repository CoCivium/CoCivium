## Decision

Treat **CoVector+ as a proposed evidence-bound differential discovery lens** over CoAll/CoSysAll/CoMap, *not* another global ontology or a literal mathematical vector for incompatible concepts. `CoVector+` terminology has **not been qualified against the complete GIBindex/CoLex term corpus**; preserve it as a candidate alias. Its work is to compare current verified capability with a precise receiver need, isolate useful differences, propose distinguishing experiments, and preserve failed hypotheses.

`SOURCE -> QUALIFIED EXEMPLAR -> RECEIVER REQUIREMENT -> CAPABILITY/UNKNOWN GAP -> COMPETING EXPLANATIONS -> DISCRIMINATING EXPERIMENT -> INDEPENDENT OBSERVATION -> ADOPT/REVISE/REJECT/SLEEP`

A difference between an aspirational design and a standard's published feature list does **not** demonstrate the standard, its wider product ecosystem or its users lack that feature. The only valid "novel" label follows a systematic prior-art review plus reproduced technical evidence. Even a positive technical result is not proof of scientific originality, market advantage, broad safety or patentability.

No evidence is claimed that the global platforms *do not* already implement similar cross-domain approaches in some other product/extension.

## Six ranked investigation fronts, not six proven inventions

| Candidate | Researchable intersection | First failure-controlled proof |
| --- | --- | --- |
| **CV01** | Source identity and permissions survive visual, accessible and no-render projections | Compare exact object IDs, provenance and authority in all three views; fail if a candidate is promoted |
| **CV02** | Rights-aware deep media retrieval plus interstitial semantic links | One rights-cleared IIIF image, registered relation, no unauthorized fetch, same accessible meaning, measured bytes |
| **CV03** | Inverse, missing and contradictory relations as explicit questions | Insert a false reverse link and expired claim, require correct UNKNOWN/REJECT by independent readers |
| **CV04** | Rich-media meaning survives original host/coordinator loss | Independent cold restore of exact source+rights/manifest; measure actual RTO/RPO, human relay and receiver ACK |
| **CV05** | Human/system UX evidence returns as **CoEvoDelta.HYPOTHESIS/PROPOSE**, not governance authority | Demonstrate a confusing view, generate proposed fix, reject forged permission and require review |
| **CV06** | Evolve evaluation methods without self-certifying regressions | Old/new evaluator shadow comparison against a frozen independent negative-control witness |

**Priority:** CV01 and CV05 are relatively cheap fixture/review candidates because [CoSysAll R0](../../examples/cosysall/README.md) already provides visual/list/machine projections and the [reciprocity bridge](../../tools/cosysall_reciprocity_r0/README.md) has 17 passing **local** fixture tests. CV03 follows naturally. CV02 requires actual cleared high-resolution media; CV04 requires a separately controlled failure domain; CV06 needs a real independent evaluator/acceptance process. Cost, value and feasibility have **not** been measured or ranked quantitatively.

### Evidence and CoVector selection protocol

1. State one receiver's actual need, current task and observable failure. Do not rank generalized "civilization benefit" with one unexplained score.
2. Bind official exemplar documentation, version/date and at least one representative implementation where possible. Qualify requirements absent from documentation as **UNKNOWN**, not "missing worldwide".
3. Represent capabilities on **noncommensurable axes**: source integrity, semantics, time/currentness, privacy/rights, locality/recovery, UX/accessibility, operations, cost, uncertainty. Keep a Pareto frontier rather than an artificial single scalar.
4. For each candidate, write the *strongest counterexample* and an independent witness/test. Include a null hypothesis: the global exemplar can already solve the proposed problem by integration or configuration.
5. Use a bounded sandbox with public/licensed artifacts and synthetic private-data tests. Capture source SHA, input fixture, environment, p50/p95 where applicable, actual costs, forbidden requests, false promotions, rollback and negative outcomes.
6. Emit a typed `CoEvoDelta` under `PROPOSE` or `REVIEW_CHALLENGE`, no inferred permission, and an explicit qualified next receiver. Keep unchosen candidates dormant with wake triggers.
7. Promote an interoperability improvement only when its actual useful outcome is reproduced. Scientific discovery, independent-provider acceptance, audience return and governance adoption are separate claims requiring separate proof.

### Deliberate inversion and counterexample lanes

- **No new architecture may be needed:** integration of IIIF + Wikibase + PROV + existing rendering may already beat a novel platform.
- **More resolution can be worse:** extra payload may decrease comprehension, accessibility or trust and increase inference/rights leaks.
- **More graph links can be worse:** strongly connected incorrect ideas propagate misinterpretation; source agreement can reflect correlated citations.
- **Less rendering can be better:** privacy-denied/no-screen/offline packet can outperform a visual treatment on the receiver's actual task.
- **Resilient copies can be fake diversity:** two hosts may share operator, credentials, registrar, CDN, model provider, key or upstream dependency.
- **No discovery is a result:** a negative or duplicate finding can avert costly reimplementation and still improve the system.

### R0 measured boundaries

- GitHub source graph: **56 public-registered objects / 61 typed relations**, a historical projection, not live planetary graph.
- CoSysAll browser: **seven semantic LOD levels** including an explicit evidence boundary; machine-only zero canvas drawing in local browser QA. Not IIIF streaming, independent media comprehension or live physical simulation.
- CoAll↔CoSysAll reciprocity fixture: **17 local Python unittest cases** passed on a small synthetic derivative; sample packet matches listed required fields/enums for CoEvoDelta v0.1. Not independent receiver pickup, rights certification or a global graph integration.
- CoVector R0: **nine documented exemplars, six testable candidate intersections**, no global product benchmark, novel prior-art claim, production adoption, external reviewer, CoEx, or independent-source discovery yet.

## One highest-value next experiment

**Do CV01 + CV05 as a joined low-effect acceptance experiment** on the current source graph. Show one vision/plan/rights/object/receipt path in visual, accessible and machine-only projections; deliberately inject an invalid/expired permission and misleading inverse link; record equal object identity, provenance, zero unauthorized effects, a reviewable CoEvoDelta proposal, and a human/independent verifier's comprehension. Hold if no real audience permission or external receiver is available.

Then advance CV02 using one properly licensed IIIF object, or CV04 if a distinct hosting cell is independently qualified. Do **not** auto-create a global worker farm or a new scheduler merely because the candidate graph is interesting.
