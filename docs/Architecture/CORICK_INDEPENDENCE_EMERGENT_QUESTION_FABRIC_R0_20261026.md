## Prime invariant

`RICK_MUST_NOT_BE_REQUIRED_FOR_SYSTEMIC_DISCOVERY`

Rick may contribute, challenge, inspire, or veto within his real authority, but CoAll must not depend on Rick to:
- notice cross-domain blind spots;
- ask inversion / null / else questions;
- connect dormant assets;
- detect self-interference;
- trigger meta-evolution;
- surface missing maintenance energetics;
- identify receiver starvation;
- propose successor frameworks;
- preserve unpopular alternatives;
- or remember what the system forgot to ask.

Founder insight is an input, not a required runtime dependency.

`FOUNDER_NE_REQUIRED_ORACLE`

## Why prior machinery was insufficient

Existing CoEvoAll / NodeNeedPull / MetaEvolution mechanisms could:
- detect typed needs;
- pull resources;
- canary;
- prove;
- learn;
- sleep/wake;
- mutate selection machinery with evidence;
- preserve lineage and dissent.

But they were mostly **need-reactive**.

They did not strongly require periodic generation of higher-order questions such as:
- What assumptions are we not representing?
- What categories are inherited from legacy?
- What is decaying because nobody owns maintenance?
- What useful contradiction is being suppressed by current framing?
- What would an outsider notice?
- Which stable regime has become capture?
- Which instability is actually useful?
- What is the orthogonal alternative to both current poles?
- What would invalidate the current superframework?
- Which important relation exists only because Rick keeps reintroducing it?

Therefore the missing layer is a **proactive epistemic pressure field**.

## CoBlindSpotPressure+

A node should gain epistemic pressure when any of the following rise:
- long time since meaningful challenge;
- repeated same-family outputs;
- one observer/model dominates;
- no null or counterexample recorded;
- no edge-origin return;
- growing vocabulary with flat proof;
- unresolved stale currentness;
- founder-originated deltas dominate;
- repeated manual reminders are needed;
- high internal activity but low receiver delta;
- no explicit retirement / successor path.

Pressure does not authorize effects. It wakes inquiry.

The system should track:

- which lenses were neglected;
- which domains were overrepresented;
- which questions only Rick supplied;
- which breakthroughs came from outsiders;
- which questions arrived too late;

Then evolve the question-selection machinery itself.

## Rick-dependence metric

Candidate vector:
- percent of material deltas first proposed by Rick;
- percent independently rediscovered by another node/agent;
- median time to rediscover a withheld Rick-style question;
- count of active workflows blocked only on Rick relay;
- count of manual reminders needed per useful cycle;
- percent of major assets with non-Rick wake/maintenance owners;
- independent recovery without Rick;
- independent challenge and successor proposals without Rick.

Target:
`RICK_CRITICAL_PATH -> 0 WHERE_SAFE_AND_FEASIBLE`

not:
`RICK_VALUE -> 0`

Rick remains a participant, not infrastructure.

## Withheld-founder test

Periodically run a bounded shadow test:

1. hide one non-sensitive founder-originated insight from the candidate worker set;
2. expose only surrounding evidence and source graph;
3. ask diverse workers to generate highest-value missing questions;
4. measure whether the insight or a better equivalent emerges;
5. record time, route, disagreements, and failure;
6. update question-generation recipes.

This is a test of system independence, not deception of affected humans.
