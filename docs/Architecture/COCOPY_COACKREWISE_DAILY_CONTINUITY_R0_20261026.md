# CoCopy+ / CoAckRewise+ Daily Continuity R0

**State:** CANDIDATE_LOCAL_UX_CONTRACT__NOT_RUNTIME__NOT_THOUGHT_INFERENCE__NO_EXTERNAL_EFFECT
**Observed:** 2026-10-26

## Thesis

CoCopy+ should evolve from a clipboard-like concept into a human-scale episodic continuity layer for CoOrb+.

Humans often maintain a rough temporal log of what they said, typed, offered, accepted, revised, postponed, contradicted, or still mean to revisit. CoCopy+ can make that continuity explicit, inspectable, source-bound, reversible, and searchable.

`COCOPY_NE_CLIPBOARD_ONLY`
`COCOPY_NE_SURVEILLANCE_LOG`

## CoAckRewise relation

Candidate event grammar:

`SOURCE_EVENT -> ACK -> REWISE -> STATUS -> RELATIONS -> NEXT / SLEEP / RETIRE`

An AckRewise entry may represent:
- acknowledged;
- accepted for this scope;
- revised;
- challenged;
- contradicted;
- superseded;
- deferred;
- unresolved;
- rejected;
- forgotten by request;
- restored from history.

`ACK_NE_AGREEMENT`
`REWISE_NE_CANON`

## Daily ribbon

CoCopy+ default projection should be a compact chronological ribbon, not a giant transcript.

Example:

`02:13  CoAkimbo+ clarified -> productive disequilibrium, not chaos`
`02:18  CoG_dIn+ bounded -> inversion generates questions, not answers`
`02:23  Rick-independence invariant added -> founder not required oracle`
`02:29  CoOrb local UX -> X2 observer offline; historical pass only`

Each row expands to:
- exact source / source pointer;
- who or what generated it;
- observed time;
- evidence class;
- acknowledgement state;
- revision lineage;
- affected work objects;
- unresolved questions;
- currentness;
- privacy class;
- successor / retirement state.

## Thoughts / inner-state boundary

CoCopy+ must not infer private thoughts, intentions, emotions, beliefs, or memories from behavior.

A thought may enter CoCopy+ only when the person deliberately records or dictates it, or explicitly imports a personal note.

`THOUGHT_NE_OBSERVED_EVENT`
`BEHAVIOR_NE_INNER_STATE`
`JOURNALED_THOUGHT_NE_MIND_READING`

## Memory modes

### NOW
Last few material events.

### TODAY
Chronological daily continuity.

### THREAD
All events attached to one work object or relation.

### ACKREWISE
Only acknowledgements / revisions / challenges / supersessions.

### UNRESOLVED
Open loops and unknowns.

### RECEIPTS
Only effects with evidence.

### RECOVERY
Failure/recovery lineage.

### FORGOTTEN / EXCLUDED
User-controlled exclusions and deletion requests where storage authority permits.

## CoOrb relation

CoOrb summons CoCopy contextually:

`SELECT OBJECT -> SHOW CURRENT -> SHOW LAST MATERIAL DELTAS -> SHOW ACKREWISE LINEAGE -> SHOW UNRESOLVED -> SHOW NEXT`

CoBar may show a tiny count:

`TODAY 17 | ACKREWISE 5 | OPEN 3 | RECEIPTS 4`

Counts are navigation aids, not productivity scores.

`COUNT_NE_VALUE`

## CoMap relation

CoCopy provides temporal sequence.
CoMap provides relational topology.

Together:

`WHEN <-> WHAT <-> WHY <-> SOURCE <-> RELATIONS <-> CURRENTNESS`

A timeline event can expand into its CoMap neighborhood; a CoMap node can open its event lineage.

## CoCrystalMorph / wallpaper / screensaver relation

Shared typed state may be projected aesthetically without turning ambience into evidence.

### Desktop layer
- calm current work constellation;
- recent material deltas;
- dormant/high-option-value seeds;
- current blockers;
- recovery state.

### Wallpaper / CoOrbCanvas
- low-motion relation field;
- receiver-appropriate visual atmosphere;
- currentness encoded redundantly by text/icon/pattern, never color alone;
- no sensitive text by default.

### CoDream / screensaver
- idle-only reflection;
- summaries of completed, unresolved, and sleeping work;
- optional generative diagrams from safe local state;
- lock-screen privacy mode;
- no fake progress animations.

`AMBIENCE_NE_RUNTIME_PROOF`
`BEAUTY_NE_CORRECTNESS`

## Privacy / retention

Default local-first.

Every event should carry:
- source;
- retention class;
- privacy class;
- exportability;
- expiry;
- deletion/forgetting rule where supported;
- whether content or only metadata is retained.

Sensitive payloads should be summarized or redacted where possible.

`LOGGING_NE_KEEP_EVERYTHING`
`HISTORY_NE_PERMANENT_RETENTION`

## Daily compaction

At day boundary or user-defined interval:

`RAW_EVENTS -> DEDUPE -> CLUSTER -> MATERIAL_DELTAS -> OPEN_LOOPS -> RECEIPTS -> SUMMARY -> POINTERS_TO_SOURCE`

Preserve exact source pointers where rights and retention permit; do not stuff every raw event into the next day's active context.

## Founder-independence relation

CoCopy+ can help eliminate Rick relay by allowing successor workers to reconstruct:
- what changed;
- what was already rejected;
- what remains unresolved;
- what Rick had to repeat;
- which questions emerged independently;
- which current work objects need wake/review.

Candidate metric:

`REPEATED_RICK_REINTRODUCTION_COUNT`

A falling count is good only if independent reconstruction remains accurate.
