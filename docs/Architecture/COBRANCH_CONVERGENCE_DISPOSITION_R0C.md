## Purpose

The branch field is now large enough that "keep creating branches" is itself a failure mode.

R0C gives the high-overlap frontier-discovery branches explicit dispositions without merging or closing any of them.

The useful shape is:

```text
conceptual branch
-> inspect existing Git branch ecology
-> reuse compatible host when possible
-> preserve genuinely distinct proof lanes
-> relate donor branches
-> manifest exact donor deltas
-> require receiver readproof
-> preserve lineage / negative knowledge / wake conditions
-> only then consider retirement
```

A conceptual branch does not require a Git branch.

`CONCEPTUAL_BRANCH_NE_GIT_BRANCH`

## Branch creation policy

Default:

`RELATE_BEFORE_BRANCH`

A new Git branch should be justified by one or more of:

- distinct collision domain;
- independent canary;
- incompatible authority envelope;
- adversarial alternative;
- frozen review isolation;
- proof that should not mutate an existing candidate host.

Ordinary conceptual exploration should usually remain relational inside an existing compatible host or as a non-Git conceptual branch.

## Why zero branches is not the goal

Some branches are useful because they preserve independent evidence, disagreement, review isolation or rollback.

Therefore:

`ZERO_OPEN_BRANCHES_NE_HEALTH`

The goal is lower **untyped branch debt**, not a cosmetically empty PR list.
