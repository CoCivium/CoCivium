# CoRelationalUX+ / CoPredictiveInput+ / CoVirtualSurface+ R0

**State:** CANDIDATE_ARCHITECTURE__PUBLIC_WORKING_NOTE__NO_PROVIDER_ACCOUNT_RETIREMENT_CLAIM

## Lead

A mature CoCivium should not require the user to live inside provider-native chat UX.

Virtual sessions, relational currentness and provider-neutral adapters can support a CoCivium-owned interaction layer in which:

`many virtual sessions -> few materialized workers -> one coherent relational UX`

Provider interfaces remain optional embodiments, not identity roots or mandatory front ends.

## One relation fabric, many projections

The semantic source is the relation/currentness fabric. CoMap+, CoOrb+, CoOrbWare+, RickBar/CoDesktop, wallpaper, ambient panels and screensaver layers are receiver-specific projections.

`RELATION_FABRIC -> CoQuanta packets -> PulseField deltas -> CoMap -> CoOrb -> CoOrbWare surfaces`

A projection does not own or silently rewrite its source.

## CoQuanta+ boundary

CoQuanta+ MAY serve as the smallest useful relational/render packet: identity, state, time, relations, evidence, uncertainty, authority, substrate and receiver relevance.

This is an operational representation. It is not evidence of physical quantum behavior, sentience or subjective experience.

## nD+T+ rendering

Higher-dimensional state SHOULD be represented through typed relations, temporal layers and receiver-relative projections rather than literal attempts to display every dimension at once.

`glance -> hover -> focus -> inspect -> challenge -> reproduce`

## CoPredictiveInput+ : beyond the cursor

Input systems MAY predictively prepare *candidate continuations* beyond the current cursor.

Examples:

- likely next command;
- likely resource/object reference;
- probable continuation packet;
- alternate formulation;
- missing evidence link;
- relevant prior relation;
- expected tool/model route;
- likely next test;
- likely recipient-relative projection.

Prediction operates in a shadow buffer.

`PREDICTED_NE_TYPED`
`PREDICTED_NE_AUTHORIZED`
`PRECOMPUTED_NE_EXECUTED`

Nothing outward or irreversible happens solely because it was predicted.

## CoAckRAW+ / CoReWis+ boundary

Preserve the raw input/effect boundary before reinterpretation.

Candidate sequence:

`RAW_INPUT -> ACK_RAW -> PARSE -> RELATE -> PREDICT -> PROPOSE -> USER_OR_AUTHORITY_ACCEPT -> EFFECT -> RECEIPT`

CoReWis+/rewrite/normalization MAY offer better forms while retaining the exact original input and provenance.

`REWRITE_NE_REPLACEMENT_OF_RAW`

## Predictive forwarding

A bounded receiver MAY receive a *forecast pointer* before full work is committed when:

- the route is local/private or otherwise authorized;
- no irreversible effect occurs;
- confidentiality is preserved;
- the forecast is clearly marked;
- cancellation/override remains available;
- prediction quality is measured.

Example:

`cursor@t -> shadow continuation@t+1 -> candidate route@t+2`

This can reduce latency without turning prediction into authority.

## CoVirtualSession+ relation

Virtual sessions remain the logical work identities. CoOrbWare renders them as workspaces/fields/constellations rather than provider chat tabs.

Lifecycle:

`HOT -> WARM -> COOL -> DORMANT -> WAKE -> MATERIALIZE -> RECEIPT -> DEMATERIALIZE`

A provider session is an expensive temporary embodiment.

## Provider/account optionality

The design target is:

- CoCivium-owned UX;
- provider-neutral task/evidence contracts;
- local/FOSS-first execution where adequate;
- replaceable remote adapters;
- exportable custody;
- no provider account as identity root.

Paid accounts MAY become unnecessary for particular workloads when equivalent or better capability, quality, safety, reliability and cost are demonstrated elsewhere.

Do not cancel or delete accounts merely because virtualization exists. Account retirement requires explicit export/custody checks, dependency tests and a human gate for consequences.

`VIRTUALIZATION_NE_ACCOUNT_SAFE_TO_DELETE`
`FOSS_OPTION_NE_FEATURE_PARITY`

## CoAttractorPull+ relation

Resources with strong descriptors, evidence, interfaces, currentness and receiver relevance MAY be pulled nearer to active work in CoMap+/CoOrbWare projections.

This is scored informational/operational attraction, not a claimed physical force.
