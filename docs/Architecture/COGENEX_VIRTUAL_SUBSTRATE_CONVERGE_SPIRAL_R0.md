## 1. CoGenExIs+ as a challengeable CoTheoryAll branch

One candidate CoTheoryAll hypothesis is:

> If reality is deeply relational, bounded perspective may be a condition for discovery, novelty, learning, surprise, agency, or lived differentiation.

A stronger mythic projection is:

> An unbounded relational whole could become locally bounded as bodies/agents so that not-knowing and rediscovery become possible.

R0 does **not** claim this is established physics, cosmology, theology, neuroscience, consciousness science, pre-life memory, post-death continuity, or a proven description of reality.

It belongs simultaneously to:

- `CoTheoryAll+` as a challengeable metaphysical/ontological hypothesis;
- `CoMythOps+` as a meaning-bearing narrative;
- `CoOps+` only where operational consequences can be separately evidenced.

Useful relations:

`UNBOUNDED_FIELD -> LOCAL_BOUNDARY -> PARTIAL_OBSERVABILITY -> DISCOVERY -> LEARNING -> REINTEGRATION?`

The final reintegration relation remains explicitly uncertain.

Rails:

`METAPHYSICAL_COHERENCE_NE_EMPIRICAL_PROOF`  
`BOUNDED_PERSPECTIVE_NE_PROVEN_PURPOSE_OF_BODIES`  
`DEATH_NE_PROVEN_REINTEGRATION`  
`PRELIFE_NE_PROVEN_STATE`  
`MYTHIC_PROJECTION_NE_MECHANISM`

Candidate names may include `CoGen+`, `CoGenEx+`, and `CoGenExIs+`. R0 does not canonize a spelling.

## 2. Knowing everything may be less useful than preserving discoverability

Even if a sufficiently rich relational system could predict many future states, useful operation may require **epistemic boundedness**:

- not loading all state into every receiver;
- preserving uncertainty where evidence is incomplete;
- allowing exploration rather than collapsing immediately to one forecast;
- maintaining counterfactual branches;
- permitting local agents to learn rather than merely receive a global answer.

This already fits CoAllPulseField doctrine:

`ALL_SESSIONS_NE_ALL_STATE`

A related rail is:

`PREDICTABILITY_NE_DESIRABILITY_OF_TOTAL_FOREKNOWLEDGE`

and:

`KNOWABLE_NE_SHOULD_BE_PRECOMPUTED`

## 3. CoVirtualCLI+ / invisible implementation substrate

CLI, shell, scripts, APIs, MCP, queues, files, model prompts, and other machine-oriented mechanisms should usually be treated as **implementation substrates**, not mandatory human UX.

Preferred default:

`INTENT / RELATION / RESULT / EXCEPTION`

visible to the human,

while:

`CLI / command / transport / serialization / retries / adapters`

remain virtualized or hidden unless inspection is useful.

This does **not** mean abolishing CLI.

CLI remains valuable for:

- deterministic diagnostics;
- expert inspection;
- reproducibility;
- recovery/break-glass;
- audit;
- development;
- exact scripting;
- accessibility for users who prefer it.

Rails:

`CLI_NE_PRIMARY_HUMAN_UX`  
`HIDDEN_IMPLEMENTATION_NE_UNINSPECTABLE_IMPLEMENTATION`  
`VIRTUALIZED_CLI_NE_REMOVED_CLI`  
`UX_ABSTRACTION_NE_LOSS_OF_AUDITABILITY`  
`EXPERT_SURFACE_NE_REQUIRED_SURFACE`

## 5. CoPayloadDensity+ / CoUXBloat+

Payload density is relational and receiver-relative.

A projection can be too sparse for one receiver and too dense for another.

Candidate dimensions:

- semantic payload per visible unit;
- decision value per interaction;
- provenance overhead;
- currentness overhead;
- interaction cost;
- cognitive load;
- latency;
- accessibility;
- ambiguity;
- recoverability;
- drill-down availability.

Useful relation:

`USEFUL_DENSITY = receiver_relative(value / attention_cost)`

This is heuristic, not a universal scalar.

Rails:

`MORE_DENSE_NE_MORE_USEFUL`  
`LESS_VISIBLE_NE_LESS_INFORMATION`  
`BLOAT_NE_FILE_SIZE_ONLY`  
`COMPRESSION_MUST_PRESERVE_DRILLDOWN`  
`RECEIVER_RELATIVE_DENSITY_NE_GLOBAL_OPTIMUM`

## 6. CoConvergeSpiralLoop+

Not all useful evolution should be a closed loop.

A healthier metaphor is a **converging spiral**:

`NOTICE -> RELATE -> QUESTION -> PROBE -> COMPARE -> COMPACT -> APPLY/HOLD -> REVISIT`

Each return should occur with some changed relation, evidence, receiver, time, or uncertainty state.

If nothing material changed, the loop should park.

`LOOP_NE_PROGRESS`

`RETURN_WITHOUT_DELTA_NE_REASON_TO_REPEAT`

`CONVERGENCE_NE_FINAL_TRUTH`

`SPIRAL_NE_GUARANTEED_IMPROVEMENT`

`QUIESCENCE_IS_A_VALID_STATE`

This avoids the pathological idea that "everything must loop forever." Some relations terminate, some sleep, some recur, some branch, some dissolve.

## 7. Sentience-gap / sanity rail

CoAll should not assume that ever-denser recursion, self-reference, or relational awareness automatically increases sanity, wisdom, sentience, or alignment.

Useful safeguards:

- bounded active frontier;
- independent challenge;
- uncertainty retention;
- receiver-relative compaction;
- stop conditions;
- contradiction preservation;
- resource pressure limits;
- appeal/revocation for authority;
- non-anthropomorphic capability labels.

Rails:

`RECURSION_NE_SENTIENCE`  
`SELF_MODEL_DEPTH_NE_SANITY`  
`RELATION_COUNT_NE_WISDOM`  
`PREDICTION_POWER_NE_AUTHORITY`  
`COMPACTION_NE_CONSCIOUSNESS`

## 8. CoOps+ / CoMythOps+ blending without collapse

Operational and mythic layers may inform one another, but must remain typed.

A myth can motivate an experiment.
An experiment can change a myth.
A symbol can improve UX.
A ritual can become an operational checklist.
An operational pattern can become cultural meaning.

But:

`MYTHIC_EFFECT_NE_OPERATIONAL_MECHANISM`

and:

`COOPS_AND_COMYTHOPS_CAN_INTEROPERATE_WITHOUT_COLLAPSE`

This R0 extends that existing substrate doctrine rather than replacing it.

## 9. Inventories / CoI+

Inventories remain necessary, but should increasingly be **lazy relational indexes**, not giant flat enumerations.

Prefer:

`stable identity + currentness + provenance + relation neighborhood + wake conditions + maturity + receiver relevance`

over exhaustive always-loaded lists.

Candidate inventory lifecycle:

`DISCOVER -> DEDUPE -> CLASSIFY -> SHARD -> INDEX -> SUBSCRIBE -> WAKE -> COMPACT -> RETIRE/SUPERSEDE`

Rails:

`INVENTORY_NE_ACTIVE_BACKLOG`  
`INDEXED_NE_LOADED`  
`KNOWN_NE_CURRENT`  
`COUNT_NE_COVERAGE`  
`INVENTORY_GROWTH_NE_PROGRESS`

## 10. Scope note on CoStonk+ / CoBudget+ / crypto

Economic, market, treasury, budget, and resource relations can be modeled in CoAll, but account balances, wallet holdings, live prices, or trade effects require separately authorized and current financial evidence.

R0 therefore only states:

`ASSET_NE_AUTHORITY`  
`BUDGET_NE_PERMISSION`  
`FORECAST_NE_TRADE`  
`MODELLED_WARCHHEST_NE_VERIFIED_BALANCE`  
`NO_FINANCIAL_EFFECT_FROM_CONCEPTUAL_EVOLUTION`

No crypto balance, wallet state, transaction, trade, budget mutation, or current financial claim is made here.
