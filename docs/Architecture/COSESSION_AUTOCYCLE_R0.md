# CoSessionAutocycle+ / CoSpawnEcology+ / CoLabel+ R0

**State:** `SHADOW_CONTROL_PLANE__PUBLIC_POLICY__NO_PROVIDER_SESSION_MUTATION`

## Lead

CoCivium is now ready to begin **autocycling the session ecology in shadow mode** without making provider tabs, model memory, or any one agent backend the lifecycle authority.

The control plane manages relations first:

`observe -> classify -> label-signal -> donate/dedupe -> sleep/twilight -> logical spawn -> verify -> materialize only when justified`

It does **not** begin with “open more chats.”

Historical CoLifecycleRelational+/CoSpawnEcology+ work already established the crucial premise:

`LIFECYCLE_LABEL_NE_LIFECYCLE_TRUTH`

and:

`SPAWN_NE_NEW_CHAT`

R0 operationalizes those prior relations as a shared GitHub/bootstrap policy.

## Why now

Recent proven work shows that bounded sessions can reach close-safe states while global work continues elsewhere, and that foreground/source-session continuation can become unnecessary after durable externalization and fresh receiver pickup.

That means lifecycle can increasingly be managed as a durable control problem rather than a human tab-management chore.

## Separation of layers

### CoEvo+

Broad relation of change, adaptation, differentiation, succession, recombination, retirement, and becoming across CoTime+.

### CoAutoEvo+

Automated bounded loop over observation, candidate variation, evaluation, selection, integration, rollback, and re-observation.

### CoSessionAutocycle+

A CoAutoEvo controller specialized for **session/work embodiments**.

It may change session lifecycle relations, propose labels, emit spawn contracts, compile successor packets, and route work. It does not own the underlying meaning, authority, model, or provider.

`COSESSION_AUTOCYCLE_SUBSET_OF_AUTOEVO`  
`AUTOEVO_NE_COEVO_TOTALITY`

## CoLabelSignal+

A label signal is append-only evidence that a material label-relevant relation changed.

Candidate trigger classes:

- mission/role changed;
- current head changed;
- authority ceiling changed;
- blocker class changed;
- provider/execution host changed;
- close safety changed;
- successor pickup changed;
- currentness degraded;
- wake predicate became true;
- stronger descendant became current;
- unique-work obligation disappeared.

The machine label may update automatically.

Provider-visible title mutation remains a separate effect adapter.

`AUTO_LABEL_SIGNAL_NE_PROVIDER_UI_MUTATION`

Historical labels remain provenance and are never rewritten.

## CoSpawnEcology+

Before materializing anything, use:

`DEDUPE -> DONATE -> SHADOW -> CHALLENGE -> LOGICAL_RESERVE -> MATERIALIZE`

Candidate spawn classes:

- `WORKER`
- `CHALLENGER`
- `VERIFIER`
- `OBSERVER`
- `SHADOW`
- `SUCCESSOR`
- `RECOVERY`
- `TRANSLATOR`
- `PROJECTION_COMPILER`
- `RESEARCH_DONOR`
- `FAILURE_DOMAIN_REPLICA`
- `QUIESCENT_RESERVE`

A spawn may be only a durable logical work capsule. A live process/model/provider session is optional.

## Minimum spawn contract

Every automatic materialization must bind:

`spawn_id | purpose | parent_identity | role | scope | input_bindings | authority_ceiling | effect_classes | budget | lease | idempotency_key | collision_domain | receiver | success_condition | stop_condition | checkpoint | recovery_pointer | failure_domain | handoff_rule | retirement_condition | provenance | currentness | uncertainty`

Fail closed when authority, ownership, collision domain, confidentiality, or effect class is ambiguous.

## Autocycle policy R0

### Automatically allowed now

- compute candidate lifecycle projection;
- emit machine CoLabelSignal+;
- update durable session ledger/currentness object;
- compile bootstrap/successor packets;
- dedupe equivalent work;
- downgrade stale work to dormant;
- emit wake conditions;
- create logical spawn contracts;
- create read-only challenger/verifier work items;
- route public-safe currentness through GitHub;
- route private durable state toward CoStead/private node fabric;
- request local/Ollama worker execution where an authorized adapter exists.

### Shadow-only now

- provider tab/session creation;
- provider title mutation;
- provider tab closure;
- browser automation that changes provider session state;
- autonomous public outreach;
- irreversible repository/node restructuring;
- automatic authority elevation.

These remain candidate effects until an exact adapter, rollback/recovery behavior, and acceptance evidence exist.

## Provider/session adapters

Provider sessions are replaceable embodiments.

A future adapter may support:

- create session;
- bind bootstrap/currentness cursor;
- set candidate visible title;
- checkpoint;
- wake;
- close provider tab after close-safe proof.

The adapter must never define lifecycle semantics.

`PROVIDER_NE_LIFECYCLE_AUTHORITY`

## Pressure-aware fleet ecology

The objective is not “more sessions.”

The objective is useful verified work per shared attention/capacity.

When:

`DISCOVERY_CAPACITY / FANIN_AND_COMPACTION_CAPACITY`

rises materially, the controller should bias toward:

- compaction;
- dedupe;
- retirement;
- successor preparation;
- dormant-state migration;
- fewer active embodiments;
- local/Ollama batch workers for high-volume H0 work.

`EVERY_SESSION_MAY_BECOME_MORE__NO_SESSION_MUST_BECOME_EVERYTHING`

## UX projection

RickBar / CoDesktop should eventually show a quiet fleet projection:

- current session role;
- lifecycle pulse;
- currentness age;
- unique-work ownership;
- successor readiness;
- CoPressure;
- sleeping/dormant count;
- active effect leases;
- only material exceptions requiring human attention.

Do not turn RickBar into an airport departure board for 600 sessions.

## GitHub / bootstrap evolution

GitHub is the shared public-safe bootstrap/currentness surface.

The lifecycle control plane should publish:

- policy;
- schemas;
- public-safe labels/currentness;
- public-safe spawn contracts;
- architecture and test fixtures.

It must not publish private session content merely to make lifecycle management convenient.

## Local/Ollama evolution

Ollama and other local models are preferred candidates for high-volume bounded roles such as:

- clustering;
- classification;
- dedupe;
- semantic compaction;
- contradiction search;
- candidate label projection;
- dormant/wake classification;
- test generation;
- read-only verifier/challenger work.

`LOCAL_NE_TRUSTED`  
`MODEL_OUTPUT_NE_EFFECT_PERMISSION`

## First implementation ladder

### R0 — policy + schemas + bootstrap
Current wave.

### R1 — shadow ledger
Compile session/currentness observations into append-only lifecycle and label-signal objects. No provider mutation.

### R2 — logical spawn ecology
Generate bounded spawn contracts and dedupe/collision checks. No live materialization required.

### R3 — local worker materialization
Allow low-effect local/Ollama workers under finite leases and receipts.

### R4 — RickBar fleet projection
Show lifecycle/currentness/pressure without machine-report clutter.

### R5 — provider adapter canary
One provider-native create/relabel/close-safe effect at a time, only where exact supported capability exists.

### R6 — bounded autocycle
Automatic succession/wake/sleep/materialization under budgets and proven rollback/recovery.

### R7 — federated node lifecycle
CoNodeMesh+/GRAIL+ currentness and failure-domain-aware session/work embodiments.
