## Why

A rich file is a byte artifact, **not** an oversized chat paste. Use one explicit selected local source, exact SHA-256 chunks, a private bounded buffer, a verified manifest and an authorized receiver adapter that separately proves readback. Vast logical work spaces remain indexes of possible tasks, not actual worker processes or provider subscriptions.

## Conservative thresholds and scale

- R1: 1..16 MiB chunk sizes, default 8 MiB, bounded memory; max 8192 chunks; default per-file size <=16 GiB, hard programmable cap <=64 GiB.
- UI R1: separate current <=2 GiB per gesture local staging cap and <=4 selected files. **Do not conflate** its physical GUI with the Node R1 module.
- Full 600 MiB canary: sparse source, all 600 MiB read/hashed; no 600 MiB durable staging assertion.
- Large files are addressed as byte ranges and manifests. Summaries/embeddings/token indexes are selective *views* of source, never infinite model context.
- CoTurtle+ can propose tests and critiques; bounded child work draws from the same parent budget, max two review rounds and depth two per existing policy. No self-granted authority or auto publication.
