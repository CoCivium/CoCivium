## Purpose

Turn recent CoCatchUp+ / CoDeltaSurface thinking into one executable currentness observer instead of another paragraph about being current.

R0 watches a deliberately small frontier:

- PR137: CoCivia correspondence/resource field;
- PR141: provider exit/recovery;
- PR143: UX currentness;
- PR146: CoSneak / CoQ&A / GTRAIL;

```text

does a productive HOLD still have its same bounded reason?

```

## Baseline is not truth

The committed fixture carries exact head pointers observed before this observer commit.

Those pointers are comparison anchors only.

`BASELINE_SNAPSHOT_NE_LIVE_TRUTH`

The workflow queries GitHub live whenever it runs.

A donor head advance is therefore surfaced as a delta, not treated as validator failure.

The host PR is special: adding this observer necessarily changes PR150's head. The compiler records that as:

`HOST_ADVANCED_BY_OBSERVER_COMMIT`

rather than manufacturing self-invalidating currentness.

## Current-head workflow rule

For each watched PR, R0 asks for workflow runs on the **current exact head**.

Historical failed runs on obsolete heads do not make the current head red.

`FAILED_OLD_HEAD_NE_FAILED_CURRENT_HEAD`

A completed current head with failures and no successful current-head run becomes a HOLD signal. A pending-only donor head is WAIT, not HOLD. A watched head with no current-head workflow proof is explicitly unproven.

The host PR is different: this observer cannot use its own in-flight workflow status as evidence of its eventual conclusion. Host self-proof is therefore deferred to the external GitHub workflow conclusion after the receipt is emitted.

This correction came directly from the first R0 run, which initially classified its own two in-flight host workflows as a HOLD. That was a CoSneak currentness bug, not a real frontier failure.

`PENDING_NE_FAILED`

`SELF_OBSERVATION_NE_POST_COMPLETION_PROOF`

That keeps observation separate from mutation.

## CoSneak relation

This surface is also a practical CoSneak detector for:

- stale baseline pointers;
- old failure emails misread as current failures;
- donor heads advancing without relation refresh;
- current-head workflow holds;
- branch proliferation that should fan in rather than spawn again.

It does not claim those signals are causal blockers.

`FRICTION_SIGNAL_NE_CAUSAL_PROOF`

## CoConvergeSpiralLoop relation

The operational loop becomes:

```text
OBSERVE
-> CATCH_UP
-> SURFACE DELTA
-> SNIFF FRICTION
-> SELECT
-> ACT ELSEWHERE UNDER AUTHORITY
-> PROVE
-> COMPACT
-> OBSERVE AGAIN
```

The R0 observer itself performs only the first three steps.

No merge, close, canonization, provider/account mutation, public effect, runtime effect or branch retirement follows.

## UX contract

The default projection should show only:

- current main head;
- watched PR count;
- material delta count;
- current-head HOLD count;
- non-host WAIT count;
- one next safe action.

Hashes, workflow lists, baselines and branch relations remain drill-down evidence.

This follows the custody UX principle that the front door should not resemble a forensic evidence locker.

## Custody boundary

The fixture and compiler are candidate-branch objects.

A successful GitHub Actions run is receiver-produced readproof that the exact candidate head was checked out and live remote state was queried.

That does not establish integration into CoAll runtime or public/current UX.

`VALIDATION_IS_NOT_ACCEPTANCE`

`NO_INTEGRATION_COEX_CANON_RUNTIME_OR_PUBLIC_INFERENCE`
