# CoFlow+ / CoAnchor+ / CoDrift+ Delta Superframe R0

**State:** CANDIDATE_SYSTEMIC_FLOW_AUDIT__NOT_RUNTIME__NOT_THEOLOGICAL_AUTHORITY
**Observed:** 2026-10-26

## Thesis

Long-running CoCivium logjams may be caused not only by missing resources or missing capabilities, but by the interaction of:
- useful anchors;
- stale anchors;
- duplicated anchors;
- under-anchored drift;
- over-anchored immobility;
- gate ordering;
- dependency concentration;
- atomic debt;
- weak receiver pull;
- and insufficient closure.

`ANCHOR_NE_MOOR_FOREVER`

## Anchor classes

### HARD invariant
Consent, privacy, source attribution, rights, authority, budget, honest evidence, safety boundaries.

Rule:
`HARD_GUARD_AT_RISK_EDGE`

Do not let a hard guard block unrelated read-only discovery.

### LEASED operational anchor
Unavailable device, missing receiver, finite review capacity, stale observation, temporary provider dependency.

Rule:
`LEASE + WAKE + EXPIRY + ALTERNATE_PATH`

### SOFT design anchor
Vocabulary preference, ideal artwork, final architecture, stylistic convention, preferred substrate.

Rule:
`SOFT_PREFERENCE_NE_BLOCK_REVERSIBLE_CANARY`

### HISTORICAL anchor
Old rule, superseded plan, duplicate gate, prior context, retired interpretation.

Rule:
`PRESERVE_LINEAGE_NE_REIMPOSE_GATE`

## Drift classes

### Productive drift
Exploration that discovers a better path while preserving source/authority/currentness.

### Semantic drift
Meaning changes silently across surfaces or generations.

### Authority drift
Permissions or implied scope expand without explicit authority.

### Evidence drift
Hypothesis starts being repeated as if observed.

### Receiver drift
Work keeps evolving away from anyone who can actually use it.

### Dependency drift
A temporary bridge becomes permanent infrastructure.

### Ontology drift
New names proliferate faster than distinct capability.

### Metric drift
Success criteria change after results are seen.

`SOURCE_DELTA -> QUALIFY -> BOUNDED_TEST -> LIVING_SOURCE -> INDEPENDENT_PICKUP -> RECEIVER_TASK -> USEFUL_EFFECT -> RETURN -> CORRECTION -> SUCCESSOR`

Measure elapsed wait and friction at every edge.

- queue time;
- active work time;
- manual relay count;
- duplicate attempt count;
- false hold count;
- prevented-error count;
- qualified new-result count;
- currentness;
- receiver acceptance;
- recovery success;

## Flow pressure

Backlog grows when qualified arrivals exceed qualified completions.

Do not increase generation merely because backlog exists.

Candidate relation:
`FLOW_HEALTH = closure_rate + receiver_pull + recoverability + useful_return - atomic_debt_growth - false_holds - duplicate_work - dependency_drag`

## CoAkimbo relation

CoAkimbo+ should perturb only where there is evidence of capture, stagnation, brittleness, or local-optimum lock-in.

`AKIMBO_NE_REMOVE_ALL_ANCHORS`

Good anchors create safe freedom elsewhere.

## CoTurtle relation

Recursive challenge should ask:
- Is this anchor still buying more safety/value than delay?
- Is this drift still creating information or merely entropy?
- Has a leased gate become permanent by neglect?
- Has a soft preference become a hard rule by repetition?
- Is a hard rule applied at the wrong layer?
- Which receiver would pull this through the logjam fastest?
- What one edge dominates total elapsed time?

## Golden delta

Compare two maps:

`MAP_A = things that reliably produced verified closure / recovery / receiver value`
`MAP_B = things that repeatedly produced stalls / atomic debt / duplicate effort / dependency / false certainty`

Then compute the qualitative delta:

`DELTA = REUSABLE_SUCCESS_PATTERN - REPEATED_FAILURE_PATTERN`

Use the delta to evolve:
- gate order;
- wake rules;
- anchor placement;
- receiver routing;
- recurrence internalization;
- proof requirements;
- naming discipline;
- recovery design;
- publication/outreach sequence.

## First bounded experiment

For each:
1. map all anchors/gates;
2. classify HARD / LEASED / SOFT / HISTORICAL;
3. record wait time per edge;
4. record human relay and duplicate effort;
5. keep HARD guards fixed;
6. shadow-remove or reorder only SOFT / expired LEASED gates;
7. compare closure time, receiver result, safety errors, recovery and cost;
8. preserve loser and null result.
