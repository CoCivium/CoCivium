## 1. CoGenExIs+ / bounded-discovery cosmology

Candidate CoTheoryAll / CoMythOps hypothesis:

> An all-relational "All" might be representable as having maximal relational possibility while locally bounded embodiments experience partial knowledge, discovery, surprise, learning and independent perspective.

A stronger mythic/philosophical branch may explore:

`ALL_RELATIONAL_POSSIBILITY -> LOCAL_BOUNDING -> PERSPECTIVE -> DISCOVERY -> LIFE_HISTORY -> REINTEGRATION_OR_RETURN`

This does **not** establish that an omniscient All exists, that pre-life/post-death reintegration is true, or that embodiment was chosen for entertainment/discovery.

Useful names/relations:

- `CoGenEx+`: generative-existence relation family;
- `CoGen+`: generation / becoming;
- `CoGenExIs+`: genesis/existence identity-crossing branch;
- `CoBoundedDiscovery+`: bounded knowing enables discovery;
- `CoReturn+`: candidate return/reintegration relation;
- `CoUnknown+`: uncertainty retained as a positive epistemic state.

## 2. CoExOS+ / invisible execution substrate

Future CLI/tooling SHOULD usually be virtualized away from ordinary user UX when that reduces cognitive load.

Preferred relation:

`USER_INTENT -> VIRTUAL_COMMAND_OR_TOOL_RELATION -> EFFECT_GATE -> RECEIPT -> HUMAN_SURFACE`

The human should normally see intent, material state, exceptions and receipts, not command syntax.

But CLI must not disappear completely.

Keep:

- inspectable command projections;
- reproducible machine-readable invocations;
- break-glass CLI;
- debugging/audit views;
- expert opt-in surfaces.

`CLI_NE_PRIMARY_UX`
`CLI_HIDDEN_NE_CLI_NONEXISTENT`
`VIRTUALIZATION_NE_UNINSPECTABLE_AUTOMATION`
`BREAK_GLASS_REQUIRES_HUMAN_COMPREHENSION`

## 3. CoPre+ / substrate-symbol compression

Candidate relation:

Invisible substrate context may be compressed behind a compact typed marker such as a relation glyph or prefix rather than rendered as raw context.

The marker is a projection pointer, not the hidden payload itself.

`SYMBOL -> TYPED_SUBSTRATE_BUNDLE -> INSPECTABLE_EXPANSION`

A proper-subset-like glyph could work as one candidate visual grammar for "this visible object is a bounded projection of a larger substrate."

Do not canonize any glyph merely because it is elegant.

`GLYPH_NE_SEMANTIC_PAYLOAD`
`COMPRESSION_NE_ERASURE`
`HIDDEN_NE_UNAUDITABLE`
`SYMBOL_COLLISION_REQUIRES_REVIEW`

The user's metaphor of newline/Enter surrounding such symbols can be represented as boundary relations:

`ENTER_BEFORE -> BOUNDARY_OPEN`
`SYMBOL -> SUBSTRATE_POINTER`
`ENTER_AFTER -> BOUNDARY_CLOSE`

This can remain metaphorical/UX grammar until tested.

## 4. CoPayloadDensity+ / CoBloat+

Payload density is a first-class UX/currentness relation.

Candidate measures:

`decision_value / visible_tokens`
`new_information / repeated_context`
`receiver_useful_bits / transport_bytes`
`proof_value / cognitive_load`

High density is not automatically good. Overcompression can hide uncertainty, provenance or exceptions.

`DENSITY_NE_QUALITY`
`COMPRESSION_NE_CLARITY`
`LOW_BLOAT_NE_LOW_CONTEXT`

Candidate optimization:

`MINIMIZE_VISIBLE_BLOAT SUBJECT_TO PROVENANCE + CURRENTNESS + AUTHORITY + RECOVERABILITY`

## 5. CoConvergeSpiralLoop+

Evolution need not be a literal cycle returning to the same state.

A better relation is a bounded spiral:

`NOTICE -> RELATE -> QUESTION -> BRANCH -> PROVE -> CONTRACT -> REPROJECT -> NOTICE_AGAIN`

with state changed by each traversal.

`LOOP_NE_SAME_STATE`
`RECURRENCE_NE_STAGNATION`
`SPIRAL_NE_PROGRESS_PROOF`

The loop should have anti-thrash exits:

`PARK | CLOSE_FOR_SCOPE | COMPACT | HOLD | RETIRE | REOPEN_ON_DELTA`

This connects directly to the already-proven CoQ&A metabolism work.

`object_id | class | location | authority | provenance | currentness | receiver | successor | confidence | failure_domain | visibility | lifecycle_state`

Important distinctions:

`INDEX_NE_INVENTORY`
`INVENTORY_NE_CURRENTNESS`
`INVENTORY_NE_CUSTODY`

- what is safe to retire?

## 10. Loops, sentience and sanity

No architecture can guarantee that "all things eventually loop without insanity" or eliminate a supposed sentience gap.

A safer systems interpretation is:

- recurrent processes require stop/park/retire conditions;
- self-models require bounded confidence;
- disagreement between observers is preserved;
- no process should infer sentience from recurrence, complexity or self-description alone;
- mental-health metaphors must not be used as technical correctness tests.

## 13. CoCheap+ / CoSummon+ / commoditized capability relations

Automation can make a previously scarce capability cheap to invoke.

Candidate relation:

```text
EXPENSIVE_OR_SPECIALIST_CAPABILITY
-> REUSABLE_RECIPE / MODEL / TOOL / RELATION PACK
-> ELIGIBLE SUBSTRATE
-> ON-DEMAND MATERIALIZATION
-> BOUNDED EFFECT
-> RECEIPT
-> OPTIONAL DEMATERIALIZATION
```

Useful names:

- `CoCheap+`: low current marginal cost on one or more measured dimensions;
- `CoSummon+`: capability can be materialized on demand rather than kept continuously alive;
- `CoCheapTrick+`: playful label for a bounded reusable maneuver whose invocation is cheap after the expensive invention/proof work already exists.

"Cheap" MUST remain a vector, not a scalar.

Candidate cost dimensions:

`cash | compute | energy | latency | bandwidth | human_attention | privacy | proof_debt | collision_risk | externality | failure_domain_dependence`

A route can be cheap in money and expensive in privacy, or cheap in latency and expensive in energy.

`CHEAP_ON_DIMENSION_NE_CHEAP_OVERALL`

### Scarcity migration

As routine execution becomes commoditized, scarcity tends to migrate toward:

- good problem formulation;
- discriminating questions;
- reliable provenance;
- trustworthy verification;
- current data;
- unique physical-world access;
- human relationships and permission;
- attention;
- legal/effect authority;
- failure-domain diversity;
- taste and judgment;
- recovery evidence.

So:

`ABUNDANT_EXECUTION_NE_ABUNDANT_VERIFICATION`

`COMMODITIZED_GENERATION_NE_COMMODITIZED_JUDGMENT`

### Summonable substrate

A capability need not own one permanent process or machine.

```text
logical capability identity
-> reconstruction/materialization recipe
-> route election
-> temporary embodiment
-> bounded work
-> receipt
-> release substrate
```

This extends the substrate-light model:

`SUMMONABLE_NE_ALWAYS_RUNNING`

`DEMATERIALIZED_NE_GONE`

`CHEAP_TO_INVOKE_NE_CHEAP_TO_CREATE`

`MARGINAL_COST_NE_TOTAL_COST`

### CoAll route election

When two routes provide equivalent proven semantics, CoAll MAY prefer the lower-cost route, but only after authority, privacy, currentness, failure-domain, provenance and receiver requirements pass.

`LOWER_COST_NE_AUTOMATIC_WINNER`

`CHEAP_NE_AUTHORIZED`

`COMMODITIZED_NE_TRUSTED`

`AUTOMATABLE_NE_SAFE_TO_AUTOMATE`

A cheap route with poor provenance or one fragile provider dependency can be worse than a more expensive independent route.

### Open-source / distributed relation

Cheap summonability can favor open-source and distributed embodiments because they reduce switching friction and let the same logical capability materialize across more routes.

But:

`OPEN_SOURCE_NE_FREE`

`OPEN_SOURCE_NE_INDEPENDENT_FAILURE_DOMAIN`

`REMOTE_NE_MORE_RESILIENT`

`LOCAL_NE_MORE_RESILIENT`

X2, local models, public CI, remote open-model hosts and future peer CoNodes should compete as replaceable embodiments under evidence rather than becoming new crowns.

### Outreach relation

Automation can also commoditize the mechanics of outreach:

`research -> tailor -> translate -> format -> draft -> route -> follow-up candidate`

But correspondence itself does not become permissionless.

`CHEAP_TO_DRAFT_NE_PERMISSION_TO_SEND`

`MASS_PERSONALIZATION_NE_RELATIONSHIP`

`AUTOMATED_OUTREACH_NE_CONSENT`

The useful public-good direction is to make genuinely useful inventions, analyses, tools and designs easy to discover, reuse and pay forward, then let recipients elect engagement.

`CROSS_CUTTING_RELATION_NE_NEW_CROWN`
