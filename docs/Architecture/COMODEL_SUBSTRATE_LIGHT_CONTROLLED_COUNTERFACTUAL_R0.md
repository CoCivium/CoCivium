# CoModel substrate-light controlled single-vs-parallel counterfactual R0

**State:** `CONTROLLED_SAME_TASK_SINGLE_VS_PARALLEL_CI_CANARY__NO_RUNTIME_NO_CANON_NO_AUTHORITY_CHANGE`

## Purpose

Supply the first controlled counterfactual that the real-receipt advisory bridge correctly refused to invent.

The same exact deterministic work object is executed in two treatments on the same GitHub-hosted runner OS class:

```text
treatment A: physical width 1
  -> one receiver

treatment B: physical width 3
  -> three concurrent receivers
```

All four execute the exact same:

- candidate head;
- model-pack bytes;
- portable runner code;
- five inference cases;
- scoring rule.

## Benefit scoring

One **unique correct inference case** counts as:

- one qualified benefit unit;
- one verified deed.

Duplicate correct receipts do not create extra benefit.

This is important. Three workers independently rediscovering the same five answers produce useful redundancy, but not fifteen unique solved cases.

Therefore:

`REDUNDANT_RECEIVER_COUNT_NE_UNIQUE_BENEFIT`

Execution cost is counted separately as one cost unit per receiver execution.

## Expected bounded result

For this deterministic task:

```text
single:
  unique correct cases = 5
  benefit units = 5
  verified deeds = 5
  benefit yield = 1
  execution cost units = 1

parallel:
  unique correct cases = 5
  benefit units = 5
  verified deeds = 5
  benefit yield = 1
  execution cost units = 3
```

Thus there is no strict verified-benefit-yield gain from widening physical width for **this work object**.

The expected advisory result is:

`ADVISE_PHYSICAL_WIDTH_1_NO_STRICT_VERIFIED_BENEFIT_GAIN`

This is advisory only. The workflow does not possess runtime width authority.

## Custody

Each receiver uploads an exact receipt.

The fan-in compiler downloads all four exact receipt objects and emits per-object content SHA-256 readproof.

A successful fan-in therefore establishes bounded:

`PICKED_UP_BY_COUNTERFACTUAL_COMPILER`

for those four workflow receipt objects.

It does not establish `INTEGRATED`, `CANON`, `RUNTIME` or `COEX`.

## What this does not mean

A no-gain result on a deterministic duplicate computation does not imply parallelism is useless.

Tasks with:

- complementary specialists;
- uncertainty reduction;
- fault tolerance;
- search-space coverage;
- adversarial review;
- heterogeneous capabilities

may show a genuine verified benefit from widening.

Those require their own controlled work objects and exact scoring surfaces.
