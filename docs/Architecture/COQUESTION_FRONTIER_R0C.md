# CoQuestionFrontier+ / CoSneak Question Election R0C

**State:** `CANDIDATE_HIGH_LEVERAGE_QUESTION_FRONTIER__NO_RUNTIME_EFFECT`

## Why now

CoSneak+ exposed that quiet friction can survive for months while visible surfaces still report success. CoQ&A+ already treats questions as durable relational objects. The next useful move is not to generate more questions indiscriminately, but to elect questions whose answers could materially change routing, safety, resilience, currentness, or human effort.

`MORE_QUESTIONS_NE_MORE_PROGRESS`

`QUESTION_VALUE_REQUIRES_POSSIBLE_DECISION_DELTA`

## Election dimensions

A candidate question earns priority when it has high expected value on several dimensions:

- could expose a hidden blocker;
- could retire duplicated work;
- could close or reopen an authority gate;
- could reduce human transport or attention;
- could reduce dependency concentration;
- could improve recovery or failure-domain independence;
- could change a product/UX decision;
- could reveal false completion;
- could discriminate between competing hypotheses;
- has a bounded proof path;
- has a receiver who can use the answer.

Avoid questions that merely enlarge ontology without a likely downstream decision.

## CoSneak coupling

A CoSneak candidate should preferentially generate a question that can disprove it.

Example:

`LATEST_LABEL_WITH_OLD_CONTENT`

should generate:

> Does the visible receiver consume this object as current state, historical state, or not at all?

That is more useful than merely declaring the file stale.
