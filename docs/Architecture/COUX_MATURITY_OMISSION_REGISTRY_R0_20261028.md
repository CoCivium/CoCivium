# CoUX+ Maturity / Omission Registry R0

**State:** BOUNDED PUBLIC-SAFE AUDIT · NO X2 MUTATION · NO CLAIM OF COMPLETE HISTORY  
**Observed:** 2026-10-28

## Why this exists

The X2 / CoOrb / CoBar / CoBrowser / CoHereNow / CoGbx work now has enough architecture and canaries that the largest risk is no longer lack of ideas. It is **silent maturity drift**:

- something was designed but never implemented;
- something passed synthetically but never reached a real device;
- something landed in source but never reached a receiver;
- something should recur but has no wake mechanism;
- something is intentionally dormant but looks forgotten;
- something is blocked by currentness, authority, privacy or evidence and nobody can see why.

R0 turns that into a registry instead of relying on chat memory.

`DOC_OR_DEMO_NE_RUNTIME`  
`PROPOSED_ONGOING_NE_ONGOING_MECHANISM`

## Front-door result

The highest-value UX gap remains **current X2 runtime binding**, not another visual concept.

Current observations conflict:

- user screenshots show X2 actively in use;
- the authorized Remote Desktop Commander observer reports X2 offline / last seen 99h ago.

Therefore:

`HUMAN_VISIBLE_ACTIVITY = OBSERVED`  
`REMOTE_MACHINE_CURRENTNESS = STALE_OR_UNKNOWN`

Neither source is promoted over the other without reconciliation.

## Registry states

- `PROVEN_BOUNDED` — exact bounded canary/proof exists for its stated scope.
- `PARTIAL` — substantial architecture/component exists but a material proof surface is missing.
- `READY_NOT_LANDED` — bounded evidence exists on a branch/donor but not current main.
- `READY_TO_HARVEST` — donor has unique useful deltas but must not merge wholesale.
- `HELD_CURRENTNESS` — current state cannot be safely inferred.
- `HELD_RECEIVER` — exact independent receiver pickup/return is missing.
- `HELD_PROOF` — key real-world event/readback is missing.
- `HELD_PUBLIC_CURRENTNESS` — public endpoint/current public journey is not qualified.
- `DORMANT_WITH_WAKE` — intentionally quiet until explicit prerequisites.
- `MISSING_PROOF` / `MISSING_RUNTIME` / `MISSING_IMPLEMENTATION` / `MISSING_ACCEPTANCE` / `MISSING_DEPLOYMENT` — the name is annoyingly descriptive.

These are more valuable than producing additional UX taxonomies.

## Required operating rule

Every lane expected to recur must answer:

1. **What wakes it?**
2. **What proves it is current?**
3. **What keeps it quiet otherwise?**
4. **What is the receiver?**
5. **What exact proof closes the next gap?**
6. **What retires or supersedes it?**

If those are absent, "ongoing" is an aspiration, not a mechanism.
