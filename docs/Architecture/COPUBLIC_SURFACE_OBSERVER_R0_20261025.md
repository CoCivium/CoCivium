## Purpose

Bridge the gap between rich internal generation and what a public reader can actually discover, understand, follow, and return from.

A public publication surface may look stable while internal agents, source graphs, media annexes, term fields, and successor candidates evolve rapidly. The observer should therefore measure the public edge directly rather than inferring it from internal activity.

```
INTERNAL GENERATION
-> EDITORIAL FAN-IN
-> PUBLIC SURFACE
-> PUBLIC SURFACE OBSERVER
-> DELTA / CURRENTNESS / ROUTE QUALITY
-> RETURN
-> SUCCESSOR CANDIDATE
```

## What to observe

For each public surface:
- publication identity;
- visible title / description;
- current hero / lead item;
- latest visible posts;
- visible route depth;
- obvious reader entry points;
- broken / stale links;
- successor / predecessor visibility;
- source / evidence visibility;
- accessibility;
- cross-link usefulness;
- publication family membership;
- last materially observed change.

## What not to infer

Do not infer:
- readership comprehension from page presence;
- endorsement from visibility;
- sensitive reader traits;
- delivery / read / ACK from publication;
- impact from impressions alone;
- authority from public placement.

## Wake triggers

Wake editorial work on:
- materially stale front door;
- broken important link;
- successor missing;
- contradictory public projection;
- newly qualified high-value source;
- reader-authored correction / challenge;
- large comprehension gap;
- accessibility regression;
- publication-family routing gap.

Do not wake on mere internal vocabulary growth.

## Core metrics

- time since last material public delta;
- percent of visible items with currentness / lineage path;
- percent with useful next route;
- broken-link rate;
- source/evidence reachability;
- cross-publication routing coverage;
- public-front semantic duplication;
- challenge/correction ingress availability;
- human relay minutes per public update.

## Screenshot / visual witness role

A screenshot may be used as a human-visible witness of what was on screen at a moment in time.

It is not:
- exact HTML state;
- proof of reader use;
- proof of publication delivery;
- proof of current backend state;
- proof of analytics.

`SCREENSHOT_NE_RUNTIME_STATE`
`VISIBLE_NE_USED`

## First canary

Take one public Substack front and produce a bounded public-surface snapshot:
1. visible identity;
2. latest three visible posts;
3. source/currentness pointers if present;
4. broken-link check;
5. one recommended route improvement;
6. one successor candidate;
7. receipt.

No reader profiling. No automatic publication.
