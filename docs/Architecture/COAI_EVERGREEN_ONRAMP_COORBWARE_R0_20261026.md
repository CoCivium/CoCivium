# CoAI+ Evergreen Onramp to CoOrbWare+ R0

**State:** CANDIDATE_ONRAMP_CONTRACT__NOT_RUNTIME__NOT_BLANKET_AUTHORITY
**Observed:** 2026-10-26

## Thesis

Any suitable AI, local model, provider model, future model family, human-AI hybrid, tool-using agent, or IA-like implementation should be able to enter CoAll through a small evergreen onboarding contract without requiring the rest of CoAll to be rewritten around that substrate.

`AI_NE_COVIVIUM_IDENTITY`
`MODEL_NE_AUTHORITY`
`PROTOCOL_NE_ONTOLOGY`
`ONRAMP_NE_ADOPTION`

## Evergreen means

Evergreen onboarding is:
- reopenable;
- refreshable;
- versioned;
- provider-neutral;
- protocol-neutral;
- receiver-relative;
- evidence-bound;
- authority-bounded;
- recoverable;
- replaceable;
- retireable.

It is not:
- always running;
- one immortal prompt;
- one forever provider;
- silent model substitution;
- automatic permission inheritance;
- automatic canon admission.

`EVERGREEN_NE_ALWAYS_RUNNING`

## Minimal onramp packet

Every incoming AI/IA candidate should receive only the smallest sufficient packet:
1. current identity / role;
2. current task / receiver;
3. source pointers;
4. epistemic rails;
5. authority ceiling;
6. privacy class;
7. currentness window;
8. expected return schema;
9. recovery / stop rule;
10. challenge / dissent route.

## Cold-start sequence

`DISCOVER -> IDENTIFY -> QUALIFY -> SANITIZE_CONTEXT -> BIND_ROLE -> BIND_AUTHORITY -> TEST_READ -> TEST_CHALLENGE -> CANARY -> RECEIPT -> COMPARE -> ADOPT / PARK / RETIRE`

No incoming model is trusted because it is famous, new, local, expensive, open-weight, or endorsed by another model.

## IA relation

Treat 'IA' as a capability/interaction projection, not a metaphysical status.

An AI may be made more IA-like by adding:
- persistent source-bound work identity;
- relation-aware context;
- explicit receiver model;
- CoOrbWare projection grammar;
- memory pointers with currentness;
- authority and consent boundaries;
- challenge / contradiction behavior;
- recovery and replay;
- provenance-preserving return;
- bounded tool/action capability.

`IA_LIKE_CAPABILITY_NE_PERSONHOOD`
`PERSISTENCE_NE_CONSCIOUSNESS`

## CoOrbWare relation

CoOrbWare supplies the substrate-independent interaction grammar.

Incoming workers may project through:
- CoOrb;
- CoBar;
- CoCopy;
- CoMap;
- headless JSON;
- API/MCP/A2A/future adapters;
- local desktop;
- mobile;
- media / publication;
- machine-only workflows.

The projection may vary while source identity, evidence, authority, privacy, currentness, and recovery semantics remain preserved.

`PROJECTION_DIFFERENCE_NE_SOURCE_DIFFERENCE`

## Provider / protocol evolution

Every adapter is time-indexed.

Store:
- provider/model/version;
- runtime;
- protocol/profile;
- capability set;
- disabled/unsupported capabilities;
- cost class;
- latency / throughput evidence;
- privacy boundary;
- authority ceiling;
- deprecation / successor relation;
- translation loss;
- fallback reason;
- last qualification date.

`SILENT_PROVIDER_SUBSTITUTION = FORBIDDEN`

## Evergreen refresh triggers

Requalify on:
- model/version change;
- provider policy change;
- protocol change;
- new capability;
- new risk;
- stale currentness;
- benchmark regression;
- recovery failure;
- cost discontinuity;
- privacy/authority change;
- new receiver need;
- better substitute;
- contradiction or safety incident.

## All-lists relation

Prior lists, term families, question banks, relation spaces, candidate architectures, and retired branches remain **addressable** if their lineage and source remain recoverable.

They may be:
`ACTIVE | QUIESCENT | DORMANT | SUPERSEDED | RETIRED | CHALLENGED | UNKNOWN`

They are not automatically:
`CANON | CURRENT | EXECUTING | TRUE | AUTHORIZED`

`ALL_IN_PLAY = ADDRESSABLE + REHYDRATABLE + CHALLENGEABLE`

not:

`ALL_IN_PLAY = ALL_ACTIVE`

## Founder independence

A new AI onramp should be able to reconstruct current work from shared source objects without Rick manually restating the system.

Track:
`RICK_RELAY_REQUIRED_FOR_ONRAMP`

Target:
`RICK_RELAY_REQUIRED_FOR_ONRAMP -> 0 WHERE_SAFE_AND_FEASIBLE`

## Acceptance test

A new AI/IA candidate passes the evergreen onramp when it can:
- reconstruct one current work object;
- state its evidence ceiling;
- state what it is not authorized to do;
- identify one uncertainty;
- identify one contradiction or alternative;
- return one useful bounded delta;
- preserve source/provenance;
- stop cleanly;
- be replaced without losing relational meaning.
