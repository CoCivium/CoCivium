**Scope:** A public-safe overview of an internally detailed, private working spreadsheet. This document does **not** reproduce private host logs, correspondence, individual session material, credentials or user data.

## Objective
Allow routine **authorized** work to progress when people are not sitting at a keyboard, mouse or display. Human judgment and consequential authority remain available and required when the relevant effect class demands them. A person should be free to use a screen, voice, touch, text, a physical stop control or no active interface as appropriate.

These are different achievements:
- **Headless:** the worker does not require an interactive desktop.
- **Screenless:** the human can understand and control selected work without a display.
- **Keyboard/mouse optional:** alternative inputs are accessible without removing those fallbacks.
- **Human-optional routine execution:** safe authorized work proceeds during human absence with independent proof of useful completion.
- **Provider-optional:** one unavailable subscription/provider does not strand a critical WorkID.
- **Rights and authority:** optional user input never becomes permission for a worker to create its own authority.

## Prior-art reconciliation
A private 2026-11-12 R0 workbook had 128 candidate operations, 139 hard edges and 16 workstreams. An explicit graph audit found **one strongly connected component containing 41 operations**, with five governance feedback edges inside it. The R1 working successor retains that source and defines **144 typed operations across 15 lanes, 243 hard edges, zero cycles, six independent roots and maximum dependency depth nine**. These are **planned operations and graph properties**, not claims of deployment or completed product capability.

A serial chain across every discipline was not a useful causal path. R1 distinguishes hard prerequisites from advisory relationships and parallel research. A safety/authority floor is specified early instead of placing governance after the very automation it must constrain.

## Ten bounded causal milestones
1. **Quiet source-attributed desktop:** identify one actual foreground interruption and its launch lineage before suppressing anything; do not start more visible diagnostic consoles.
2. **Currentness and proof:** source, timestamps, observation scope, version and independent receiver proof are separate fields.
3. **Durable WorkID:** actions, checkpoints and lineage survive a browser tab and a session boundary.
4. **One elected actuator:** independently parallel research, serialize shared effects through revocable leases, idempotency keys and recovery.
5. **Provider-neutral read-only recurrence:** prove one useful task executes naturally on an independent authorized worker; control notification duplicates and budget.
6. **Alternative input baseline:** compare existing Windows Voice Access to a modular voice stack before creating a new resident input service.
7. **Screenless output:** audibly deliver strongest proof, blocker and next safe action; honor mute, privacy and alternate accessibility.
8. **Cross-device and off-provider recovery:** cold-restore the exact work object from an independent failure domain; do not confuse mirror storage with autonomous receiver uptake.
9. **Reality-calibrated CoNeedle:** measure accepted useful outcomes, user intervention cost, interruption rate, recovery latency and proof debt, with explicit unknown values.
10. **First-use and absence acceptance:** consented user task, quiet UI and reproducible recovery precede a 24-hour unattended test and any broader adoption.

## Immediate elected sequence
`READ EXISTING OWNER → ONE NONDISRUPTIVE OBSERVATION → CAUSAL ATTRIBUTION → REVERSIBLE CANARY → INDEPENDENT ACCEPTANCE`

In parallel, continue public-safe contract comparison, currentness validation and read-only provider-neutral worker tests. Actual local-process, privacy, financial, credential, publication, deletion and irreversible effects have separate gates. No new X2 shell, task, account, service, user-message notification or global session wake is authorized by this proposal.
