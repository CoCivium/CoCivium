# CoFrontierIntake+ R0

State: SYNTHETIC_MODEL_FRONTIER_INTAKE__NO_MODEL_DOWNLOAD_NO_RUNTIME_ADOPTION_NO_AUTHORITY_CHANGE

## Purpose

New models, runtimes, releases, and alleged leaks should enter CoAll as evidence-bearing candidates, not as fashionable names.

Lifecycle:

~~~text
RUMOURED
-> CREDIBLE_SIGNAL
-> ANNOUNCED
-> PUBLICLY_AVAILABLE
-> PROVENANCE_VERIFIED
-> ISOLATED_CANARY
-> CAPABILITY_EVALUATED
-> COALL_RELATED
-> ROUTABLE_FOR_SCOPE
~~~

Possible exits include REJECTED, QUARANTINED, and LICENSE_BLOCKED.

A candidate may remain indefinitely at any intermediate state.

## Relation to provider exit

CoAll now has a proven non-ChatGPT deterministic execution path, but open/alternate-model capability is still a separate frontier.

This intake fabric is the membrane between:

"new model exists"

and:

"this exact model artifact may be considered for this exact bounded task scope."

MODEL_AVAILABLE_NE_PROVIDER_EXIT_READY

## Exact identity

A model name is not exact identity.

A future real intake should bind, where applicable:

- source/repository identity
- release/version identity
- exact artifact/weights/package hash
- runtime and adapter versions
- tokenizer/config identity
- license source and allowed scope
- provenance chain
- reconstruction or reacquisition recipe
- currentness
- dependency profile
- failure-domain profile
- authority ceiling
- privacy ceiling

MODEL_NAME_NE_MODEL_IDENTITY

## Provenance and license

Public availability is not verification.

Hash mismatch quarantines the candidate.

A verified artifact whose license does not allow the requested scope becomes LICENSE_BLOCKED rather than "probably fine."

AVAILABLE_NE_VERIFIED
HASH_MATCH_NE_LICENSE_GRANT

## Isolated canary

The first real execution should be bounded:

- no private corpus
- no external effects
- no network unless explicitly bounded
- deterministic or tolerance-bounded test vectors
- resource caps
- exact receipt
- fail-closed handling of unexpected effects

ISOLATED_CANARY_NE_RUNTIME_ADOPTION

## Capability evaluation

A model that runs has only proven that it runs.

Capability evidence should remain task-scoped, such as exact reconstruction, code repair, relation extraction, structured planning, tool-schema adherence, adversarial review, long-context recovery, or multilingual projection.

Benchmarks may inform evaluation but do not replace task-fit evidence.

MODEL_RUNS_NE_CAPABILITY_VALIDATED
BENCHMARK_NE_TASK_FIT

## Open-weight nuance

Open weights improve optionality but do not by themselves prove offline readiness, local runtime availability, model quality, privacy, reconstructibility, legal permission, or failure-domain independence.

OPEN_WEIGHTS_NE_OFFLINE_READY
TWO_MODELS_NE_TWO_FAILURE_DOMAINS

## Current R0 proof

The R0 fixture uses synthetic candidates only.

It checks:

- rumour hold
- hash-mismatch quarantine
- license blocking
- capability-pass without CoAll relation remains held
- one fully gated bounded routable case
- negative controls against newest-wins, bigger-wins, name-as-identity, open-weights-as-offline-ready, false failure-domain multiplication, and automatic default routing

No actual model is downloaded, installed, executed, benchmarked, or routed.

## Next bounded frontier

A future real intake may select one small open/alternate model candidate and apply:

source + hash + license
-> isolated first inference
-> scoped capability probes
-> dependency/failure-domain profile
-> CoAll relation registration
-> bounded route comparison

Only then could it contribute evidence toward a provider-independent reasoning route.
