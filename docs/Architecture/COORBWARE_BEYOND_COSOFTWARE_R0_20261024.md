**State:** PUBLIC_ARCHITECTURE_CANDIDATE__NOT_RUNTIME__NOT_CANON  
**Observed:** 2026-10-24

## Core distinction

**CoSoftware** is code, binaries, services, scripts, apps and runtime implementation.

**CoOrbWare+** is the observer-relative relational operating grammar that can project the same work identity, evidence, authority, currentness, uncertainty, receiver state and recovery semantics through many implementations and devices.

`COSOFTWARE = IMPLEMENTATION SUBSTRATE`

`COORBWARE = RELATIONAL PROJECTION / INTERACTION GRAMMAR`

CoOrbWare is therefore not a new truth store and not a replacement for software. It is a layer above and across software, devices, models, people and surfaces.

## What else fits under the CoOrbWare family

Prefer these as **capability axes**, not dozens of separate products.

### CoRelationWare+
Typed objects, edges, inverse relations, dissent, dependency, substitution and supersession.

### CoContextWare+
Compiles receiver/task/device/time-specific context from a larger addressable field.

### CoEvidenceWare+
Carries source, proof, uncertainty, falsifiers, negative results and receipts through every view.

### CoAttentionWare+
Ranks what deserves foreground attention while preserving hidden/omitted relations for inspection.

### CoReceiverWare+
Tracks intended receiver, route, pickup, ACK, use, challenge, adoption and follow-up without collapsing them.

### CoRecoveryWare+
Preserves checkpoints, successors, restart/replay, stale-state handling and independent recovery paths.

### CoFutureWare+
Projects forecasts, scenarios, counterfactuals, wake conditions and calibration as typed futures, never as facts.

### CoCultureWare+
Projects cultural priors, accessibility, language/glyph fluency, norms, dissent and inclusive participation into interfaces without silently granting authority.

### CoSubstrateWare+
Selects among local code, FOSS models, provider models, mobile, desktop, VR, public web, headless nodes, datasets and physical experiments by fit.

### CoModelWare+
Treats model/provider sessions as replaceable workers behind durable work identities and common evidence contracts.

### CoInputWare+
Maps keyboard, mouse, touch, stylus, voice, accessibility controls and future spatial input into typed observations and explicit effects.

### CoGlyphWare+
Projects CoGibberTru / CoPriMath relations into compact symbols, text fallbacks and inspectable semantic rails.

These names are descriptive axes. Promote a top-level module only when it earns a distinct tested operation.

## Observer-relative rule

The same source-bound work object may render differently for:
- rick;
- another human receiver;
- a synth/model worker;
- a child-safe surface;
- a board/research view;
- a mobile device;
- a headless verifier;
- a future nonhuman receiver.

Different projection does not imply different truth.

`PROJECTION_DIFFERENCE_NE_SOURCE_DIFFERENCE`

## Device relation

A device contributes:
- display capability;
- input capability;
- currentness;
- battery/energy budget;
- privacy boundary;
- accessibility;
- local compute;
- network;
- receiver identity.

It does not become the work identity.

`DEVICE_NE_WORK`
