# CoFlow+ Anchor / Drift Delta R0

**State:** CANDIDATE_FLOW_ARCHITECTURE__EVIDENCE_BOUND__NOT_RUNTIME
**Observed:** 2026-10-26

## Core finding

The current CoCivium delta is not idea scarcity. It is:

`PROVEN_CANDIDATE_PRODUCTION + SOURCE_REPAIR + PUBLIC_EDGE`
versus
`UNPROVEN_INDEPENDENT_OPERATION + RECOVERY + RECEIVER_RETURN`

Therefore the dominant logjam is a transition problem between protected source truth and free-flowing useful operation.

## Two anchor classes

### Load-bearing anchors

Keep these hard:
- source identity and version;
- consent, confidentiality and rights;
- effect authority;
- exact proof and receiver pickup;
- reversible recovery;
- dissent / contradiction history;
- currentness state;
- failure-domain identity.

These anchors make flow trustworthy.

### Drag anchors

Candidate examples:
- duplicate qualification of the same reversible work;
- provider-specific recurrence kept after a generic capability exists;
- repeated manual approval for low-risk local tests;
- terminology gates that do not change evidence or receiver value;
- newest-wins or latest-session dependency;
- one human acting as courier between surfaces;
- stale plans that still block successors;
- waiting for perfect global architecture before testing a small edge;
- re-proving source facts already receipted.

These anchors should be removed, bypassed, expired, or made conditional.

`ANCHOR_NE_ALWAYS_GOOD`
`DRIFT_CONTROL_NE_GLOBAL_FREEZE`

## Flow topology

`SOURCE -> QUALIFY_ONCE -> BIND_RECEIVER -> ELECT_REVERSIBLE_PATH -> CANARY -> RECEIPT -> RETURN -> LEARN -> SUCCESSOR`

with hard gates only re-entering when:
- authority expands;
- privacy class changes;
- risk rises;
- irreversibility rises;
- receiver changes materially;
- source currentness expires;
- contradiction appears.

## Drift

Drift is not one thing.

Track separately:
- semantic drift;
- goal drift;
- authority drift;
- source/currentness drift;
- receiver drift;
- implementation drift;
- resource/cost drift;
- cultural drift;
- attention drift;
- dependency drift.

Some drift is adaptation. Some drift is corruption. Some drift is harmless.

`DRIFT_NE_FAILURE`

## Flow / friction measures

Candidate metrics:
- time from qualified source to first reversible canary;
- time from canary to independent receiver return;
- number of repeated qualification steps;
- number of human relay steps;
- number of provider-specific hops;
- percent of work with explicit successor;
- percent of blocked work blocked only by stale/duplicate gate;
- closure yield / atomic debt;
- verified useful effect per human-attention hour;
- recovery time after interruption;
- percent of failed experiments recycled into next-cycle learning.

## What worked vs what did not

Worked:
- source-pinned public routes;
- CI/browser tests;
- synthetic cyclic-regeneration models;
- real public article publication;
- cold-start scoped checks;
- negative-result preservation.

Still stalled or incomplete:
- hosted newcomer completion;
- independent reader conversion;
- cross-failure-domain recovery;
- machine-owned X2 currentness;
- non-originator stewardship;
- installed cross-substrate drift controller;
- public front-door hygiene;
- verified compounding useful effect.

## G_d / ultimate-orientation lane

G_d may be used only as a counterfactual/philosophical challenge:

`If a benevolent generative orientation existed, which anchor would it preserve, which drag would it release, and what evidence would distinguish the two?`

This can generate hypotheses. It cannot authorize effects or upgrade evidence.

`GD_GUIDANCE_NE_ORACLE`

## CoRediscover / CoUndiscover

Useful modes:
- **Rediscover:** recover a previously useful relation lost to context or drift.
- **Undiscover:** deliberately remove a false assumption, obsolete term, or inherited constraint.
- **Discover:** identify genuinely new relation/evidence.
- **Requalify:** check whether an old relation is still current.

`UNDISCOVER_NE_DELETE_HISTORY`

## Anti-logjam policy

For reversible, low-risk, local work:
`PROVE_MINIMUM -> ACT_SMALL -> RECEIPT -> LEARN`

For consequential work:
`PROVE_STRONGER -> HUMAN/AUTHORITY_GATE -> ACT -> RECEIPT -> RECOVERY`

Do not apply the consequential path to every local canary.

## First bounded tests

1. Pick five currently blocked reversible items and identify whether each is blocked by a load-bearing or drag anchor.
2. Remove one drag anchor without weakening source/rights/proof.
3. Compare closure time and error rate before/after.
4. Track whether human relay decreases.
5. Preserve the failed intervention if flow worsens.
