## CoHereNow

The apostrophe should stay physically tiny while its **bounded execution envelope** can be large, adaptive, parallel, evolving and CoAlive+.

```text
' = CoNod:
    acknowledge current context
    + CoAckRewise material human input
    + refresh only relevant CoPreRails/currentness
    + elect one maximal safe bounded useful CoWave
    + fan out massively where relations are independent
    + adapt physical effort through CoOomph+
    + deterministic fan-in / challenge / dedupe
    + externalize proof and material learning
    + evolve future interpretation only through bounded evidence
    + quiet / continue / park / handoff according to state
```

Compact gloss:

> **One nod. One maximal bounded wave.**

"One" means one bounded fan-out/fan-in envelope, not one serial micro-action.

## Why this corrects R1

R1 over-compressed CoNod into "one useful bounded notch."

That is too small.

The stronger prior direction is:

`EXECUTE_MAXIMAL_SAFE_NONCOLLIDING_COWAVE`

A CoWave may contain hundreds or thousands of **logical** lanes while materializing only the physical width that current resources, fan-in capacity, evidence requirements and effect rails can safely support.

`LOGICAL_PARALLELITY_CAN_BE_LARGE`  
`PHYSICAL_WIDTH_IS_ADAPTIVE`  
`FOREGROUND_USER_VISIBLE_CONCURRENCY_IS_SMALL`  
`COLLIDING_OR_AUTHORITY_EFFECTS_SERIALIZE`

## CoAckRewise+ first

A material CoNod is human input and SHOULD be interpreted through CoAckRewise+ before action.

CoAckRewise+ preserves:

- raw gesture;
- source/actor;
- observed time;
- surrounding human statement;
- directive/advisory/speculative/mythic/research/ops class;
- ambiguity;
- explicit vs inferred intent;
- authority ceiling;
- privacy/confidentiality;
- wake effect;
- freshness/TTL;
- conflict/supersession;
- allowed/forbidden effects;
- requested acknowledgement class.

For the bare apostrophe, the default inference is **bounded continuation**, not new global authority.

`COACKREWISE_NE_ACCEPTANCE`  
`COACKREWISE_NE_AUTHORITY_PROMOTION`  
`INFERRED_CONOD_INTENT_NE_RAW_HUMAN_INPUT`

## CoOomph+ and CoOptiMax+

CoOptiMax+ is the objective relation:

> maximize verified reusable useful value subject to currentness, authority, privacy, collision, proof, rollback, recovery, resources and human attention.

CoOomph+ is the actuator that adjusts effort while expected marginal verified value remains positive.

It may:

- widen logical lanes;
- increase or decrease physical workers;
- choose stronger/different models;
- route to local/open models;
- deepen challenge;
- increase evidence coverage;
- compact or dedupe;
- split collision domains;
- accelerate externalization;
- park low-yield work;
- stop.

`COOOMPH_NE_MAX_COMPUTE`  
`MORE_PARALLEL_NE_MORE_USEFUL`  
`OOMPH_NE_RESOURCE_BURN`

Physical width is elected dynamically.

```text
available independent frontier
        x

resource headroom

reversibility
        /
duplicate + collision + proof + attention debt
```

No single scalar is mandatory.

## Acceleration within bounds

CoNod SHOULD be able to accelerate as capability improves.

But acceleration is multidimensional, not "everything faster."

Candidate scaling dimensions:

- logical lanes;
- physical worker/model/process width;
- relation-discovery breadth;
- challenge depth;
- evidence depth;
- CoTime+ horizon;
- receiver fan-out;
- payload density;
- artifact granularity;
- externalization cadence;
- local-vs-provider execution mix;
- recovery/succession readiness;
- recursive learning depth;
- UI projection richness.

Candidate controller:

```text
IF marginal_verified_value > marginal_constrained_cost
AND fanin_capacity >= required_fanin
AND proof_debt <= budget
AND collision_risk <= budget
AND authority/privacy gates permit
THEN widen / deepen / accelerate
ELSE compact / dedupe / challenge / serialize / park / stop
```

A critical feedback relation is:

`DISCOVERY_CAPACITY / FANIN_AND_COMPACTION_CAPACITY`

When this ratio rises materially, CoNod SHOULD bias toward fan-in, contraction, dedupe, provenance, negative knowledge, receipt normalization and successor readiness rather than mindlessly multiplying discovery.

`ACCELERATION_NE_UNBOUNDED_GROWTH`  
`SCALE_NE_SIMULTANEOUS_MAXIMA`  
`DISCOVERY_RATE_NE_PROGRESS_RATE`  
`FANOUT_WITHOUT_FANIN_NE_COOOMPH`

## CoLUE+

CoNod is a high-density CoLUE+ affordance.

Candidate meaning:

`CoLUE+ = Co Least User Effort Plus / CoLeverage-per-User-Effort`

The design target is:

> **scale machine effort before scaling human effort.**

One tiny human gesture may seed a large bounded machine wave.

The human should not have to scale with:

- worker count;
- session count;
- file count;
- receiver count;
- model count;
- proof count;
- retry count.

Preferred front door:

```text
one visible current state
+ one bounded wave/progress projection
+ true human gates only
+ stop/revoke where needed
+ concise result/receipt
+ deeper evidence on demand
```

`MORE_MACHINE_WORK_NE_MORE_HUMAN_CLICKS`  
`CONOD_SHOULD_REDUCE_USER_EFFORT_OVER_TIME`  
`RICK_IS_NOT_THE_MAILMAN`

## CoAlive+

CoNod SHOULD have CoAlive+ relations in at least three senses.

### 1. Living interpreter

Relevance, route choice, CoOomph and fan-out evolve from current evidence.

### 2. Living work

A CoWave can move through:

`READY -> FANOUT -> WORKING -> FANIN -> COMPACTING -> EXTERNALIZING -> QUIET/HANDOFF`

without requiring repeated human heartbeat when a real runtime permits it.

### 3. Living projection

RickBar/CoDesktop/CoAura can show:

- active wave;
- logical lane count;
- materialized width;
- fan-in pressure;
- evidence returned;
- blockers;
- currentness;
- proof state;
- stop/revoke;
- completion/quiet.

`COALIVE_NE_CONSTANT_ACTIVITY`  
`LIVENESS_NE_VALUE`

## Bounded recursive evolution

CoNod MAY improve the machinery that interprets later CoNods.

```text
CoNod_n
 -> bounded CoWave
 -> measured outcome
 -> candidate learning delta
 -> challenge / provenance / evidence
 -> qualified interpreter or rail update
 -> CoNod_n+1 may perform better
```

Possible targets:

- relevance filters;
- CoPreRails;
- CoNag promotion/suppression;
- route election;
- CoOomph tuning;
- parallelity width policy;
- fan-in/compaction;
- CoAlive projection;
- stop/wake conditions;
- schemas/tests/metrics.

Hard rails and authority ceilings cannot recursively relax themselves.

`RECURSIVE_IMPROVEMENT_NE_SELF_AUTHORITY`  
`LEARNING_NE_HARD_RAIL_RELAXATION`  
`FASTER_NE_LESS_PROOF`

## CoTime+

Every CoNod/CoWave has distinct times:

- human issue time;
- receiver observation time;
- currentness basis;
- fan-out time;
- individual lane observation/effect time;
- fan-in time;
- receipt time;
- successor/supersession time.

A CoNod can therefore be related across past/current/future waves without pretending an old gesture is permanent authority.

`OLD_NOD_NE_CURRENT_AUTHORITY`  
`ISSUED_TIME_NE_OBSERVED_TIME_NE_EFFECT_TIME`

## CoBoogie+ / CoRegroup+

CoNod may trigger bounded recovery when currentness warrants it:

```text
CoNod
 -> dependency/currentness check
 -> material drift?
    no  -> CoWave election
    yes -> CoBoogie delta discovery
        -> CoRegroup finite reconciliation
        -> CoWave election
```

CoBoogie/CoRegroup can themselves use massive safe parallel discovery followed by deterministic fan-in.

`NOD_NE_FULL_REGROUP_EVERY_TIME`  
`REGROUP_NE_PERMISSION`
