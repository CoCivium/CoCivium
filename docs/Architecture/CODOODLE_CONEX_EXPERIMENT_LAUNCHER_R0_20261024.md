# CoDoodle+ / CoNex+ Experiment Launcher R0

**State:** PUBLIC_ARCHITECTURE_CANDIDATE__NOT_HIGH_RATE_RUNTIME__NOT_CANON  
**Observed:** 2026-10-24

## Purpose

Turn dense human prompt fragments, symbols, relations, priors, deltas, inversions, temporal modes, speculative model spaces and random perturbations into a **large candidate experiment field** without confusing candidate generation with execution, truth, authority or receiver adoption.

The engine may operate at machine speed. Human-time urgency governs what gets materialized.

## Core loop

```
SOURCE / PRIOR / DELTA
-> PARSE RELATIONS
-> EXPAND ALTERNATIVES
-> INVERT / NEGATE / COMPLEMENT
-> TEMPORAL BRANCH
-> SUBSTRATE / SURFACE VARIANTS
-> RANDOM / SEEDED PERTURBATION
-> DEDUPE / LINEAGE
-> SCORE
-> SELECT TINY FRONTIER
-> TEST
-> RECEIPT
-> FAN-IN
-> EVOLVE
```

Candidate count may be huge. Active execution stays bounded.

## CoDoodle+

A CoDoodle is a lightweight, source-bound candidate transformation of one or more inputs.

Candidate operations may include:

- combine;
- split;
- reverse;
- negate;
- complement;
- substitute;
- translate;
- compress;
- expand;
- reframe;
- temporal-shift;
- receiver-shift;
- observer-shift;
- substrate-shift;
- scale-shift;
- render-shift;
- counterfactual;
- anti-history;
- weird-lane perturbation;
- random seeded mutation.

A doodle is not evidence.

## CoNex+

A CoNex is a typed nexus where relations may branch, recombine or request tests.

Candidate nexus fields:

`nexus_id | source_refs | priors | relation_types | branch_budget | randomness_seed | authority_ceiling | receiver_scope | stop_rule | lineage | receipts`

A nexus may host many **latent** branches and only a few active ones.

## Else / NotElse engine

For each candidate C, the engine may derive:

- ELSE(C): alternative candidate;
- NOT(C): explicit negation where meaningful;
- INVERSE(C): reversed relation;
- COMPLEMENT(C): missing or opposing context;
- NULL(C): no-effect / no-change baseline;
- OUTSIDE(C): out-of-scope or external-view branch;
- UNKNOWN(C): unresolved candidate;
- COUNTERFACTUAL(C): altered-condition branch.

These are typed transformations, not logical truths.

## Time / CoT+ relation

Each candidate may carry:

- issued_at;

- target_time;
- horizon;
- valid_until;

Temporal branches include:

`PAST | PRESENT | FORECAST | COUNTERFACTUAL | ANTI_HISTORY | SUCCESSOR | RECOVERY`

Later knowledge may not overwrite frozen priors or prospective forecasts.

## Civ2+ / story-swap lane

The engine may emulate **story forms** for Civ2+, ET hypotheses, G_d, MythOps, historical dialogue, future scenarios and other model spaces.

Required conversion:

```
STORY
-> FORMAL QUESTION
-> VARIABLES / RELATIONS
-> COMPETING EXPLANATIONS
-> FALSIFIERS
-> TEST
-> UPDATE
```

Never:

```
GOOD STORY -> TRUE PHYSICS
```

Speculative or symbolic lanes remain clearly typed.

## Random generators

Randomness may be injected at selected nexuses to escape local search bias.

Preferred modes:

- deterministic seeded pseudorandom generation for reproducibility;
- stratified sampling;
- mutation operators;
- novelty-biased sampling;
- adversarial sampling;
- weird-lane reserve;
- null / anti / inverse lane reserve.

Randomness does not increase authority or evidence quality by itself.

`RANDOM_NE_NOVEL`  
`NOVEL_NE_USEFUL`  
`USEFUL_NE_TRUE`

## Human-time scaling

The engine may generate candidates far faster than humans can inspect them.

Therefore optimize for:

`CANDIDATE_GENERATION_RATE >> HUMAN_REVIEW_RATE`

while keeping:

`ACTIVE_FRONTIER << CANDIDATE_FIELD`

and ranking by:

- expected information gain;
- human-time saved;
- falsifiability;
- receiver value;
- reuse;
- reversibility;
- proof cost;
- privacy/security risk;
- compute/energy cost;
- independence value.

## Microsecond language

"Per microsecond" is a benchmark target only when measured on a named implementation and workload.

Architecture may support:

- vectorized generation;
- lazy combinatorial address spaces;
- precomputed operator tables;
- content-addressed reuse;
- delta-only recomputation;
- seeded replay;
- parallel stateless generation.

Do not claim microsecond throughput without a timed receipt.

## Experiment launcher

A candidate becomes launchable only after:

```
SOURCE_BOUND
+ AUTHORITY_OK
+ TESTABLE
+ BUDGETED
+ STOP_RULE
+ BASELINE
+ FALSIFIER
+ RECEIPT_TARGET
```

Then a selector elects a bounded frontier.

## Auto-cycle

```
DORMANT
-> WAKE ON MATERIAL DELTA
-> GENERATE CANDIDATES
-> SELECT FRONTIER
-> RUN BOUNDED TESTS
-> FAN-IN
-> RECEIPT
-> CHECKPOINT
-> SLEEP
```

No permanent hot loop is required.

## Acceptance tests

2. different seed produces different candidate subset;
3. no candidate launches without authority/test/budget/stop fields;
4. duplicate candidates collapse while lineage is preserved;
5. null/inverse/challenge lanes survive selection;
6. speculative story never upgrades to observation;
7. old prior remains recoverable after update;
8. logical candidate count can scale without proportional worker count;
9. one bounded selected experiment produces PASS/FAIL/HELD receipt;
