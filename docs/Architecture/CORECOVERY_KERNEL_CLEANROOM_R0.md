# CoRecoveryKernel+ Clean-Room Reader R0

**State:** `CANDIDATE_SELF_CONTAINED_RECOVERY_PACKET__NO_SECOND_FAILURE_DOMAIN_CUSTODY_CLAIM`

## Purpose

Advance the recovery-kernel proof ladder from structural validity toward independent-reader reconstruction.

The canary builds one bounded recovery packet from exact PR141 source objects, then gives that packet to three fresh GitHub-hosted receiver jobs:

- Linux
- Windows
- macOS

The receiver jobs perform **no repository checkout** and require no ChatGPT transcript or X2 local machine.

They receive only the packet bytes plus Python.

## Packet contents

The packet carries:

- exact copies of the four provider-exit/recovery architecture documents;
- exact copies of the four corresponding machine fixtures;
- generated orientation with the exact candidate head;
- destructive/effect authority ceilings;
- the five currently documented continuity gaps;
- a human-readable `RECOVER.txt`;
- a standalone verifier;
- a content-hash manifest.

Every source copy is bound to its exact Git blob before packaging.

## Clean-room receiver contract

A reader must reconstruct, from packet bytes alone:

- system identity: `CoCivium/CoAll`;
- candidate source head;
- destructive authority = false;
- current account-close-safe claim = false;
- five priority continuity gaps;
- first safe recovery step;
- stop conditions.

It verifies every packet file hash before producing a readproof.

## What a PASS means

A cross-reader PASS supports:

`SELF_CONTAINED_ORIENTATION_PROVEN_FOR_THIS_PACKET`

and:

`CHAT_PROVIDER_NOT_REQUIRED_FOR_PACKET_READING`

`X2_NOT_REQUIRED_FOR_PACKET_READING`

`REPOSITORY_WORKTREE_NOT_REQUIRED_FOR_PACKET_READING`

It does **not** prove:

- ChatGPT account close safety;
- complete chat/session drain;
- private offsite custody;
- a second public host;
- GitHub failure-domain independence;
- provider-independent reasoning;
- full project reconstruction.

The workflow artifact has 30-day retention and is therefore transport evidence, not durable independent custody.

`WORKFLOW_ARTIFACT_NE_DURABLE_OFFSITE_CUSTODY`

## Why three reader OS classes

Cross-OS readers reduce accidental dependence on one local filesystem/process convention.

They are still GitHub-hosted and therefore share an important governance/platform failure domain.

`DISTINCT_RUNNER_OS_CLASSES_NE_FAILURE_DOMAIN_INDEPENDENCE`

## Relation to account retirement

This canary reduces one exit blocker: a competent receiver can recover orientation without a provider transcript or local workstation.

It does not clear the account-retirement gate.

Current hold remains until broader evidence covers:

- complete unique-state/session census;
- independent private custody;
- independent public/bootstrap mirror or export;
- provider-independent reasoning route;
- credential/billing/ownership map;
- explicit destructive authority.
