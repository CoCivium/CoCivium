# CoPublication Metabolism R0

**State:** PUBLIC_ARCHITECTURE_CANDIDATE__NOT_LIVE_PERSONALIZATION__NOT_HISTORY_ERASURE__NOT_RUNTIME  
**Observed:** 2026-10-25

## Thesis

A publication should be able to evolve as a living projection without rewriting the historical artifact a reader actually encountered.

```
SOURCE GRAPH
-> PUBLIC PROJECTION
-> READER
-> OPTIONAL / AGGREGATE SIGNAL
-> CONFUSION / INTEREST / CHALLENGE / USE
-> CANDIDATE DELTA
-> TEST
-> SUCCESSOR PROJECTION
-> REDIRECT / TOMBSTONE / ARCHIVE
-> RETURN TO SOURCE GRAPH
```

## Publication lifecycle

Candidate states:

`SEED -> DRAFT -> REVIEW -> PUBLIC -> CURRENT -> AGING -> SUPERSEDED -> ARCHIVED -> REACTIVATED`

A publication may also be:
- HELD;
- CORRECTED;
- RETRACTED;
- MERGED_BY_RELATION;
- SPLIT;
- TRANSLATED;
- FORMAT-SUCCESSORIZED.

## Reader-facing currentness

Every live projection may carry:
- version;
- observed/published time;
- last checked time;
- currentness class;
- successor pointer;
- predecessor pointer;
- what changed;
- why changed;
- correction history;
- evidence/source link;
- archive/tombstone state.

`CURRENT_NE_ETERNAL`

## Honest urgency

Urgency may emerge from real temporal conditions:
- live events;
- changing APIs;
- regulation;
- real deadlines;
- limited pilot capacity;
- changing evidence;
- expiring third-party resources;
- ongoing experiments.

Do not intentionally break links or hide predecessors merely to create pressure.

`URGENCY_NE_DECEPTION`  
`EXPIRY_NE_MANIPULATION`  
`DEAD_LINK_NE_ENGAGEMENT_STRATEGY`

## Foreground fade

The past may fade from navigation prominence while remaining recoverable.

```
OLD FRONT DOOR
-> SUCCESSOR
-> OLD VERSION REMAINS ADDRESSABLE
-> OPTIONAL REDIRECT
-> CHANGELOG / LINEAGE
```

`FOREGROUND_FADE_NE_HISTORY_ERASURE`

## Read-to-evolve

A page view is an observation, not authority.

Signals may include:
- explicit reaction;
- chosen topic;
- completion;
- saved item;
- voluntary challenge;
- explicit question;
- requested depth;
- format preference;
- correction report;
- contribution.

Use only disclosed, privacy-respecting, non-sensitive signals for adaptation.

`READ_NE_AUTHORITY_TO_MUTATE`  
`INTEREST_NE_IDENTITY`

## Evolution surfaces

A successor may change:
- headline;
- ordering;
- depth;
- format;
- examples;
- diagrams;
- cross-links;
- accessibility;
- language;
- currentness note;
- challenge prompts;
- source references;
- offer / call to action.

A successor must not silently change:
- historical source identity;
- what the old version actually said;
- reader consent;
- authority claims;
- evidence provenance.

## Federation relation

Each publication in the federation can specialize by receiver/use-case while retaining one source graph.

```
ONE SOURCE GRAPH
-> MANY PUBLICATION FRONTS
-> MANY READER PATHS
-> MANY RETURN SIGNALS
-> ONE RECONCILED LEARNING FIELD
```

## Predictive lane

Prediction may help prioritize:
- likely confusion;
- likely useful cross-link;
- likely depth preference;
- likely topic relevance;
- stale content;
- likely drop-off;
- likely challenge class.

Prediction remains shadow-only until separately authorized for consequential effects.

`PREDICTION_NE_PERMISSION`

## Parallelism

Massive logical parallelism is suitable for:
- headline candidates;
- diagram variants;
- receiver-fit hypotheses;
- translation;
- format conversion;
- accessibility review;
- contradiction search;
- fact-checks;
- successor proposals;
- link-health checks;
- currentness audits.

Actual publication and direct outreach remain bounded.

`MASSIVE_PARALLEL_EDITORIAL_NE_MASSIVE_PARALLEL_EFFECTS`

## Core-return loop

```
CORE
-> PUBLICATION FEDERATION
-> EDGE / READER
-> USE / CHALLENGE / CONFUSION
-> RETURN SIGNAL
-> RECONCILE
-> SUCCESSOR
```

This turns publication into a measurable edge-to-core learning surface.

## First proof

Take one Great ReFact chapter and publish three static successor simulations:
1. original;
2. reader-generalized successor;
3. developer-specific successor.

Verify:
- same source identity;
- old version remains recoverable;
- changed fields are explicit;
- no sensitive profiling;
- no silent claim mutation;
- successor has measurable reader-fit improvement.
