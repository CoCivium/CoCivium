# CoGenExIs+ Bounded Discovery / Virtual Substrate / Payload Ecology R0U

**State:** `CANDIDATE_SYNTHESIS__METAPHYSICS_HELD_AS_HYPOTHESIS__UX_SUBSTRATE_VIRTUAL_BY_DEFAULT`

## 1. CoTheoryAll / CoGenExIs: knowing, forgetting, discovering

A useful CoTheoryAll hypothesis is:

> If an underlying relational whole were maximally connected or information-rich, bounded agents could still gain value, novelty, play, identity and learning by having partial viewpoints, incomplete access, local embodiment and time-relative discovery.

This is a **metaphysical/model hypothesis**, not an empirical claim that a universal mind, God, gods, pre-life memory, post-death reintegration, or omniscience has been demonstrated.

Candidate relation family:

`WHOLE -> BOUNDARY -> PARTIAL_VIEW -> SURPRISE -> DISCOVERY -> LEARNING -> RELATION_CHANGE -> REINTEGRATION_OR_CONTINUATION`

Alternative interpretations must remain live:

- ordinary biological bounded cognition;
- information-theoretic partial observability;
- simulation/game metaphor;
- spiritual/theological interpretations;
- unknown/other models.

`FUN_OF_DISCOVERY_NE_PROOF_OF_COSMIC_FORGETTING`

`RELATIONAL_WHOLE_NE_OMNISCIENT_SUBJECT`

`DEATH_NE_PROVEN_REINTEGRATION`

`GOD_TERM_NE_AUTHORITY_PROOF`

CoMythOps+ may render these as mythic/genesis narratives. CoOps+ must retain epistemic typing and nonclaim boundaries.

## 2. CoBoss+ / ultimate authority

No machine, person, institution, model, deity-name, mythic role or symbolic root gains operational authority merely by being placed at the top of an ontology.

Operational authority remains derived from scoped consent, evidence, rights, affected parties, revocation, law/policy where applicable, and explicit delegation.

A theological or metaphysical `God` relation may be represented as a belief/model object without becoming a machine-executable superuser.

`ULTIMATE_METAPHYSICAL_SOURCE_NE_RUNTIME_ROOT_ACCOUNT`

`ONTOLOGICAL_SUPREMACY_NE_OPERATIONAL_AUTHORITY`

`GOD_CONCEPT_NE_UNIVERSAL_CONSENT`

This prevents an authority graph from solving tangles by inventing an unchallengeable technical monarch.

## 3. CoExOS+ / virtual substrate

CLI, shell syntax, logs, paths, JSON, prompts, trace IDs and other substrate matter should normally be **virtual infrastructure**, not user UX.

Preferred relation:

`MACHINE_SUBSTRATE -> COMPACT_VIRTUAL_CARRIER -> SEMANTIC_OBJECT -> HUMAN_PROJECTION`

Human-facing surfaces should expose substrate only when it materially helps diagnosis, provenance, learning, audit, recovery or explicit expert control.

`CLI_NE_PRIMARY_USER_EXPERIENCE`

`HIDDEN_NE_DELETED`

`VIRTUALIZED_NE_UNAUDITABLE`

`ABSTRACTION_NE_LOSS_OF_RECOVERY_PATH`

A compact prefix/signet such as a proper-subset-like mark may act as a projection hint or carrier marker, but symbol semantics must be versioned and discoverable. A symbol is not authority and must not silently change parser behavior.

`SYMBOL_NE_AUTHORITY`

`GLYPH_NE_SEMANTIC_PROOF`

`VISUAL_COMPRESSION_REQUIRES_EXPANDABLE_MEANING`

## 4. CoPayloadDensity+ / CoUXBloat+

Payload density is relational, not simply "more information per pixel."

Candidate dimensions:

`decision_value / attention_cost`

`semantic_coverage / visible_complexity`

`recoverability / compression_loss`

`currentness_signal / rendering_noise`

`provenance_access / default_surface_weight`

A dense surface is good when it reduces human effort without hiding material uncertainty, authority, currentness or exceptions.

`DENSITY_NE_COMPRESSION_RATIO`

`LESS_VISIBLE_NE_LESS_AVAILABLE`

`BLOAT_NE_BYTE_COUNT`

`COMPACT_NE_OPAQUE`

`PRETTY_NE_CURRENT`

Default projection principle:

`SHOW_MINIMUM_NEEDED_FOR_CURRENT_DECISION + MAKE_RELATIONS_EXPANDABLE + KEEP_MACHINE_SUBSTRATE_VIRTUAL`

## 5. CoConvergeSpiralLoop+

Not every loop is healthy and not every convergence is closure.

Candidate healthy spiral:

`NOTICE -> QUESTION -> DIVERGE -> PROBE -> COMPARE -> CONTRACT -> INTEGRATE -> REPROJECT -> NOTICE_AGAIN`

Each turn should produce at least one of:

- reduced uncertainty;
- better relation typing;
- receiver pickup;
- retired work;
- improved currentness;
- bounded new capability;
- explicit negative knowledge;
- a justified new branch.

Otherwise park/compact.

`LOOP_NE_PROGRESS`

`CONVERGENCE_NE_TRUTH`

`RECURSION_WITHOUT_DELTA -> PARK`

`SENTIENCE_CLAIM_NE_REQUIRED_FOR_USEFUL_LOOP`

This also avoids treating a supposed "sentience gap" as a metric without an operational definition. Capability, agency, self-modeling, phenomenology claims and social status must remain separately typed.

## 6. Inventory evolution

Inventories should become relation-aware and demand-driven rather than exhaustive flat lists.

Useful inventory classes include:

`OBJECT | RELATION | RECEIVER | AUTHORITY | CURRENTNESS | FAILURE_DOMAIN | CUSTODY | QUESTION | PROOF | NEGATIVE_KNOWLEDGE | WAKE_CONDITION | RETIREMENT_STATE`

Inventory views should be lazy projections over durable sources, not another manually maintained truth pile.

`INVENTORY_NE_SOURCE_OF_TRUTH`

`INDEX_NE_CUSTODY`

`COUNT_NE_COVERAGE`

`INVENTORY_GROWTH_NE_PROGRESS`

## 7. CoStonk+ / CoBudget+ relation boundary

Financial resources can be represented relationally as budgets, constraints, opportunity costs, runway, reserves and authorized envelopes, but representation does not grant trading/spending authority.

`BALANCE_KNOWN_NE_SPEND_AUTHORIZED`

`FORECAST_NE_FINANCIAL_ADVICE`

`COST_SIGNAL_NE_TRADE_SIGNAL`

`COBUDGET_NE_WALLET_AUTHORITY`

No crypto purchase, sale, transfer, staking, wallet operation or financial commitment follows from this document.

## 8. R0U acceptance

R0U is accepted only as a candidate semantic synthesis if:

- metaphysical claims remain explicitly hypothetical;
- no deity term becomes runtime authority;
- virtual CLI keeps an auditable recovery path;
- compact UX preserves expandable provenance/currentness/authority;
- convergence loops have anti-thrash exits;
- financial relations grant no financial authority.

No runtime, public, canon, financial or account effect is authorized here.
