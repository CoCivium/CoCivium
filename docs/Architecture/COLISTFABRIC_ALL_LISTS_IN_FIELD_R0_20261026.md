# CoListFabric+ R0 — All Lists in the Field, Tiny Frontier in Motion

**State:** CANDIDATE_META-ORCHESTRATION_CONTRACT__NOT_RUNTIME__NOT_AUTHORITY
**Observed:** 2026-10-26

## Thesis

All materially relevant lists, backlogs, atlases, candidate sets, question banks, receiver sets, maintenance queues, failure lists, media queues, outreach pools, and successor lists should remain addressable in one field.

They should not all be active at once.

`ALL_LISTS_IN_FIELD_NE_ALL_LISTS_IN_MOTION`

## Core operating rule

All lists feed one election pipeline:

`INGEST / POINTER`
-> `SOURCE BIND`
-> `DEDUPE / CLUSTER`
-> `CURRENTNESS`
-> `AUTHORITY / PRIVACY / RISK GATE`
-> `RECEIVER / BENEFIT FIT`
-> `PROOF / INFORMATION GAIN`
-> `DEPENDENCY / COST / RECOVERY`
-> `TOP 20`
-> `FIRST RING 8`
-> `ELECT 1 BOUNDED DEED`
-> `TEST / EFFECT IF AUTHORIZED`
-> `RECEIPT`
-> `RETURN LEARNING`
-> `RECLASSIFY LIST ITEMS`
-> `SLEEP / WAKE ON MATERIAL DELTA`

## List-of-lists relation

Do not create a sovereign master list whose order becomes truth.

Instead maintain a typed **list-of-lists index** with:
- list identity;
- source;
- owner / steward if any;
- purpose;
- scope;
- receiver;
- currentness;
- evidence class;
- authority class;
- privacy class;
- wake rule;
- stop rule;
- successor;
- overlap / duplicate relations;
- last material delta;
- current frontier contribution.

`MASTER_LIST_NE_MASTER_TRUTH`

## CoZillion relation

CoZillion and relation-address spaces remain latent candidate generators.

CoListFabric decides what gets represented now.

`LATENT_SPACE -> MATERIALIZED_LISTS -> ACTIVE_FRONTIER`

This reuses the existing distinction:
`LATENT_RELATION_SPACE != MATERIALIZED_RELATION_GRAPH != ACTIVE_FLOW_FIELD`

## CoOrb relation

CoOrb should not show every list.

Default projection:
`HERE_NOW | TOP_20 | FIRST_RING_8 | EFFECT_1 | BLOCKERS | DORMANT_WAKE | STALE | RECEIVER_WAIT | RECOVERY`

Drill-down exposes the originating list(s) and exact lineage.

## CoCopy relation

CoCopy records material list-state transitions:
- promoted to frontier;
- blocked;
- requalified;
- superseded;
- retired;
- receiver returned;
- proof changed;
- wake fired.

## CoSpeedo relation

Track:
- number of lists addressable;
- number currently materialized;
- number active;
- duplicate ratio;
- stale ratio;
- closure yield by source list;
- atomic debt by source list;
- receiver-return rate;
- average age before retirement/successor;
- repeated Rick reintroduction count;
- percentage of frontier sourced independently of Rick.

Do not optimize for number of lists.

`LIST_COUNT_NE_PROGRESS`

## Naming and ontology control

A new named list/family is justified only when:
1. it changes selection or execution behavior;
2. its semantics are not already represented;
3. it has an explicit lifecycle;
4. it can be merged or retired;
5. the name reduces coordination cost.

`NEW_LIST_NE_NEW_CAPABILITY`

## G_d / mythic relation

G_d or mythic lists may remain in the field as clearly labeled philosophical / hypothesis lanes.
They do not receive priority merely from symbolic importance.

`MYTHIC_PRIORITY_NE_EVIDENCE_PRIORITY`

## Answer to 'are all lists in play?'

**Yes, in the addressable field. No, not as active work.**

Desired invariant:
`ALL_RELEVANT_LISTS_ADDRESSABLE + ALL_STATES_VISIBLE + TINY_FRONTIER_ACTIVE + RECEIPTED_RETURN`
