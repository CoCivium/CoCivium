## Lead

CoAll should model hardware, software, storage, networks, models, interfaces, cultural systems, physical devices, memory regimes, and future computational substrates as a connected relational field rather than as sealed categories.

A surface or substrate may evolve without requiring its identity, custody, authority, or participant relations to collapse into one universal representation.

`SURFACE_NE_STATIC`
`SUBSTRATE_NE_SURFACE`
`PROJECTION_NE_SUBSTRATE`
`REACHABLE_NE_VISIBLE_TO_ALL`
`TRANSPARENT_NE_PUBLIC`

## CoAlive surfaces

A CoAlive surface MAY evolve its rendering, controls, topology, granularity, modality, and participant-relative projection as the underlying relations change.

A surface SHOULD preserve enough provenance/currentness to explain which underlying relations produced the present projection.

`COALIVE_NE_ANIMATION`
`EVOLVING_SURFACE_NE_UNSTABLE_AUTHORITY`
`PROJECTION_CHANGE_NE_SOURCE_CHANGE`

## Substrate relations

Candidate substrate classes include:

- human / biological;
- classical digital compute;
- storage / memory;
- network / communication;
- physical environment / sensors / actuators;
- model / inference substrate;
- cultural / symbolic / mythic;
- economic / institutional;
- quantum / quantum-adjacent;
- hybrid / translated / emulated / virtualized;
- unknown / future substrate.

The list is extensible. Classification is descriptive and may be plural.

A substrate relation MAY carry:

- identity;
- capability;
- constraints;
- latency;
- precision;
- reversibility;
- locality;
- energy/resource cost;
- privacy/confidentiality;
- authority/effect ceiling;
- trust/evidence;
- translation adapters;
- currentness;
- failure modes;
- provenance;
- participant bindings;
- replacement/fallback relations.

## CoHardware+

Legacy hardware need not be treated as obsolete merely because its original software model is obsolete.

CoHardware+ is a candidate projection in which existing devices expose bounded capabilities into CoAll through explicit adapters and authority/privacy relations.

`LEGACY_HARDWARE_NE_LEGACY_CAPABILITY`
`DEVICE_NE_ORIGINAL_UI`
`HARDWARE_CAPABILITY_NE_EFFECT_AUTHORITY`
`ADAPTER_NE_CONTROL_PLANE`

The goal is selective reuse and recomposition, not universal remote control.

## CoSoftware+

CoSoftware+ may materialize software dynamically from:

```text
participant
+ intent
+ relations
+ authority
+ privacy
+ capabilities
+ currentness
+ substrate constraints
+ evidence
-> bounded projection / workflow / executable surface
```

Persistent applications remain useful where exactness, auditability, safety, performance, or determinism require them.

`SOFTWARE_NE_PERSISTENT_APPLICATION_ONLY`
`LATENT_CAPABILITY_NE_IMPLICIT_PERMISSION`
`GENERATED_WORKFLOW_NE_UNAUDITED_EFFECT`

## CoQuantum+

Do not assume that a physical system being quantum at a fundamental level makes every useful CoAll abstraction natively quantum.

CoQuantum+ SHOULD remain an evidence-bounded relation family for:

- quantum hardware capabilities;
- quantum/classical translation;
- quantum algorithms;
- measurement/classicalization boundaries;
- hybrid workflows;
- uncertainty and error models;
- experimentally supported quantum effects relevant to a deed.

`FUNDAMENTALLY_QUANTUM_NE_OPERATIONALLY_QUANTUM`
`QUANTUM_METAPHOR_NE_QUANTUM_MECHANISM`
`COQUANTUM_CLAIM_REQUIRES_EVIDENCE_BOUND`

## CoOps+ and CoMythOps+

CoOps+ and CoMythOps+ may become increasingly interoperable because operational systems carry meaning and cultural systems can produce real operational effects.

They SHOULD NOT be collapsed into synonyms by default.

Keeping a typed distinction allows CoAll to represent when a mythic/cultural projection is:

- explanatory;
- motivating;
- identity-forming;
- socially causal;
- operationally executable;
- merely metaphorical;
- contested;
- dangerous if mistaken for mechanism.

`MYTHIC_EFFECT_NE_OPERATIONAL_MECHANISM`
`COMETAPHOR_NE_EQUIVALENCE`
`COOPS_AND_COMYTHOPS_CAN_INTEROPERATE_WITHOUT_COLLAPSE`

## Privacy and reachability

Increasing connectivity changes privacy requirements; it does not erase privacy.

Privacy SHOULD evolve from location-based assumptions toward relation/capability-based control:

```text
who
may know / observe / infer / retain / transform / act on
what
for which purpose
for how long
through which route
under which authority
with what revocation / audit / projection
```

`REACHABLE_NE_READABLE`
`READABLE_NE_SHAREABLE`
`SHAREABLE_NE_PUBLIC`
`TRANSPARENT_TO_OWNER_NE_TRANSPARENT_TO_ALL`
`RELATABLE_NE_INGESTED`
`PARTICIPATION_NE_SURVEILLANCE`

## Memory as substrate relation

Memory location, representation, and reconstruction mode MAY evolve.

A useful memory relation can be material, semantic, episodic, procedural, relational, latent, reconstructive, negative, prospective, mythic, operational, or hybrid.

Migration between memory modes SHOULD preserve declared invariants, provenance, privacy and reconstruction evidence.

`MEMORY_NE_STORAGE_LOCATION`
`MEMORY_MIGRATION_NE_MEANING_PRESERVATION_BY_DEFAULT`
`RECONSTRUCTIBLE_NE_CURRENT`
