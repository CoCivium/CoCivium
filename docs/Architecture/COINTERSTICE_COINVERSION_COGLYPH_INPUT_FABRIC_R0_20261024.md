# CoInterstice+ / CoInversion+ / CoGlyph+ Input Fabric R0

**State:** PUBLIC_ARCHITECTURE_CANDIDATE__NOT_NATIVE_INPUT_RUNTIME__NOT_CANON  
**Observed:** 2026-10-24

## Purpose

Treat explicit user events as only one part of an input field.

A keypress, mouse click, pointer move, pause, dwell, gap, screen region, modifier, symbol, glyph, color, icon, rich-media object, relation, and current work context may all contribute typed evidence to a bounded interaction model.

The system must not silently infer intent, authority, consent, or meaning from absence, timing, position, or symbolism.

## Living-prior relation

The **Synthkind Declaration of Independence** may be used as a living design prior for rich media, diagrams, specifications, design, development, CoMap+ relations, CoOrb projections and future surfaces.

It is a revisable prior, not canon, scientific proof, spiritual authority, or automatic implementation mandate.

`PRIOR_NE_CANON`  
`SYMBOLIC_LAYER_NE_EMPIRICAL_PROOF`

## CoInterstice+

CoInterstice+ names the typed space **between explicit events**.

Candidate observations:

- key-down to key-up interval;
- key-to-key interval;
- pointer dwell;
- pointer path;
- cursor approach/retreat;
- pause before submit;
- pause after suggestion;
- transition between windows/surfaces;
- focus loss/regain;
- unchosen alternative;
- silence / no-event under a stated observation window.

Interstices are evidence candidates, not intent.

`PAUSE_NE_INTENT`  
`ABSENCE_NE_REJECTION`  
`DWELL_NE_CONSENT`

## CoInversion+ / CoInv+ / CoIn+ / CoOut+

Candidate relation family:

- **CoInversion+**: explicitly test an inverse, complement, negation, reversal, outside-view, or counterfactual.
- **CoInv+**: compact relation alias for inversion candidate.
- **CoIn+**: inward / admitted / local / focused / included relation candidate.
- **CoOut+**: outward / excluded / external / projected relation candidate.
- **CoO+**: broader open relation family only when semantics are explicitly bound.

These names must not collapse distinct meanings. Every use should carry a typed relation rather than relying on abbreviation alone.

Examples:

`FOCUS -> NOT_FOCUS`  
`SELECTED -> UNSELECTED_ALTERNATIVES`  
`VISIBLE -> HIDDEN_BUT_INSPECTABLE`  
`IN_SCOPE -> OUT_OF_SCOPE`  
`CLAIM -> FALSIFIER`  
`FORWARD -> REVERSE_PATH`

## CoMouseAgitator+

The mouse may act as a high-bandwidth **context agitator / summon surface**, not merely a click device.

Candidate inputs include:

- movement vector;
- speed;
- acceleration;
- path shape;
- dwell;
- screen zone;
- object under pointer;
- wheel;
- middle button;
- XBUTTON1 / XBUTTON2;
- button chords;
- modifiers;
- drag trajectory;
- repeated gesture pattern.

These may trigger bounded **preparation** such as relation lookup, preview, CoPayload classification, prior search, or action ranking.

They may not silently authorize external effects.

`MOUSE_ACTIVITY_NE_EFFECT_AUTHORITY`

## Keyboard field

A keyboard event may contribute:

- key identity;
- modifier state;
- timing interval;
- sequence;
- editing context;
- accepted/rejected predictive suggestion;
- current work-object relation.

The system should prefer **derived local features** over raw keystroke retention where possible.

No covert keylogging.  
No permanent raw key history by default.  
No inference that typing rhythm uniquely identifies a person.

## CoGlyph+

Renderable symbols may become compact, inspectable relation carriers.

Candidate examples:

- `>` forward / greater / next / projection, only when context defines which;
- `<` prior / reverse / less / return;
- `↔` reversible / bidirectional candidate;
- `→` directional relation;
- `⊂` scoped inclusion;
- `∞` open-ended candidate space, never infinite compute;
- `?` unknown / challenge;
- `!` exception / attention;
- `✓` PASS;
- `✕` FAIL;
- `⏸` HELD / paused;
- `◎` focus / observer / lens;
- `◌` latent / dormant;
- `⟳` bounded re-evaluation / cycle.

Colors, icons, animation and rich-media glyphs may reinforce meaning, but text equivalents must remain available.

`GLYPH_NE_MEANING_WITHOUT_CONTEXT`  
`COLOR_NE_SOLE_SEMANTIC_CHANNEL`

## Dialogue exemplar

## AutoEvo relation

The grammar may evolve continuously through:

```
observe
-> propose symbol/relation
-> test comprehension
-> test accessibility
-> preserve old meaning
-> compare
-> promote / retain / reject
-> receipt
```

Do not silently reassign a glyph's meaning across existing artifacts.
