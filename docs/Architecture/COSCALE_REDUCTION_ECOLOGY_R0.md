## Lead

CoCivium may explore effectively unbounded candidate spaces and sustain indefinitely renewable processes without requiring infinite compute, infinite live sessions, infinite authority, or permanent execution.

The governing pattern is:

`UNBOUNDED_POSSIBILITY -> FINITE_WAVE -> RECEIPT -> UPDATED_FRONTIER -> DORMANCY_OR_NEXT_WAVE`

Every execution is finite. The evolutionary process need not have a predetermined terminal version.

## CoScaleEcology+

Useful state may be projected at several scales:

- relation / edge;
- object / artifact;
- task / work object;
- session / virtual session;
- worker / process;
- swarm / chorus;
- device / node;
- LAN / local fabric;
- organization / receiver ecology;
- public/global projection;
- historical lineage;
- simulated / counterfactual space;
- effectively unbounded candidate space.

Scaling up does not imply more truth. Scaling down does not imply less importance.

`SCALE_UP_NE_MORE_TRUTH`
`SCALE_DOWN_NE_LESS_IMPORTANCE`

## CoFiniteInfinity+

“Infinite” or “endless” SHOULD mean one or more of:

1. unbounded candidate generation;
2. recursively extensible relation space;
3. indefinitely renewable finite waves;
4. no predetermined final version;
5. dormant work that can be reawakened by evidence or need.

It MUST NOT imply:

- infinite simultaneous compute;
- infinite provider sessions;
- infinite spending;
- infinite authority;
- infinite retention;
- uncontrolled self-replication.

## CoProcessField+

Some useful processes are not one-shot jobs but renewable fields:

`OBSERVE -> UPDATE -> CHALLENGE -> COMPRESS -> SLEEP -> WAKE -> COMPARE -> EVOLVE`

Candidate fields include currentness, evidence, contradiction, resource discovery, historical ReEvo, model quality, receiver interest, privacy risk and recovery health.

A field MAY be mostly dormant.

`ONGOING_NE_ALWAYS_RUNNING`

## CoMultiprocess+

Several temporary processes MAY act on one durable work object:

`CoWorkObject -> verifier | local model | critic | renderer | historical comparator | receiver adapter | recovery worker`

Each process emits a typed delta with provenance.

`PROCESS_NE_IDENTITY`
`PROCESS_NE_AUTHORITY`
`PROCESS_NE_TRUTH`

## CoRenewal+

Every long-lived process SHOULD periodically requalify itself:

- still useful?
- still current?
- duplicated?
- cheaper substitute available?
- should sleep?
- should merge?
- should fork?
- should retire?
- should be challenged?
- should a historical branch be revived?

Immortality is not a default lifecycle state.

## CoReduce+

Reduction is a typed relation, not erasure.

Candidate reduction classes:

- `LOSSLESS` — source can be reconstructed exactly from retained information;
- `REVERSIBLE` — source remains available and reduction maps back to it;
- `LOSSY` — detail is deliberately omitted;
- `RECEIVER_SPECIFIC` — projection optimized for a bounded receiver/task;
- `TEMPORARY` — generated for a transient context;
- `MATERIALIZED_CACHE` — disposable derived acceleration;
- `LEARNED_ABSTRACTION` — useful reduction retained as its own artifact;
- `CANONICAL_CANDIDATE` — proposed stable abstraction, not automatically canon;
- `SUPERSEDED` — retained for lineage but no longer preferred;
- `COMPOSTABLE` — safe to regenerate and not independently valuable.

A reduced form MUST preserve a pointer to its source lineage, reduction method/version, evidence boundary and loss class where applicable.

`REDUCED_NE_SOURCE`
`COLLAPSED_NE_GONE`
`HIDDEN_NE_ABSENT`
`SUMMARY_NE_CANON`

## Is reduction forever?

No.

A reduction MAY:
- persist indefinitely because it is useful;
- be regenerated from source;
- expire when stale;
- be superseded by a better abstraction;
- be discarded if safely reproducible;
- be re-expanded when a receiver needs detail;
- be retained only as a receipt/hash/recipe;
- become independent evidence only if separately qualified.

The default is:

`PRESERVE_MEANINGFUL_LINEAGE_NE_PRESERVE_EVERY_RENDER_FOREVER`

## CoCompressionTurtle+

Compression itself is testable:

`SOURCE -> REDUCTION -> RECONSTRUCTION_OR_REFERENCE -> OMITTED_INFORMATION_AUDIT -> RECEIPT`

Questions:
- did the reduction preserve required facts?
- were uncertainties collapsed incorrectly?
- were contradictions hidden?
- can provenance still be inspected?
- can the source be recovered or re-fetched?
- did the reduction materially reduce human or machine cost?

## Historical ReEvo

Historical artifacts are immutable lineage inputs. Reductions of history do not replace originals where originals remain available.

A historical summary MAY be the default projection while exact historical source stays recoverable.

`HISTORICAL_SUMMARY_NE_HISTORICAL_SOURCE`
