# CoEvoAll 2026-10-15 Architecture Fan-In R0

**State:** CANDIDATE_REVIEW_BRANCH  
**Purpose:** compact the strongest durable deltas from the 2026-10-15 work wave into the public repository without claiming runtime adoption.

## Headline

CoAll should converge on a provider-neutral capability fabric rather than provider-specific helper families.

`capability persists; binding evolves`

Current high-value families:

- **CoContentCapability+**: discover, fetch, read, parse, normalize, qualify, extract, relate, research, challenge, edit, copy, transform, project, readback.
- **CoPlatformHelper+**: platform adapters, typed relation mapping, evidence/currentness, portable representation, receiver-relative surfaces, replacement seams.
- **CoMachineCapability+**: filesystem, git, shell, process, remote, telemetry, artifact, observer, receipt, recovery.
- **CoVid+ / CoVids+**: human media + AI-readable semantic substrate + provenance + accessibility + challenge + archive + remix.
- **CoArmada+ / CoPete+**: renewable virtual work frontier with bounded real execution, mutual challenge, fan-in, compaction, and anti-busywork governors.
- **CoLegacyToCiv2+**: evergreen comparison of legacy software/systemics against CoAll/Civ2+ with explicit permission for legacy approaches to win.

## Six-pin control view

The current compact control surface remains exactly:

1. Proof
2. Pull
3. ContinueGraph
4. Armada
5. EvoYield
6. Compact

No seventh pin is implied by this fan-in.

## Content capability grammar

Sources such as Substack, news, Sites, GitHub, RSS, files, local stores, and APIs are bindings, not separate ontologies.

`READ_NE_PARSE`  
`PARSE_NE_UNDERSTAND`  
`UNDERSTAND_NE_INGEST`  
`INGEST_NE_ADOPT`  
`INGEST_NE_TRUST`

Likewise:

`COPY_BYTES_NE_COPY_MEANING`  
`DERIVE_NE_QUOTE`  
`QUOTE_NE_REPUBLISH`

Every material transformation should preserve source identity, source time, observation time, provenance, transformation, semantic loss, rights/license, authority, receiver, and currentness.

## Machine capability contract

Every replaceable machine adapter should expose:

`target | adapter currentness | authority | collision domain | reversibility | effect class | operation | readback | receipt | receiver readproof | recovery`

Effect classes:

- C0 observe
- C1 prepare
- C2 local reversible
- C3 shared gated
- C4 high consequence

Provider bindings may include PS7, local Git, GitHub, Sites, Remote Desktop Commander, local MCP, authenticated LAN routes, and future adapters.

`PROVIDER_BINDING_NE_AUTHORITY`  
`ADAPTER_FAILURE_NE_DEVICE_IDENTITY_FAILURE`  
`BLOCKED_ADAPTER_NE_BLOCKED_GRAPH`

## CoPete+ worker metabolism

Workers should keep **value flowing**, not keep one another artificially busy.

Useful relations include:

`CHALLENGES`  
`PRESSURE_TESTS`  
`VERIFY_INDEPENDENTLY`  
`FINDS_MISSING_EDGE_FOR`  
`GENERATES_OPTION_FOR`  
`AUDITS_RECEIPT_OF`  
`LEARNS_FROM_FAILURE_OF`  
`COMPACTS_OUTPUT_OF`  
`RESEEDS_FROM`

A worker-generated task must justify expected information gain, decision value, dependency unlock, recovery value or optionality against compute, energy, latency, verifier load, duplication, collision risk and human attention.

`BUSY_NE_PRODUCTIVE`  
`TASK_GENERATED_NE_TASK_JUSTIFIED`  
`FANOUT_REQUIRES_FANIN_CAPACITY`  
`NO_INFORMATION_GAIN -> SLEEP_OR_RETIRE`

## Renewable frontier

The target is an effectively unbounded virtual work address space with bounded real materialization.

Do not equate representable tasks, virtual roles or copied agents with independent live workers.

`TRILLION_ADDRESSABLE_TASKS_NE_TRILLION_RUNNING_AGENTS`  
`VIRTUAL_CELL_NE_WORKER`  
`ROLE_COUNT_NE_INDEPENDENCE`  
`FANOUT_WITHOUT_FANIN=NOISE`

Candidate work is continuously regenerated from new evidence, contradictions, failed predictions, stale dependencies, newly available tools, receiver gaps, failure modes, accessibility problems, resource changes, prior-art recovery, and negative knowledge.

## Legacy-to-Civ2 evergreen comparison

The campaign should continuously compare:

- operating systems and productivity suites
- databases and knowledge systems
- browsers and communications
- development and automation tools
- cloud/local/device architectures
- AI and multi-agent systems
- security, identity and recovery
- media/publication systems
- health, education and civic systems
- centralized vs federated systemics
- account-centric vs portable identity
- session-centric vs durable-work-centric execution
- provider lock-in vs replacement seams

The campaign must search for where legacy systems win, where CoAll wins, where hybrids win, and where neither has the right primitive.

`COMPARISON_NE_SUPERIORITY`

## Recovery of dropped optionality

A standing reconciliation lane should revisit older CoCivium work for:

- source-unique capabilities never integrated
- useful negative results
- stale lifecycle labels
- missed provider-independent replacements
- dormant product candidates
- abandoned but newly viable experiments
- unmerged research/design deltas
- duplicate concepts needing compaction
- receiver-readproof gaps
- recovery/failure-domain gaps

Recovery must be evidence-bound. Age does not imply obsolescence; nostalgia does not imply value.

`OLD_NE_OBSOLETE`  
`PRIOR_NE_CANON`  
`REUSE_REQUIRES_CURRENTNESS`

## Current execution debt

Architecture remains ahead of runtime substrate.

The desired acceptance test is still:

> 24 hours of useful evolution, surviving at least one worker/session/adapter failure, with durable receipts and no manual session cycling.

Until that passes, manual session cycling is bootstrap UX debt, not the intended product.

## Nonclaims

- autonomous continuous compute between scheduler wakes
- X2 local runtime adoption
- PS7 conformance
- a trillion live agents
- all-session pickup
- canon, CoEx or broad runtime integration
- public readiness of every candidate family
