# CoCivium Native Vertical Slice R0

**State:** `EXECUTABLE_STATIC_NATIVE_VERTICAL_SLICE__NO_PUBLIC_DEPLOYMENT_NO_RUNTIME_EFFECTS`

## CoHereNow

CoCivium has many separately proven candidate relations, but a user should not have to understand the repository topology to experience them.

R0 composes one executable, provider-independent static journey:

```text
CoTime currentness strip
        ↓
CoCivia disclosed avatar
        ↓
CoBar input
        ↓
CoReply
        ↓
CoVIA evidence / provenance
        ↓
optional learning path
        ↕
English / French projection
```

The artifact is a single self-contained HTML file with no external network dependency.

## Why this slice

The project already has candidate work for:

- CoCivia public onboarding;
- CoBar delivery/currentness;
- CoTime pulse/currentness semantics;
- disclosed CoCivia identity;
- resource contribution and observer projections.

What was missing was a single bounded product journey proving that these relations can inhabit one coherent surface.

This R0 therefore favors **composition over another ontology branch**.

3. renders a single static HTML artifact;
4. verifies one CoCivia avatar;
5. verifies one CoBar input;

## UX boundary

A green workflow means the composition contract is executable.

It does **not** mean a human has accepted the journey.

Current UX state remains:

`UX_ACCEPTANCE_UNPROVEN`

`RENDERED_NE_UX_ACCEPTED`
