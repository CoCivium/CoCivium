# CoDesktopPresence+ / X2-first Living UX Charter R0

**Observed:** 2026-11-03. **State:** PUBLIC-SAFE_REVIEW_CANDIDATE__LOCAL_BROWSER_PREVIEW_PASS__NOT_X2_INSTALLED__NOT_ALL_SESSION_ACK.

## Decision

Make X2 a first qualified exemplar of CoOrbWare, not a new sovereign operating system or another opaque dashboard. All receiver embodiments should converge on a **shared typed work/state/provenance/authority spine** and a compact contextual interaction grammar. They need not render identical screens or simultaneously run every worker. The user's desktop, native apps, CoBar, CoOrb, wallpaper, idle, mobile, headset, voice and headless projections are replaceable views of the same subject identity.

**Key correction:** Replacing a static wallpaper alone will not improve active work when application windows cover it. Elect a *CoDesktopPresence* family: 

`ACTIVE_DESKTOP -> GLANCE -> AMBIENT/WALLPAPER -> IDLE/SCREENSAVER -> WAKE/RESTORE_READ_CURSOR`

with native legacy application access and a reversible exit at all times.

## First user-visible journey

1. **HereNow:** A calm first screen answers what matters, what changed, what is stale, and what is actually blocked. No raw worker swarm or unqualified global counts.
2. **CoBar:** A persistent, low-attention control band only when a locally authorized, healthy host exists. One current work object and one qualified next deed.
3. **CoLivingGlyph:** The green dot resolves `intent + current object + observer + proof + CoTime + resource envelope + consent/authority + inverse` into a context-specific *offer*. Green does not grant permission or indicate unobserved runtime health.
4. **CoOrb / CoMap:** Expand typed relations, gaps, hypotheses and source pointers. Inverse/null/counterfactual and CoTurtle challenge are accessible, but visual connections are not evidence of causality.
5. **CoTime / CoSHAT-like:** Distinguish event, observed, recorded and valid time. Historical source is immutable; forecasts remain conditional and later calibratable. A hash/time capsule is a candidate until an exact receiver contract accepts it.
6. **CoProof / CoRecovery:** Drill into source, predecessor, checkpoint, receipt, unavailable observer, effect ceiling, undo, export and recovery. The user should not be the session heartbeat or the cross-surface mailman.
7. **CoPlay:** Permit meaning-preserving artistic, spatial and playful projections with source/inverse available. Beauty alone is not benefit, verification or product adoption.

## Shared UX agreement protocol (not an automatic vote)

- `CANDIDATE`: publish exact version/hash, predecessor relation, objective, privacy class, affected contracts and demonstration.
- `ROUTED`: interested sessions/receivers may discover a scope-relevant packet by HOT/WARM/DIGEST/WAKE subscription, not an all-to-all transcript broadcast.
- `PICKED_UP`: distinct receiver independently reads/verifies exact objects and emits a scoped ACK; a GitHub commit or search result alone does not prove this.
- `REVIEWED`: specialized UX, accessibility, operations, privacy, safety and CoTime reviewers can qualify, challenge, or propose successor. Preserve dissent, not fake consensus.
- `PROVEN_FOR_SCOPE`: measurable task success, currentness/recovery and reversible interactions are independently tested on a named embodiment.
- `INTEGRATED`: qualifying receiver uses exact state and evidence without depending on one provider tab.
- `COEX / CANON / PUBLIC`: separate governed transitions; never inferred from appearance, adoption intent or local tests.

No requirement that every session read every payload, agree on one visual style, or receive context while idle. What must converge is **the contract and lossless identity**, with receiver-relative presentation and causal proof.

## X2 acceptance frontier

1. Requalify the authorized local X2 observer and exact process/task window provenance. A screenshot of an active desktop is not remote observer pickup.
2. Preserve old wallpaper, current desktop state, shortcuts and undo path. Do not change OS wallpaper/startup automatically or relocate files.
3. Select one already-existing local CoBar/RickBar/CoOrb surface; avoid duplicate watchers or a second control plane.
4. Bind one real, permission-qualified CoWorkObject, then show `CURRENT / WHY / NEXT / UNKNOWN / CHALLENGE / RECOVER` in one accessible projection.
5. Demonstrate hide/restore, normal Windows app access, degraded X2 state, restart and evidence-based recovery. No console windows for background CoRunner jobs, while preserving logs/errors/operator terminal on explicit request.
6. Measure first-glance comprehension, task completion, recovery time, focus theft, false-greens, context loss, human relay, cognitive load, memory/CPU, accessibility and whether the user voluntarily returns.
7. Require a real receiver/effect readback before graduating from prototype to local service. Sleep/retire failed candidates without erasing prior source.

## 2026-11-03 follow-up: zero-to-one UX with CoNull+ and CoQuanta+

A user-reported Windows wallpaper change is a legitimate **starting event**, not an operational claim that CoDesktopPresence/CoOrbWare has been deployed. Never equate a new background picture with a running surface, successful CoBar host, synchronized receiver, or installation. Keep private local asset names and file contents out of the public review surface.

Use existing CoNull+ and CoQuanta+ primitives, rather than inventing a new controller, ontology or brand:

- **CoNull evidence vector:** exact source file/path/hash `NOT_OBSERVED`; actual OS background readback `NOT_OBSERVED`; prior wallpaper backup/return path `UNKNOWN`; unauthorized/unreachable device observer `UNOBSERVABLE`. These are scoped knowledge gaps, *not* assertions that a file, wallpaper, process, or worker is absent. `NULL_NE_ZERO`; `UNOBSERVED_NE_ABSENT`.
- **CoQuanta first-pulse envelope:** `work_object_id | source_event_ref | evidence_class=USER_REPORT | source_report_at | actual_event_time=null | observer | privacy_class | device_receiver | projected_surface | epistemic_state | asset_sha256=null | os_readback_ref=null | prior_state_ref=null | authority_ceiling=READ_ONLY | wake_predicate | next_deed | effect_receipt | successor`.
- **Start condition:** an admissible, provenance-preserving user report may elect a *read-only next observation*; it may never pre-green asset verification, OS application, receiver pickup, semantic acceptance, rollback capability, or autonomous agent behavior. A wallpaper image may be beautiful before it is operational. `VISUAL_START_NE_INTEGRATED_UX`.
- **CoQuanta promotion gates:** `REPORTED -> VERIFIED_LOCAL` needs actual bytes, path, hash and source-observer proof; `VERIFIED_LOCAL -> PICKED_UP` needs exact receiver readproof; `PICKED_UP -> INTEGRATED` needs an authorized named X2 runtime readback and observed effect. The OS wallpaper-application claim separately requires an OS wallpaper readback, and a reversible return requires an actual predecessor path or verified recovery strategy. Do not quietly mark these transitions from the user's narrative alone.
- **Next X2 deed:** when an authorized independent X2 observer becomes reachable, inspect the current Windows background and file bytes read-only, preserve old background state if recoverable, assess whether the existing CoBar/CoOrb host is present, then compare the same real work object through legacy desktop, CoBar/CoOrb, and typed headless views. Measure foreground focus theft and comprehension. No PowerShell/CMD popup, no unapproved wallpaper/registry/startup mutation, no new service, and no Rick-as-mailman.
- **Wake instead of human nag:** persist a typed `AUTHORIZED_X2_OBSERVER_REACHABLE` condition and context-bound pointer in the existing CoRelationalAutocycle/CoPulse receiver work, *only if there is an actually registered scheduler/receiver*. A dormant description is not an operating watcher.

A local standard-library-only structural gate was prepared privately with **14/14 synthetic fixture tests passing**, including rejection of false-green status, missing hashes, false receiver pickup, unsupported rollback and accidental wallpaper mutations. These tests are *not* Windows/X2 runtime proof, independent receiver ACK or UX acceptance. The source package's private custody and receiver pickup must be checked separately. Reuse: `examples/conotspace/README.md`, `docs/Architecture/CORELATIONAL_UX_PREDICTIVE_INPUT_R0.md`, `docs/Architecture/COORBWARE_BEYOND_COSOFTWARE_R0_20261024.md`.

## 2026-11-03 follow-up: wallpaper truthfulness versus live status

A user-supplied X2 image (private visual evidence, do **not** republish the WhatsApp-containing original) shows a background CoHereNow/CoBar-style design with a **green check next to "Resolve PS7/CMD popups"** while a real Windows PowerShell window is visibly foregrounded. The image also displays **"92% healthy"** and CPU/RAM/network-like values without visible live observer/source/valid-time binding. This is a direct **truth-calibration test case** for static ambient design. It is **not proof that the visible terminal was automatically spawned**: its contents show typed interactive commands. The error `@echo off` is CMD syntax entered into PowerShell, independent of whether any startup watcher is genuinely installed.

**UX acceptance corrections (proposed, not installed):**

1. **STATIC_SCENIC:** wallpaper may render identity, neutral icons, aspirational topology and a current-version reference. Do not paint "completed", "healthy", current time, online, synchronization, active-worker counts or numerical system health as live facts. If archival/design specimen includes them, visibly label **ILLUSTRATIVE / SNAPSHOT**, never an active status.
2. **LIVE_STATUS:** CoBar/CoOrb may show current `PASS`, `HELD`, `STALE`, `UNKNOWN` or `PREDICTED` only when each datum is receiver-relative and carries `source_id | observer | observed_at | valid_until | evidence_ref | authority | effect_receipt`. On expired heartbeat, downgrade from success to **UNKNOWN/STALE**, never a permanent green check.
3. **CoLivingGlyph ●:** green is a permitted next *proposal* plus explicit verification state, not generic assent, completion, command execution or authority. Context-specific action/inverse must survive into source-bound detail. Distinguish symbolic green accent from verified green status through accessible text, not colour alone.
4. **FOREGROUND_CONSOLE:** classify `OPERATOR_TERMINAL` (requested; may stay visible) versus `BACKGROUND_RUNNER` (must not steal focus). A screenshot of an open shell cannot establish an automatic popup. Bind exact startup task/shortcut/action, process parent chain, launch policy and observed focus event before declaring origin or repairing. Running a CMD batch fragment at an interactive PS prompt is a user-interface error, not proof of defective process supervision.
5. **ONE_REAL_OBJECT:** the first native/overlay pilot must render a single verified object from a read-only real receiver, not a second wallpaper with moving demo metrics. Test: unplug observer -> stale/unknown, restart -> exact cursor/hash readproof, undo -> native desktop unharmed; compare to baseline actual focus theft/time to first useful action.
6. **PRIVATE_EVIDENCE:** personal messaging portions of the original screenshot must not be copied into public GitHub artifacts; carry only anonymized observation, exact screenshot hash and private source pointer when authorized.

**Acceptance canary:** No static success ticks or simulated numeric telemetry presented as live; no background-launched foreground consoles in repeated traced runs; operator terminal remains available on demand; zero false-green on injected stale, disconnected or contradictory receivers; status explains source/time; original native desktop works with overlay disabled.

`ILLUSTRATIVE_NE_HEALTHY` · `STATIC_TICK_NE_EXECUTION_RECEIPT` · `VISIBLE_TERMINAL_NE_UNREQUESTED_POPUP` · `UNKNOWN_NE_GREEN` · `OBSERVER_OFFLINE_NE_PC_OFF` · `NO_X2_RUNTIME_MUTATION` · `SOURCE_REVIEW_NE_RECEIVER_ACK`.
