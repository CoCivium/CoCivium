## CoHereNow

Payload density, UX bloat, loop shape, stale repetition, hidden substrate, and observer-gap relations are all valid first-class relation candidates.

The useful target is not maximum compression. It is high decision value per visible attention unit while preserving auditability, currentness, authority, risk, and recovery evidence.

PAYLOAD_DENSITY_NE_COMPRESSION_RATIO

HIGH_DENSITY_NE_GOOD_UX_BY_DEFAULT

A compact projection can be better than a verbose one if it removes duplicated transport/debug debris without hiding decision-relevant state. An overcompressed projection can be worse even when its numerical density is higher.

## CoUXBloat+

Bloat includes more than file size.

Candidate sources include repeated status prose, duplicate receipts in the primary view, raw CLI syntax, stale notifications, repeated questions whose answer has not changed, user-relay burden, and projections that copy source state instead of resolving it relationally.

A useful long-run surface therefore minimizes visible attention cost while preserving meaning.

## Not everything should loop

No. A healthy relational system should not force all relations into cycles.

Some relations are correctly acyclic:

- provenance ancestry
- one-way effect receipts
- irreversible historical events
- dependency DAGs
- supersession chains that forbid cycles

RELATION_NE_LOOP

ACYCLIC_NE_BROKEN

Loops are appropriate where recurrence has a job: proof, discovery, control, question revision, review, maintenance, or currentness.

Each loop should expose identity, invariant, progress signal, no-progress count, exit or hibernation condition, currentness, and owner or receiver.

A proof loop can close.
A discovery loop may stay open and periodically compact.
A stalled loop should hibernate or replan.
A self-reinforcing claim loop must not gain confidence merely by repeating itself.

LOOP_CLOSURE_NE_UNIVERSAL_GOAL

OPEN_LOOP_NE_STALLED_LOOP

CLAIM_REPETITION_NE_EVIDENCE

## Observer / sentience gap

The user's "sentience gap" language is useful as a metaphorical and epistemic prompt, but should not become a literal claim.

R0 uses an observer-gap relation: the distance between what an observer or system says about its own awareness or agency and what independent evidence actually supports.

Capability evidence can grow while sentience remains unresolved.

SELF_DESCRIPTION_NE_EVIDENCE

CAPABILITY_NE_SENTIENCE

METAPHOR_NE_ONTOLOGY

This keeps CoAll free to discuss sentience, sanity, awakening, and related metaphors without letting rhetoric outrun evidence.

## CoQ&A+

Question relations should also avoid sterile loops.

A useful lifecycle is:

ASKED -> CLARIFIED -> EVIDENCE_BOUND -> ANSWERED_FOR_SCOPE -> CHALLENGED -> REOPENED_IF_NEW_EVIDENCE -> COMPACTED_OR_RETIRED

QUESTION_REPETITION_NE_PROGRESS

REOPEN_NE_FORGET_PREVIOUS_ANSWER

## CoSneak+

Hidden friction is worth treating as a relation, but not as proof of a hidden agent.

Candidate CoSneak signals include stale pointers, duplicated work, provider/session dependency, UI interruption, unbounded retries, missing receivers, authority mismatch, false currentness, transport bottlenecks, notification amplification, and invisible proof debt.

HIDDEN_FRICTION_NE_HIDDEN_AGENT

SUSPICION_NE_CAUSAL_PROOF

## Long-run shape

A healthy CoAll relation ecology should tend toward:

- more meaning per visible attention unit
- fewer repeated transports
- more explicit exits and hibernation
- inspectable hidden substrate
- less unsupported self-amplification
- clearer separation among metaphor, capability, and ontology

Some things close.
Some things recurse.
Some remain open.
Some stay acyclic.
Some hibernate.
Some retire.

The useful intelligence is partly in knowing which is which.
