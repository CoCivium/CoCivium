## CoBenefit+

For this R0, **CoBenefit+** is the qualified benefit field derived from one or more CoBenefitObservation+ objects.

A benefit observation SHOULD preserve:

- beneficiary;
- baseline;
- observed effect;
- counterfactual confidence;
- attribution uncertainty;
- duration;
- side effects;
- evidence refs;
- observation time/currentness.

`BENEFIT_OBSERVED_NE_BENEFIT_CAUSED`  
`ENGAGEMENT_NE_COBENEFIT`

## CoOomph+

CoOomph+ is a bounded effort/effect-allocation relation.

It may increase, decrease, redirect, compact, sleep, fan out or serialize work according to:

- expected verified benefit;
- uncertainty reduction;
- receiver capacity;
- currentness debt;
- collision/effect risk;
- privacy/authority;
- proof debt;
- human-attention cost;
- compute/energy cost;
- externalization latency;
- successor readiness.

It must never infer authority from value or speed.

`COOOMPH_EFFECT_REQUIRES_EXISTING_AUTHORITY`  
`BENEFIT_NE_AUTHORITY`

## Participant-edge acceleration loop

`CoEyes observe -> CoTime bind -> CoBenefit qualify -> CoPressure compare -> CoOomph elect effort -> bounded deed -> receipt -> observe again`

The loop is allowed to accelerate only when measured outcomes justify it.

Candidate acceleration test:

`benefit_yield_per_verified_deed ↑ AND receiver_pressure <= budget AND proof_debt <= budget`

Otherwise pace, compact, sleep or regroup.

`SOURCE_EMISSION_RATE_NE_RECEIVER_CAPACITY`
