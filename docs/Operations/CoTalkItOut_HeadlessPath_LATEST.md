## Sudden-death invariant | 2026-11-14

**New standing product assumption:** any manual/provider-hosted chat session can become unusable **without warning, at any instruction boundary**, including *before it can send a final status, handoff, closure, checkpoint, or stop signal*. No session's anticipated graceful shutdown is a dependable correctness prerequisite. This is an engineering worst-case assumption, not a claim that every session has actually failed or that the platform provides a death event.

**Non-negotiable capture boundary:** user-visible input/approved source delta must be durably admitted by an **independent, authorized intake** before any downstream model/tool effect relies on it. Record immutable WorkID, typed payload or minimal authorized source pointer, input digest, consent/privacy scope, origin/source version, idempotency key, lease epoch, desired effect class, and wake/retry policy. Return **durable intake ACK only after an independent exact-object readproof**. Anything typed solely into a provider text box or generated in model context before its first qualified external write is still vulnerable to loss; **NEVER claim lossless recovery of never-received content**. Keep sensitive data out of public GitHub.

**Crash-at-any-boundary contract:**
1. `BEFORE_INTAKE`: no durable object, mark `UNRECOVERABLE_OR_UNKNOWN`; do not invent an ACK or reconstruct unseen text from summaries.
2. `AFTER_DURABLE_COMMIT_BEFORE_ACK`: source may retry; look up by WorkID+content digest and return same outcome, never create duplicate effects.
3. `AFTER_ELECTION_BEFORE_EFFECT`: lease/fence expires; independently authorized successor retries from committed intent, not previous chat context.
4. `AFTER_EFFECT_BEFORE_RECEIPT`: reconcile effect externally with idempotency token/actual effect readproof; hold if uncertain, no blind replay.
5. `DURING_RECEIPT_OR_CHECKPOINT`: atomic commit, externally pinned digest and monotonic generation; reject torn/forged/old acknowledgments.
6. `AFTER_RECEIVER_ACK_BEFORE_UI_PROJECTION`: useful result is already durable; any viewer can reconstruct after cold start.
7. `AFTER_PROVIDER_TAB_DEATH`: elected independent worker continues under its existing authority and STOP policy; never presume the tab stays open or that a browser heartbeat proves work completion.

**Recovery procedure:** a separate receiver discovers incomplete WorkIDs from the committed ledger upon its *own* authorized wake, independently verifies the original source hash and authorization, checks holder lease/replay/STOP, resumes only eligible reversible effects, and writes its own exact-object readproof and observed useful result. Display `HOLD` when source completeness, recipient origin, effect status or consent is unknown. No new per-session auto-refresh/polling console jobs; reuse the elected background owner. Test by killing process/session **at each boundary**, including under X2/CoStead power isolation, and report source coverage, missing/lost work, duplicate-effect count, receiver ACK, and measured human touches.
