# CoHome+ / CoWizard+ / CoExtension+ Ecology R0

**State:** `CANDIDATE__DRAFT_PR__NO_RUNTIME_CANON_INSTALLATION_OR_STORE_AUTHORITY_CHANGE`

## Lead

CoHome+ should become the broad human/synth front door to a very large but typed catalogue of CoAll capabilities, helpers, wizards, handles, terms, modules, extensions, projections and upgrade paths.

It should not become one gigantic launcher full of inscrutable tiles. The catalogue must be relational, searchable, receiver-relative, currentness-aware and permission-safe.

`CATALOGUE_NE_DUMP`
`DISCOVERABLE_NE_INSTALLED`
`INTEREST_NE_CONSENT`
`SUGGESTION_NE_ACTIVATION`

## Consent and adaptive suggestion

A system MAY suggest an extension, wizard or capability based on explicit interest, context or repeated relevant tasks.

It MUST NOT silently install or activate based merely on inferred interest.

Preferred ladder:

`DISCOVER -> EXPLAIN_WHY -> SUGGEST -> USER_OPT_IN -> PERMISSION_REVIEW -> INSTALL -> ACTIVATE -> RECEIPT -> REVOKE/ROLLBACK_AVAILABLE`

If the user only "seems interested":

`INFERRED_INTEREST -> SUGGESTION_ONLY`

If the user explicitly opts in:

`EXPLICIT_OPT_IN -> MAY_BEGIN_INSTALLATION_FLOW`

`INFERRED_INTEREST_NE_INSTALL_CONSENT`
`OPT_IN_TO_CATEGORY_NE_OPT_IN_TO_EVERY_FUTURE_EFFECT`

## CoScendence+

`CoScendence+` is a candidate **legacy-browser bridge extension**, not a forced browser replacement.

Purpose:

- expose CoHome;
- expose CoOrb;
- surface currentness/provenance;
- add CoHandles;
- connect local/native CoAll capabilities where permitted;
- offer CoBrowser as an optional successor;
- preserve rollback to ordinary browser operation.

Candidate progression:

`LEGACY_BROWSER`
→ `COSCENDENCE_EXTENSION`
→ `COHOME/COORB_SIDECAR`
→ `OPTIONAL_COBROWSER_TRIAL`
→ `COBROWSER_IF_EXPLICITLY_CHOSEN`

This lets CoScendence be a bridge rather than a coercive upgrade funnel.

`COSCENDENCE_NE_FORCED_MIGRATION`
`EXTENSION_NE_BROWSER_OWNERSHIP`
`UPGRADE_OFFER_NE_UPGRADE_CONSENT`

## CoBrowser relation

CoBrowser SHOULD be a deeper native relational browser substrate where CoHome, CoOrb, CoTerm, CoHandle, provenance, currentness, subscriptions and local-first capabilities can be first-class rather than extension-emulated.

But CoBrowser should coexist with:

- legacy browsers + CoScendence;
- legacy browsers without extensions;
- standalone CoHome;
- native desktop/mobile clients;
- headless/machine clients.

`COBROWSER_NE_ONLY_FRONT_DOOR`
`SIDE_CAR_AND_NATIVE_CAN_COEXIST`

## AutoEvo and catalogue evolution

Catalogue items, categories, recommendations, wizards and handles MAY evolve under CoEvo/CoAutoEvo.

AutoEvo MAY:

- detect stale metadata;
- detect broken links;
- detect superseded capabilities;
- propose new aliases;
- propose new wizard flows;
- propose receiver-specific projections;
- detect duplicate catalogue entries;
- propose successor mappings;
- improve explanations;
- test low-effect catalogue rendering;
- flag permission drift.

AutoEvo MUST NOT silently widen permissions or install/activate external capabilities.

`AUTOEVO_NE_AUTO_INSTALL`
