## Lead

CoCivia should become a **first-class GitHub participant/front**, but not by pretending a literary/analytical composite voice is already an independent human principal.

The clean identity stack is:

`Principal / System -> Front or Shell -> Seat / Service Principal -> Effects`

A GitHub account is a **seat**, not identity truth.

`PRINCIPAL_NE_SHELL_NE_SEAT`

## Why a GitHub App / service principal is preferred later

A machine/front identity should ideally have:

- scoped repository permissions;
- revocable credentials;
- auditable actions;
- explicit installation scope;
- separate effect ceiling;
- no need to impersonate a human;
- provenance on automated contributions;
- replaceable runtime/AI implementation behind the same front contract.

A regular human-style vendor account may still be useful for some fronts, but it should not be the default merely because GitHub calls every login a “user.”

## GitHub account / organization evolution candidate

Because the current root is a GitHub **User** account, the longer-term topology should be separately evaluated:

1. keep the current user account as-is;
2. convert/migrate toward a GitHub Organization;
3. create a new organization under a different stable name;
4. maintain multiple independent mirrors/orgs for failure-domain diversity.

No option is elected solely from this document.

Before any account conversion:

- inventory repo ownership and integrations;
- confirm GitHub App/connector consequences;
- preserve redirects/URLs where possible;
- test permission and recovery paths;
- protect public URLs and release assets;
- preserve independent admin recovery;
- record rollback limits.
